## 1. 先把对话里的前置问题答了

对话原文设定的判据是：

> 如果大部分是算法错误，subtask 和 AST 帮助不大，应换方向；如果大量是接口、依赖和组合错误，可以研究结构约束。

这可以直接测。对 200 条候选的每一条测试结果做自动分类：有异常就取异常类名，无异常但 `actual != expected` 记为算错。

| 事件 | 数量 |
| --- | ---: |
| 至少有一个候选的主因是纯算错的题目 | 39 / 50 |

### 1.4 结论（直接回答对话里的那个问题）

**在这批数据上，算法错误是绝对主因（49%），契约/接口类错误只占 13%。** 按对话自己设的判据，这条路指向"换方向"，而不是"研究结构约束"。

但有两个必须写清的边界：

1. **生成器太弱会造成偏差**。3B 模型 + APPS 入门题，49% 的算错里有多少是"算法想错了"，有多少是"根本没读懂题"，现在分不开。这一点需要第 4 节的 N8 去补。
2. **语法类错误占了候选级的 8%，而且高度集中**（15 个候选贡献了 178 个失败测试点，占全部异常的 57%）。这 8% 是**完全可以用工具消掉的确定性收益**，属于"阻止具体错误"这一类，比重不大但收益确定。

## 2. 对话记录里需要修正的三处判断

### 2.1 判据是对的，但没有变成筛选器

对话给出的四条价值来源（提供新信息 / 可靠反馈 / 缩小搜索空间 / 阻止具体错误）很准，但它只用来否定三个旧方向，没有拿去筛新方向。本文档第 3 节把它固化成打分表，第 4 节每个方向都要过这张表。

### 2.2 失败归因实验缺一个自变量：生成器强度

对话的实验设计是"选 30–50 道中等或困难题，比较三种生成方式，然后归类失败原因"。缺的是**生成器强度**这一维。同一批题交给 1.5B 与 7B，失败构成会明显不同：语法与契约错误随模型变强而下降，算法与题意错误则不会同步下降。不加这一维，归因结论无法迁移，也没法解释"为什么弱模型上算法错误特别多"。

### 2.3 "接口错误"被错误地绑在了分解方法上

对话把"子任务接口与组合错误"当作 subtask 分解的专属问题。实测数据显示，**在单函数任务里接口类错误同样存在**：`NameError` 37 次、`IndexError` 26 次、`TypeError` 24 次、`AttributeError` 21 次。

这意味着"契约错误的检测与修复"可以作为一个**独立于分解方法**的研究对象（N1），而它的价值不依赖 subtask 那条线是否成立。

## 3. 判据：什么样的方法才可能有用

按对话记录的四条，我把它写成可打分的形式，每条 0/1/2 分：

| 代号 | 判据 | 含义 |
| --- | --- | --- |
| I1 | 注入新信息 | 模型原本不知道的事实（具体反例输入、失败位置、类型契约） |
| I2 | 可靠验证信号 | 能判对错，且与已有测试不重复 |
| I3 | 缩小搜索 | 减少候选数、减少生成步数、或把解空间切小 |

**总分 0 的方向不要做**，无论它听起来多漂亮。上一轮的 D1–D8 与这一轮的 N1–N8 都在第 4 节末尾一起打分。

## 4. 八个方向

### N1 契约错误检测器：把"接口错误"从分解方法里解耦出来

- **来源**：第 2.3 节（对话把接口错误绑定给 subtask 分解，实测显示单函数里同样有）。
- **判据**：I4（主要）+ I1（部分）。
- **要检测的五类契约错误**：
  1. 变量在使用前未定义（对应 `NameError`）；
  2. 返回值的**个数**与调用点解包方式不匹配；
  3. 返回值的**容器类型**与调用点用法不匹配（返回 `set` 却被下标访问）；
  4. 参数个数/顺序与函数定义不匹配；
  5. 把可变对象当值传递却依赖其未被修改（别名/副作用）。
- **为什么现在能做**：他们的记录里有每条测试的 `stderr`，异常类名可以直接当作**弱标签**来评估检测器，不需要人工标注。
- **最小实验**：用 `ast` + 简易可达性分析实现上面 5 条规则，在 200 条候选上跑，以"该候选是否出现对应运行时异常"为标签算召回与误报。
- **判定标准**：召回 ≥ 60% 且误报率 < 10% 才值得继续；否则停。
- **已有工作重叠（必须如实写进汇报）**：`pyflakes` 已经覆盖未定义名，`mypy` 覆盖多数类型错误。**单函数场景的增量空间很小**。真正的空白在"跨函数/跨子任务的契约不匹配"与"返回值个数及类型与调用点用法不一致"这两类，它们需要跨过程的推断，静态检查器通常不做。
- **工作量**：3–4 天。

### N2 最小反例：把执行反馈变成"新信息"

- **来源**：对话对三个旧方向的批评——它们都没有给模型新信息。
- **判据**：I1（主要）+ I3。
- **假设**：把"某个测试没过"升级为"这个**最小输入**会让你的程序输出 A，而它应该是 B"，能让 Refine 的修正成功率明显提高。理由：模型在长代码里需要自己猜错在哪，而最小反例把注意范围直接压到一个点上。
- **做法**：对失败的测试输入做结构感知的最小化（把列表缩短、把数值推向边界、把字符串截短），得到仍然失败的最小输入，连同期望输出、实际输出一起作为 Refine 的输入。
- **最小实验**：在现有"public 全过但 private 全败"的 5 条候选 + 25 条 `runtime_error` 候选上，对比两种 Refine 输入：(a) 现在的自然语言反馈；(b) 最小反例三元组。比修正成功率与"改坏原本正确部分"的比例。
- **判定标准**：修正成功率提升 ≥ 10 个百分点，方向成立。
- **已有工作重叠**：Self-Debugging、Reflexion 用了完整执行反馈；CEGIS 用反例做合成；输入最小化是成熟技术。空白点在"最小反例 × 过程奖励 × 步骤定位"的结合，以及"最小反例能不能指到某一步"。
- **工作量**：5 天。

### N3 候选间差分定位：不用 oracle 也能找错

- **来源**：对话反复强调"定位才是难点"（AST 只能说明语法合法，说明不了算法对错）。
- **判据**：I1 + I3。
- **假设**：同一题多个候选在同一输入上输出不同，说明这个输入是"分歧点"。分歧点集合本身就是免费的定位信息，不需要正确答案。
- **实测支撑（现在就能算）**：在 24 道有解题目、70 个公开测试点上，**75.7% 的测试点存在候选间输出分歧**；在这些分歧点上，正确候选的输出属于"多数派"的有 42/53（79%），属于少数派的有 11/53（21%）。
  - 换句话说：**多数投票在分歧点上免费拿到 79% 的正确率**。任何定位或选择方法都必须先超过这个基线，否则没有意义。
- **最小实验**：用分歧点把候选分组，统计"少数派候选是否就是失败候选"的命中率；再把这个信号与 public 通过率选择做对照（同样的 50 题、同样的候选池）。
- **判定标准**：少数派定位的命中率显著高于 21%（随机水平以上），且与 public 选择结合后有增量。
- **风险**：候选中"一起错"的情况（12 道 L0 死区题）无法靠差分区分，这是方法的天花板，报告时必须单列。
- **工作量**：3 天。

### N4 生成协议作为自变量：先修 FunPRM 的可迁移性，再谈步骤粒度

- **来源**：上一轮结论"183/200 单函数是协议使然"（`src/generator.py` 的提示词要求 exactly one program + exactly the starter signature）。
- **判据**：I3。
- **假设**：把生成协议改成 FunPRM 的 Chain-of-Function 形式（要求拆出可独立复用的顶层函数、附 docstring、高层函数在前），函数级步骤的区分度会恢复，"函数即步骤退化"这个现象会消失或大幅减弱。
- **最小实验**：同一 50 题 × 4 候选，只改提示词，重跑一次生成（3B 本地，几十分钟），对比：
  - 顶层函数数分布（现在 183/200 只有一个函数）；
  - 函数级步骤标签与最终结果的相关性（现在函数级步骤无可评内容）；
  - 语法错误率是否变化（协议变复杂后可能上升）。
- **判定标准**：多函数候选比例 > 50% 且函数级步骤的相关性显著非零 → 说明瓶颈在协议，不在 FunPRM 的步骤定义；若多函数比例仍 < 20% → 3B 能力不足，需要换生成器（接 N8）。
- **为什么值得排在前列**：它用一个**可执行器验证过的变量（提示词）**，直接检验一个已经写进本地文档的结论。成本低，结论二值化，而且无论正负都有话可说。
- **工作量**：2–3 天。

### N5 受控扰动矩阵：错误类型 × 可检测性 × 可定位性

- **来源**：对话的"失败归因"实验里，人工读代码归类是主观且昂贵的。
- **判据**：I4 + 方法学价值。
- **做法**：拿现有 **56 条私有测试全过的候选**，对每一条自动施加受控扰动，得到"已知错误类型 + 已知错误位置"的样本：

| 扰动 | 对应的真实错误 | 数量 |
| --- | --- | --- |
| `>` 改 `>=`（以及反向） | 边界条件错误 | 每条候选 2 个变体 |
| 返回值由 `list` 改 `set` | 契约/类型错误 | 1 |
| 删掉一个边界判断（`if` 分支） | 遗漏条件 | 1 |
| 交换相邻两次赋值的顺序 | 依赖顺序错误 | 1 |
| 去掉 `copy()` / 改成原地修改 | 别名/副作用错误 | 1 |
| 循环上界 `n` 改 `n-1` | off-by-one | 1 |

- **要测三件事**：
  1. **可检测性**：public 测试能捕获多少比例的扰动（覆盖率）；
  2. **可评分性**：现有评分器在扰动前后的分数变化是否稳定单调；
  3. **可定位性**：定位方法能否指出被扰动的行。
- **为什么它比"人工归类 50 道题"更好**：完全自动化、可复现、错误位置是精确已知的 ground truth，而且产出的数据集可以被后面所有定位/评分方法复用。
- **判定标准**：若某类扰动的 public 捕获率 < 50%，这类错误就是"现有反馈看不见的错误"，正是过程监督该解决的问题；捕获率 > 90% 的类别没有研究价值。
- **工作量**：4–5 天（构造扰动器 + 跑测试）。

### N6 因果最小对照对：给步骤标签加一层因果验证

- **来源**：上一轮 D2（用"错误候选 vs 正确候选"的差异集合做标签）。这里补上对话强调的判据——不能只有相关性，要有因果。
- **判据**：I1 + I2。
- **做法**：在 24 道有解题上取"错误候选 A，正确候选 B"，按行对齐差异块，把 A 中的差异块逐个替换成 B 的版本，用私有测试判断替换后是否通过。
  - 替换后通过 → 该差异块与该失败有**因果**关系，可以安全地当作步骤级错误标签；
  - 替换后仍失败 → 该差异块只是风格差异，不是错误原因，不能当标签。
- **成本**：每对候选约 10 次本地执行，纯 CPU。
- **判定标准**：因果验证通过的差异块比例 ≥ 50%，才说明"差异集合标签"可信；低于 30% 说明短代码上的差异太碎，这条路代价过高。
- **价值**：这一步同时验证上一轮的 D2 与这一轮的"接口错误"假设——如果被判定为因果的差异块里，契约类修改占相当比例，那就说明"接口/契约"确实是可被自动定位的错误类型。
- **工作量**：4 天。

### N7 评测方法学：把小样本过程奖励研究的报告规范固定下来

- **来源**：审查 `docs/debate/` 时发现的三个陷阱（同分规则、候选池上限分层、pooled 统计混入题目难度）。
- **判据**：方法学价值（不进 I1–I4 打分，它是给所有方向兜底的）。
- **产出**：一份可复用的报告清单，例如"必须报告候选池上限的分布""必须显式声明同分规则并给出敏感性区间""跨题统计与题内统计分开报"。
- **为什么值得花时间**：现在的对照实验都在 50 题、4 候选的规模上，任何没被显式声明的自由度都会变成"换个规则结论就变"的风险（实测：同一 public 信号在四种同分规则下差 0.016–0.077）。
- **工作量**：1 天，写文档。

### N8 生成器强度 × 失败构成的迁移性

- **来源**：第 2.2 节（对话的归因实验缺这一维）。
- **判据**：I1（提供的是关于方法适用边界的信息）。
- **假设**：语法与契约类错误随模型变强而下降，算法类错误不会同步下降；因此"阻止具体错误"这条路的收益随模型变强而衰减，而"提供反例信息"这条路的收益不衰减。
- **最小实验**：同一批题用三档生成器（`qwen2.5-coder:1.5b`、`qwen2.5-coder:3b`、`dolphin3:latest` 已存在本地；另有条件时可加 7B 量化），各生成 4 候选，用 N1 的分类器统计失败构成。
- **判定标准**：不需要 Go/No-Go，是一组测量数据；但如果三档下算法错误占比都 > 40%，说明结构约束型方法的天花板被钉住，应把精力放到 N2/N3/N6。
- **工作量**：2 天（生成 + 分类）。

### 两条路线

**路线甲（先修正已有结论）**：N4 → N8 → N7。
先把"183/200 单函数"这个已经写进文档的结论查清楚是协议问题还是能力问题，再把归因实验的生成器维度补上。三天内可以出结论。

**路线乙（把"定位"做成真问题）**：N3 → N5 → N6 → N2。
核心论点：在这批数据上，真正稀缺的是"错在哪"，"怎么拆"的稀缺程度要低得多。先用量化基线（多数投票 79%）钉住参照系，再用扰动矩阵造出带 ground truth 的错误集，最后把定位结果接到 Refine 上验证收益。

两条不冲突，甲在前，乙在后。若只做一件事，**做 N4**：它便宜、二值化、且直接检验一个已经写进汇报材料的结论。

## 7. 明确不要做的

1. **不要把"AST 对齐"当成默认正确的前提**。实测的 49% 算法错误是它管不到的区间；AST 能提供的定位信息在契约类错误上才明显（13%）。
2. **不要在弱生成器上继续研究"算法错误"**。3B 模型在 APPS 入门题上 12/50 题连一个候选都过不了，这类题上的失败归因无法区分"算法想错"与"没读懂题"。
3. **不要跳过多数投票基线**。分歧点上的多数投票免费拿到 79%，任何新定位方法都得先报这个数。
4. **不要用人工阅读归类 50 道题**。N5 的扰动矩阵给出的是精确 ground truth，成本更低、可复现。
5. **不要在没有同分规则声明的情况下报告任何选择类指标**（这是 `docs/debate/` 那份审查的核心结论）。

## 8. 一页速记

1. 对话里的前置问题已有答案：**候选级主因 49% 是算错，契约/接口类只占 13%**，语法类 8%。按对话自己的判据，结构约束型方法在这批数据上天花板有限。
2. 但弱生成器会放大算法错误占比，这个结论必须用 N8（三档生成器）补齐才能汇报。
3. 对话漏掉的第 0 步：**183/200 单函数是提示词强制的结果**，改提示词重跑（N4）比继续设计新框架便宜得多，也更能定案。
4. 真正稀缺的资源是"错在哪"，不是"怎么拆"。分歧点上多数投票已经免费拿到 79%，这是所有定位方法的起跑线。
5. 用现有 56 条全过候选做受控扰动（N5），可以得到精确 ground truth 的错误集，比人工归类可靠且可复用。
6. 上一轮的差异集合标签（D2）需要加一层因果验证才站得住，做法是把差异块逐个替换回正确版本看是否通过（N6）。
7. 判据要当筛选器用：一个方法如果既不提供新信息、也不提供可靠验证、也不缩小搜索、也不阻止具体错误，就不要做。
