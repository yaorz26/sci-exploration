# 五分钟汇报稿（2026-09-10）

> 用法：先自己念一遍，把括号里的数字改成你复核后的数字。念不顺的地方就说明你还没理解，回去看对应文件。

## 1. 开场（30 秒）

老师，这两周我按您给的方向读了两篇论文，并做了第一步观察。
方向上我的理解是把代码生成任务拆成子任务、评价每个子任务，但**"子任务到底怎么定义"目前没有共识**：
CodePRM 把自然语言思路步骤当步骤，FunPRM 把函数当步骤。我做的第一件事是在我们已有的 APPS 数据上量了一下这两种定义是否真的成立。

## 2. 三个数字（1 分钟）

1. **183 / 200**：APPS train-50 的 200 个候选里，183 个只有 1 个顶层函数。
   按 FunPRM 的"函数即步骤"，这些候选只有一步，过程奖励就退化成结果奖励。
2. **1–16 步（中位数 5）**：同一批候选的模型思路步骤数。所以"思路步骤"和"函数"不是同一数量级。
3. **0.825 / 27 题**：public 通过率与 private 结果的 Spearman 相关性只有 0.825；
   用 public 通过率选择后，50 题里仍有 27 题没有完全通过 private 测试——说明执行反馈并不总能定位错误。

## 3. 我做过的实验现状（1 分钟）

- 已有复现基线上，学习到的神经过程评分器没有超过直接用 public 通过率选择：
  后 13 题上首候选 `0.533`、public 选择 `0.683`、神经评分器最好 `0.514`。这个配置已经标记为 No-Go。
- 我目前倾向的解释是：**不是输入模态不够（反馈也有了），而是步骤定义和任务形态不匹配**。

## 4. 我下一步想做什么（1.5 分钟）

提出一个最小假设：**把固定的步骤粒度换成任务自适应的语义步骤**。

- 单函数任务 → 用思路步骤做步骤单位；
- 模块化任务 → 保留函数级步骤；
- 由候选代码的结构复杂度自动落档。

对照设计四档：S0 单步（退化为结果奖励）、S1 函数级（FunPRM 设定）、S2 思路步骤级（CodePRM 设定）、S3 结构自适应（我的假设）。
控制变量固定：同一候选池、同一题目划分（前 37 / 后 13）、同一随机种子。
主指标：private pass rate、pass@1、步骤排序 Spearman、错误定位准确率。

可证伪的预测：
- 单函数题目上 S1 与 S0 应该没有差别（预测 Spearman 差 < 0.05）；
- S2/S3 应该比 S1 高（预测 Spearman 提升 ≥ 0.10）；
- 如果 S1 在单函数题目上就已明显好于 S0，我的假设就被推翻，那就转向结构化反馈方向。

## 附：可能被追问的问题与准备

| 追问 | 你的回答要点 |
| --- | --- |
| 为什么神经 PRM 打不过 public 选择？ | 两种可能：标签方差（每节点只有 2 条 continuation）或信号冗余（public 通过率已含大部分信息）。我准备了 test-retest 相关性来区分，这就是要做的下一个实验。 |
| 183/200 是不是因为 APPS 题太简单？ | 是 starter code 形态导致的。但这个观察的价值不是“普遍规律”，而是它给出了**粒度的下界端点**：当函数=整体时，函数级步骤彻底失效。真正的结论是“粒度存在有效区间”，不是“函数不能当步骤”。 |
| 我们最终要用大模型做复杂项目，函数很多，你这个观察还有意义吗？ | 有，但问题会反过来变成“**函数太多**”。大项目里几百个函数全展开成步骤，成本爆炸且语义碎裂；而且函数之间是**调用图（有向图）**，不是 PRM 假设的一条链。所以我的主张从“函数太粗”升级为“**步骤的粒度与结构假设都要按任务重新定义**”，下一步先做静态统计（数函数数、量调用图是不是链），不需要 GPU。 |
| 那为什么不做大项目？ | 评测成本。真实仓库要 Docker + 依赖环境，不是单机能跑的；而且模型越强，候选之间的差距越小，过程奖励本来就越来越难有额外信息。这是我下一步要换成 ClassEval / BigCodeBench 的原因。 |
| 那 FunPRM 是不是就错了？ | 没有错。它在 LiveCodeBench/BigCodeBench 上用了"提示词要求按函数组织"，属于开放式生成。问题在于这个前提没有被显式检验，换到函数式题目就失效。 |
| 你的贡献是什么？ | 目前是：量化了"函数 ≠ 子任务"的比例（183/200），并给出步骤粒度自适应的最小假设与可证伪预测。还没有新方法结果。 |
| 数据里有没有泄漏？ | 没有。private 测试只用于标签和最终评估，从不进入 prompt；候选顺序和划分都已固定并记录。 |
| 复现到什么程度了？ | 工程闭环（数据、执行器、候选生成、轻量 PRM、GVR、MCTS、3B QLoRA 训练）都跑通，但达不到论文规模，结论上限是"缩小规模复现"。 |
