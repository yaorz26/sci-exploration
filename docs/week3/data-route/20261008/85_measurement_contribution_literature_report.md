# P39：现有功能级评测已覆盖什么，D1还需证明什么

结论：D1不能把功能级任务、明确接口、执行测试、输入输出token记录或动态依赖图称为首创。两个已有一手工作覆盖这些组成部分。所查六段没有给出D1拟议的联合设计，但这只支持收窄后的研究候选，不能证明全领域不存在同类工作，更不能补上主问题A的模型效果证据。

## 新问题与核对范围

竞争解释：现有工作已有完整联合框架；只覆盖部分构件；或D1现有反例不足以形成可检验贡献。原17号索引主要回答接口和任务抽取，本次新查预算含义、依赖图采集时点、生成后组件参与与观察分母。采用两个官方v1缓存、六个定向窗口，记录源码哈希/行定位及中文转述，不通读全文、不保存大段摘录。web通道500失败已保存，换缓存而不继续原样重试；不称最新版本核实。

## 阶段审查

学到：已有研究覆盖拟议贡献的多个构件，成本记录和任务依赖不能单独作为创新。排除：不能把“有Token IO”解释为本来没有成本指标，也不能把任务抽取图直接当成生成方案贡献测量。仍未知：其他工作是否已有完整联合设计；D1人类能否稳定理解测量单位；同总cap下结构与收益关联。人工仍0，当前总预算下完整M2仍不足，手工程序不替代模型效果。

可保留的候选贡献是：可复核的功能适配数据集，以及由明确反例支撑的测量与方法协议边界；若要进一步回答A，必须有前置分组支撑、正式冻结和实际配对结果。当前不称已经完成A或获得普遍适用规律。

## 方向审查与下一项

停止增加相同接口/标记/调用反例，也不因检索未发现而继续无限扩文献。P40转向一个直接影响A设计的问题：原20题在开发/储备、来源和显式相关组件限制下，三个前置结构维度是否有可比较的支撑？先冻结轴与比较规则，精确枚举只改变一轴且其余两轴相同的同来源任务对，单列同相关组件和跨组件；没有支撑的比较不得靠满秩或任务总数掩盖。
