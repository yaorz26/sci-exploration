## 新增信息与反例

容量1与容量2执行put(a,1)、put(b,2)、read(a)，前者缺失、后者返回1，这是第二来源的跨键容量竞争与阴性对照。LRU/LRI容量均2时，put(a,1)、put(b,2)、read(a)、put(c,3)：LRU保留a/c，LRI保留b/c。两者相同查询和值不代表后续淘汰相同；读访问对状态的影响必须进入契约。

缺键read随后带默认值get，累计misses=2、soft_misses=1；contains、pop和每步自动观察不计命中。clear保留累计统计、重写已有键刷新写入顺序且不增加项数，均有明确手算锚点。输入域只含正容量、字符串键及所列动作，不含on_miss/并发或域外校验。

有限枚举为两策略×容量1/2×固定9动作的0—3步，共4×(1+9+81+729)=3280序列；手算含所需4步模式。没有声称覆盖任意JSON值、全部长度或全域正确。两实现由同一助手准备，并不形成独立人工真值。

人工缺陷为LRI错误刷新读取、get漏soft_miss、clear错误重置统计、观察时逐键调用普通读取。四项全部检出，是这些具体缺陷的可发现性，不是模型错误率或全面缺陷覆盖。最后一项尤其说明：自动输出items若使用`cache[key]`，会改变统计与LRU顺序；正确参考使用无读取副作用的dict.items。用于测量的观察也须审查是否改变后续行为，不能只关心返回值。
