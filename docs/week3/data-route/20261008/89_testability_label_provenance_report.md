# P41：标签对应是初标表的样本事实，不是构建器计算出来的

静态证据排除了一个可能误诊：当前构建程序没有用依赖标签计算独立可测程度，也没有将两者从旧结构类别共同映射。`task_specs_expansion.py`的STRUCTURE_V2为20个任务ID各存一个五元组，两字段分别为字面量；`task_specs.py`导入，`build_dataset.py`复制到manifest。20/20任务五个相关字段完全相同。

因此P40的对应与缺少对比仍是这份作者初标表的事实，但不能归因于构建器硬编码函数关系。字面量逐题指定也不能证明作者判断彼此独立，不能解释最初判断心理/次序，不是人工双审。真正人类仍0，不得由100字段复制一致算标注κ。

## 问题、证据与范围

先冻结构建器、manifest和P40行表哈希。首步相关AST显示字段来自外部表，原单构建脚本不足以判机制，故在88号追加理由与范围：只追踪另两文件的STRUCTURE_V2声明/导入节点，总三文件、不执行模块。没有提取TASKS、不读取/输出隐藏案例；与P31意外暴露的红线说明保持一致。

定位：`build_dataset.py`115—119行逐字段复制；`task_specs.py`399行导入；`task_specs_expansion.py`594—615行单一字典声明。仅对这个字典使用ast.literal_eval，未运行任务函数、构建器或curator。两字段都是独立存储位置，不能将“独立存储”称为“独立语义测量”。

## 阶段审查与方向审查

学到：当前代码路径是复制20条初标，不是机械推导；在20条中依赖集合与可测类别仍完全对应。排除：不能据P40查表恢复就断言构建器自动产生标签。仍未知：这种对应是选择偏差、粗定义、作者判断还是任务范围造成；真实人类能否分开判断；主问题A实际收益未知。

下一步不修改初标或把no改yes来填空格，也不扩大回归。P42定向查一个公开非缓存功能：boltons Stats的多种描述统计，是否能给至少两个用途不同、各自有明确输入/输出的外部行为契约，而不强制有序转换？若只有同用途多字段或仍依赖整体过程，就不宣称补上独立可测对比。只在公开功能适配层构建另池候选，主20/11—9保持。
