输入mode为exact或casefold，records为key/value记录流，输出每个规范键的首次完整原记录，保持首次出现顺序。返回原拼写、原value，而非规范后的key。公开文档明确保序和记住全部已见元素，因此顺序义务有公开来源依据；不是因为源码用了某个容器才增加要求。

## 三种关系与范围

两个mode各有一条全局顺序阳性：a记录、b记录交换后，完整输出不同。68条有限插入关系中，目标键a的0—2条记录历史不变，插入原键b/B的其他规范类记录到各位置，目标规范键a的代表不变。全局顺序要求可以与指定范围的实体内容隔离共存。这些是输入记录流历史，不是原B02/B04的外部操作序列，候选明确保存history_domain=input_item_sequence，不追溯继承旧cross_operation_state标签。

第71条关系给出实体判定反例：casefold下左输入为a:1，右输入为A:3、a:1；目标规范键a的代表从a:1变成A:3。这是同一规范实体的较早历史改变，不是不同实体之间的干扰。只按原拼写分实体会把A和a误当两个对象；这和C04的实例/调用键粒度问题一起表明，实体定义须包括等价规则。

有限原输入格为两个mode×6种记录×长度0—4，2×(1+6+36+216+1296)=3110；六条手算另行保存。4个人工缺陷是只去相邻重复、保留最后代表、错误排序、忽略casefold；不把检出率当模型发生率。Unicode锚点ß/SS测试casefold等价，不声称所有Unicode输入覆盖。
