# P23结果：原任务里有缓存家族的无历史成员，也有无状态的对齐域依赖

从原12个未测任务公开需求中选择C05/M05，冻结新手算关系后，26/26关系通过参考和另一结构交叉检查；29个不同任务—输入、58次实现求值。隐藏案例读取0、模型/API0、人工0。原P15附件不覆盖，原20题307记录和11/9切分不改；其他10题仍未完成关系测量。

## 两个区分结果

C05位于原显式缓存关联群，却只逐对判断键是否等价，公开输入没有缓存、容量或操作序列。20条插入合法其他调用对的关系保持目标判断：固定[1]与[1.0]，typed=false为true、typed=true为false，插入前后均不改变目标。改变typed会改变同一目标结果，但这是规则配置变化，不是另一实体历史干扰。缓存宽家族不能自动替代任务状态/依赖属性；有限隔离也不是全域独立证明。

M05没有跨操作持久状态，却存在至少两种不同观察依赖。相同键行交换后身份顺序变化，不同键行交换后排序结果不变；插入较小键行后目标行的全局位置0→1，目标身份/键内容仍为a/2。因此全局位置与目标内容必须分开，不能把位置变化一概记成目标实体内部状态干扰。

更关键的非缓存反例：左输入两列`[[1,2],["a","b"]]`；右输入增加较短非键列为`[[1,2],["a","b"],[7]]`。原两列逐字不变，投影只观察原两列输出，却由`[[1,2],["a","b"]]`变成`[[1],["a"]]`。这是公开strict=false下的最短长度对齐规则，新增列改变了共同有效行域。它是按列实体观察的依赖，不能叫跨行容量淘汰、操作历史或共享可变状态。

## 支撑影响与第二遍质疑

P22容量列等于关联缓存群的结论，只限当时8+2已有证据行；C05这一原群成员展示了为什么不应把该等式推广为整个家族的性质。不能把它的“无容量字段”随意编码为未测行为的可靠否定，再据此宣布统计模型已经可识别。当前需要保留行为是否适用、观察粒度和历史域。

M05虽新增more-itertools来源的稳定排列见证，仍属于输入行序列，不解决“另一来源操作历史全局顺序”缺口。它带来的新价值是非缓存对齐域约束，而不是把原20题扩成更多或机械补重复顺序例子。

需求筛选本身不算26条行为证据。B01/M01/M02/F01/F02/B03/B05/B06/F03/F04均没有P12式操作序列，但若有输入序列、验证整题失败或层合并，仍可能有其他依赖；未测/不适用/未找到见证不能混写为无依赖。新探针未评分旧隐藏或生成储备模型候选，不用于调提示或预算。
