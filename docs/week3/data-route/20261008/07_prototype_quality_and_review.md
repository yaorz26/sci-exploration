# D1 首批8题原型：质量检查与有限独立审查

日期：2026-10-08。当前数据版本：`d1_project_prototype8_v4_20261008`。这是自建评测数据的首批候选原型，不是最终20--30题数据集，也不是任务分解适用边界结论。

## 数据与自动检查

4个真实Python项目各2题：boltons（区间解析、有序多值记录）、more-itertools（滑动窗口、按相邻下降分段）、cachetools（LRU、TTL缓存）、confuse（字符串配置、键值配置规范化）。来源完整提交、原文件位置和哈希、版权许可已记录；许可为BSD-3-Clause或MIT，下载合计686167字节。

第四版共151测试案例：公开16、隐藏135。每题参考实现连续3次通过，另一种内部实现通过；未实现版本失败，3个基本错误实现均失败。额外手工设计16个具体语义错误，全部被识别。16/16只是这组缺陷的结果，不是自动变异框架覆盖率或需求完备证明。相关上游测试85项通过，另18子测试通过；confuse该轮只验证StrSeq，不能写成所有上游测试均通过。

用例均为JSON输入及预期值/异常类型，评分器对候选只调用`solve(payload)`；不访问内部helper。运行中限制总输出1MiB及20秒，独立检查正常返回、死循环、持续输出、导入失败均按预期处理，失败保留分母。所有题面均公开不修改输入的要求。

## 独立审查的实际范围

采用 `workbuddy-delegate` 技能进行只读自动审查，模型`glm-5.3`。大材料审查10分钟超时，没有结论；缩小为8题公开需求与示例后，有限审查完成。其有效发现是B02返回值歧义及任务代表性不足。审查员没有看到完整隐藏测试，因此其“内部helper是否被测试调用”的未知项由另一次实际用例格式和评分器调用检查补证，不把审查员的未知写成已经发生的缺陷。

审查建议覆盖capacity=0、ttl=0、step≥width、空/单元素等。前两项已追加明确用例，后几项已有用例；F02非字符串键超出公开输入域承诺，不强加未披露评分要求。独立人工真值仍未取得；另结构实现与原数据同作者，不能当双人编制。当前有限自动审查足以修正确定歧义并进入**开发流程探针**，不足以冻结最终数据质量。

本地Qwen2.5-Coder 7B另做两个批次及一次澄清复核，总计3次调用。初次把跨操作缓存标成无状态，其他建议也与实际示例不符；澄清后仍未可靠修正，并出现输出截断。因此本地7B审查不作为有效结构标签或独立通过证明。所有原始回复保留，不筛选漂亮结论。

## 结构判定与尚未解决的问题

外部审查对B02/C01/C02的跨操作状态判断与初标方向一致，但对“能独立验证”的定义仍有分歧：逐步对照完整快照，与不运行整体功能就可验证一个语义阶段，是不同尺度。M01的“游标状态”也不应和缓存跨操作共享状态混为一类。修订定义前，不计算可靠量表的一致性结论，不把原型标签用于正式分组检验。

LRU与TTL同属缓存家族；来源仓库与任务类型目前混杂。部分任务是小型工具函数或单步规范化，适合作为简单对照，但不能独自代表项目功能级生成。扩量时补实际项目中含多种行为规则的功能、来源内的简单/复杂对照及输入条件证据；不通过参数变体凑20--30题。

污染风险未知。最近提交不能保证功能代码未被模型训练见过。尚未完成新颖性文献复核，不声称首创或无污染。
