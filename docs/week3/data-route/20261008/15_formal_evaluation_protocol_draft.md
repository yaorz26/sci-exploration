# D1正式评测协议草案 v0.1

本文件是正式执行前的审阅稿，不是已经揭盲的确认结果。题目与主问题保持不变：

> 在等总生成预算下，阶段依赖、跨操作共享状态、可独立验证程度与任务分解相对整体生成收益之间有什么关系？

## 当前数据能支持什么

initial20 v5有20题、307个行为用例，开发11题、储备9题。前置审计发现开发/储备与仓库来源完全重合：boltons和cachetools全在开发，more-itertools和confuse全在储备；20个功能家族各只有1题。因此当前切分不能支持“控制来源后比较结构因素”的因果结论，也不能把11道开发题称为跨来源确认集。

人工复核前，数据集只应标为“候选数据集”。独立人工复核完成后，可作为数据集成果交付；模型边界结果必须另行标记为探索性，直到来源、家族和结构覆盖达到预设门槛。

## 估计量与比较单位

每题每个方法只生成一个候选，主结果以题为单位：

- Y_i(M0)：整体生成候选是否通过该题全部公开与隐藏测试；
- Y_i(M2)：先计划、逐辅助函数实现、最后组装入口的候选是否通过全部测试；
- Δ_i = Y_i(M2) - Y_i(M0)：同一题的配对差，取值为-1、0、1。

主报告同时给出公开通过数、隐藏通过数、整题全过数、生成失败数和实际总token。生成失败按该方法该题未通过处理，同时保留失败阶段和错误类型；不能把“未生成”改写成行为错误。

正式总体指标为 sum(Y_i(M2)-Y_i(M0)) / N 及其题级配对bootstrap区间。结构分层只做描述性汇总；在每个结构单元少于4题、或某个来源只出现在一个切分时，不拟合多因素因果模型。

## 两臂与预算

正式协议必须把预检和生成都算入同一个题目—方法预算。每次请求保留 prompt_eval_count 和 eval_count，实际花费为两者之和；预检的单token输出也计入。若预检本身重复输入，重复输入就是分解臂的真实成本，不从账本中删除。

候选生成顺序固定为：读取public题面 → 预检 → 生成 → 保存候选；所有题目的两臂候选生成完成并冻结后，才读取private评分。不得用public分数挑候选，不得重试，不得根据失败结果改题。

M0提示允许自行写辅助函数；M2先输出2—3个辅助函数计划，再逐个实现，最后实现 solve(payload)。计划、helper、entry的函数名和依赖在生成后冻结；跨段定义冲突属于组装失败，单列记录。

## 任务进入正式比较的门槛

1. 20题全部完成独立人工双审；每个结构字段保留两份原始判定、分歧说明和最终协商值。没有两份人工表，不计算κ，也不声称结构真值可靠。
2. 题面、参考实现、另一实现、公开/隐藏测试和许可审计全部通过；历史版本保留，不覆盖。
3. 重新安排正式比较切分，至少让每个结构层级在两个以上来源中出现；若做不到，结论标签降为“当前来源组合下的描述性边界”，不写成结构因素效应。
4. 预先登记任务清单、seed、模型、上下文、总token预算、失败处理和统计方法；登记后不得按模型成绩换题。
5. 先跑一题端到端预算烟测，确认“预检计入预算、private延后读取、冻结文件完整”后，才进入批量运行。

## 当前停止条件

在人工双审、来源平衡和总预算协议完成前，不启动新的模型生成，不训练、不启动RL，不把现有5题成本探针写成问题A的答案。若后续补样仍无法跨来源覆盖结构层，停止因果边界主张，保留数据集和描述性失败分析作为成果。
