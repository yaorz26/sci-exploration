# P18结果：先统一问题单位，仍需核对实体定义是否符合题意

两个已有案例说明，只比较同题的耦合标签，会混入不同问题；但不能把所有粒度分歧都视为合法选择。C04按实例观察得到目标计算增量0/0，按同实例的调用键观察得到0/1，这两个问题的对象与共享边界不同。E_M06在casefold条件下A/a是同一规范实体，把两者当不同实体违反公开等价规则，不能通过“粒度不同”从分歧统计中排除。

本阶段只分析P12/P17已保存的3条关系，没有重跑任务、调用模型或生成“人类标注”。结果是候选复核口径，不是新的人类可靠性数字或问题A效果。真实人工0，未计算κ；8条助手逻辑路径通过仅是程序口径自检，不能证明标注协议在真实人群中可靠。

## 需要增加的测量单位

每个问题单位需保存题目、历史范围、实体字段、等价规则、分区边界、观察投影、所问命题的范围及量词。“允许范围内存在干扰”与“这两个/这批有限输入没有反例”不能互换。有限未见干扰不能直接填成所有允许输入均无干扰；同规范类的早先记录改变代表，不是跨实体干扰的有效对照。

候选协议分别记录粒度选择和同一预先规定单位上的行为判断，并列预定总分母、单位不匹配、契约不兼容、unknown及不适用数量。人类原始表完整保留；如果另报明确判断子集一致率，必须同时报其覆盖和分母，不能替代总体，也不能通过事后丢弃分歧提高κ。字段形式相同不证明两段自由文本语义相同，仍需人工核对。

## 第二遍反证与修订

v1把probe_id放入问题单位domain，导致同一属性引用不同证据编号时也被排成不同问题。这是候选协议自身的错误，v1产物保留；v2将证据编号移至独立evidence_ref，并增加同单位/不同证据编号的反证路径。另将E_M06的同规范实体历史变化标作本对跨实体比较不适用，避免写成“无跨实体干扰”的全任务结论。此处改变比较口径，不改任何已有机器关系或标签。

不尝试用这两个例子调出新的可靠性阈值、造两人填写或重算旧κ。原v0.2、原盲审ZIP和正式启动条件保持；本方案仅是管理端候选schema。阶段目标已达到：合法的不同问题单位、违反题意的实体选择、同问题判断分歧须分别处理。
