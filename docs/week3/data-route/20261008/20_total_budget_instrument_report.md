# 严格总预算工具的零调用验证结果

新增BudgetedClient记录器已通过12/12模拟检查，真实API和模型调用0。它独立于旧成本执行器，不能据此声称正式执行器或真实端到端烟测已完成。

## 现在验证到哪里

所有请求输入与输出进入同一本账，包括单token预检及重复提示。一个35 token的合成例子：预检用10输入+1输出，余额24；生成再次用10输入，输出上限从请求的20裁为14，最终35。下一次请求在发送前被拒绝。该例仅验证预算规则，没有真实token测量或模型成绩。

完整prompt/模型/选项在调用前写入，原响应在检查计数与后续解析前写入，文件哈希与账本绑定。模拟验证计划JSON解析失败时仍保留响应；这能避免未来重现旧B03/C04失败阶段原文缺失，但不能修复历史缺失。

输入占满预算、没有输入上界或调用额度耗尽时，不发送请求。实际计数超过事先输入上界、服务端输出超过输出上限、缺少计数或正文时保留证据并使协议失效；超时标成本未知，禁止下一次请求。已知超额照实记入账本，不能删token、回退花费或拿旧输出截断冒充预算内结果。

## 必须保留的限制

记录器接受的是调用方事先核验的输入token保守上界，并不自行证明这个上界正确。只有上界和服务端上限实际可靠时，才能在发请求前保证总预算。旧执行器仍把预检成本单列，不能未经集成就用于问题A正式评测。

当前模拟传输只返回预设字符串/计数，没有网络模块，不读public或private，也不生成真实候选。保存的synthetic-model、合成证据、合成请求不能写成人工或模型实验结果。尚需接入真实模型计数、候选冻结、接口解析、private延后访问和整题评分；这些环节未经本阶段验证。
