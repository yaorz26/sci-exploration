# P14：公开题面与重复提示的预算占用

问题：同一总token上限下，M2重复需求/计划/已实现代码的开销是近似常数，还是会随任务描述长度与helper数增长，从而改变可用于实现的余额？这一测量影响A中结构关联的解释，但不回答模型质量。

方法：沿用P8/P9已验证的原生Qwen词表/ChatML渲染，仅加载vocab。读取20题公开task.json，不读取隐藏测试、源码或模型成绩。按当前执行器的M0/plan/helper/entry模板，构造明确的2/3 helper占位计划及短/长代码情景。计划不假称模型实际输出，不是假定任何任务的正确拆法，也不称所有可能计划的理论最低成本。

同时比较原indent=2 JSON与语义字段完全相同的紧凑JSON；两种序列化重新解析必须与原公开对象相同。计算逐调用输入、总输入、6500减总输入的最大输出余额及8192单次上下文适配。余额是构造情景，不是假定实际生成长度或成绩。列作者初标/来源仅做描述，不拟合因果效应或稳定多因素回归。

预算本地20分钟、模型0、API0、下载0，一次执行及最多一次因实质代码错误的修订。保存全部构造prompt、计划、数据哈希、词表身份和结果，不重新跑已通过校准。退出是可复核的输入成本情景与对下一探针/数据设计的影响；若无差别则保留负结果并切到其他问题。

使用储备公开题面的长度仅作数据描述，不使用储备被测候选/隐藏成绩选择配置。本阶段不变更正式策略、预算、旧生成结果或原数据。
