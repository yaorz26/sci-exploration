# P45：开发集的联合结构画像是否有描述性支撑

具体未知：在不拆开解释单个因素的前提下，把依赖集合、状态范围、独立可测程度合成任务画像后，开发11题是否仍有多个画像单元可比较？如果画像与来源/显式关联组件一一绑定，主问题A只能做逐题配对和边界描述，不能做画像层关联。

竞争解释：开发集有多个任务共享同一画像且跨来源/组件；画像有变化但主要由来源或相关组件决定；画像几乎每题唯一，不能支持稳定分层。三者会改变后续正式评测的分析表，不改变已确认主问题A。

最低成本验证：只读v5 manifest、显式相关组件表和已有family sensitivity表，构造不可再拆的联合画像键：完整behavior_dependencies集合、state_scope、separate_behavior_testability。分别对全20、开发11、储备9统计画像频数、来源数、显式组件数、同来源/同组件覆盖；保留完整分母和空格，不读测试/private、不执行任务、不按成绩筛选。画像重复不等独立样本，跨来源也不等可识别。

预算20分钟、最多20行，模型/API/下载/任务求值/隐藏读取0，两次修订。若开发画像退化，下一步只做联合画像的描述性协议和适用边界；若有多单元，再设计留一来源/相关组件敏感性，不直接拟合因果或多因素模型。
