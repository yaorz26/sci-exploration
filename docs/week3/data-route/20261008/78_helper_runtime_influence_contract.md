# P36：调用helper是否意味着返回值参与最终结果

具体未知：静态helper调用/运行时调用次数能否区分有效组件参与、入口重算的约束检查、调用后丢弃？竞争解释为调用即可视为组件组合，或同样调用仍有不同结果依赖。

最低成本验证：沿用P34索引连接与原输入重算的已保存程序，增加一个调用_sorted_keys但丢弃其返回值、入口直接重算的手工程序。先冻结代码/六手算；只新程序执行六输入，原两程序正常结果从P34保存复用。对首碰撞及reverse两输入，在固定边界把helper返回改为反向keys或身份indices，再作RuntimeError阳性；记录helper调用次数、实际终值/异常、相对于已存基线的变化。同调用次数若对应错误输出、仅断言失败、返回不变，就否定“调用即参与”的粗代理。

预算20分钟、六新程序正常求值+最多12干预求值、模型/API/旧格/旧参考/隐藏0、两修订。干预helper故意不符合局部契约，不把组合后的失败当模型分数；错误返回不能据此证明真实模型缺陷，干预仅识别此手工程序对有限观察的敏感性。RuntimeError传播与返回值贡献分开；运行时敏感性不自动生成前置分组或最小接口真值。

若成立，停止不断新增手工反例，转研究能否在实际保存的生成方案上观察这些指标及失败缺失，或转新功能家族；不把更多构造正确例子当主问题A的效果答案。
