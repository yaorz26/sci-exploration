本地模型`qwen2.5-coder:7b`，Ollama记录7.6B、Q4_K_M、模型摘要`dae161e27b0e90dd1856c8bb3209201fd6736d8eb66298e75ed87571486f4364`。temperature=0.2，基础seed=20261008，helper seed依次加1、2、3，入口seed加10；上下文8192。每题每臂首个候选，不进行成绩驱动的重试或选择。

M0一次实现完整入口，可以自行使用helper。M2自主计划2--3个helper，再逐个实现并组装。每臂可分配的输出token上限4096：计划512，各helper640，剩余分配入口。先保存全部候选及选择冻结记录，再只评4开发题（B01/B02/C01/C02）；more-itertools/confuse的4储备题未生成或评被测模型候选。所有失败保留在4题分母中。

实际输入、输出和调用次数不相等；本轮只验证流程，不能据此回答严格等总成本的研究主问题。

## 公开提示诊断与评分器修复

额外冻结2次B01公开诊断：中文纯文本、英文纯文本，模型/temperature/seed/上下文/输出上限相同，只评分两个公开用例，不执行隐藏测试、不挑选候选替换探针结果。

发现英文候选带示例`print`，正确的返回结果被额外打印污染了JSON评分通道。修复为把候选导入与运行的打印转入有大小上限的诊断通道，再按函数返回值评分。保留原错误输出和固定候选；打印并返回正确值的回归检查通过。修复后，中文候选公开0/2，英文候选公开2/2；不能从单题每种一个候选证明语言或格式效应，也不能把公开2/2说成整题隐藏全过。

修复评分器后对已冻结v2候选事后复算，两臂仍0/4；8题参考与另一实现共16项复查均通过。事后复算另存，不覆盖v2原始成绩。这处测量缺陷不能解释v2的真实排序、状态、返回结构和接口错误。

本轮本地调用合计30次：自动审查3、探针v1 8、探针v2 17、公开诊断2，低于100次上限。代码候选均在本地生成；WorkBuddy仅作有限自动复核。未训练、未启动RL、未发布数据。

## 阶段审查与方向审查

已获得可运行原型、有限独立自动复核、两轮流程失败及成本证据。仍缺：最终数据代表性、独立人工真值、可重复结构量表和正式总成本控制。当前结果属于**开发诊断**，不是主问题A的正式否定结果。

选择先推进数据与测量定义：保留所有8题，补入跨多个行为环节的项目功能及开发简单对照，按质量规则扩至20--30题；修订“内部局部状态/跨操作状态”和“逐步输出可查/阶段可单独验证”的定义。正式比较前另冻预算、候选策略和结构标签。暂不扩大同一配置的生成，不凭模型是否做对删题，不把英文公开候选加入私有成绩驱动的候选选择。

这是当前有限探针的停止点，D1方向继续。下一批功能候选已回查源码存在，见`09_dataset_card_and_expansion_candidates.md`；它们尚未构建或通过质量验收。

M2的2--3个helper上限是本次方法配置，**不是数据集对内部结构的要求**。正式方法需要在总成本约束下重新规定可选拆分数量与接口检查；本次超过上限的失败不能直接推断该任务不适合其他粒度的拆法。
