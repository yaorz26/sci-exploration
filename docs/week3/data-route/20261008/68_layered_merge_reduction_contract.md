# P31：纯函数层合并是否能用逐对归并，组合顺序是否足够

具体未知：F03前层优先、递归合并对象的功能，能否通过局部正确的二元合并逐层组合？竞争解释：二元规则与多层一致、调整结合顺序即可；或“同键所有候选都必须是对象”是全集合门槛，逐对合并丢失类型/来源证据，即使各二元调用正确也不能一般替代多层需求。这会提供无跨操作状态的另一种阶段/信息保留义务。

公开需求选择F03，不读隐藏选题/模型调参。先手算三层源、固定顶层x的投影：A={x:{a:1}}、B={x:{b:2}}、C={x:0}。公开需求因出现标量候选，不递归合并x，结果取最高层整个{x:{a:1}}。局部正确二元合并A/B先得{x:{a:1,b:2}}，再C取该整个对象；先B/C得{x:{b:2}}，再A又递归得{x:{a:1,b:2}}。两个结合方向都可能错，不仅是“选错了顺序”。

另A对象/B标量/C对象的对照检验两个结合方向是否不同；全对象及缺键控制区分门槛、优先顺序和递归贡献。仅公开声明的JSON源对象、前层优先、不变输入；null是提供值而非缺失，须保留。先冻结手算锚点和最小有限域，再使用原参考/另一结构对n层及逐对折叠分别求值，缓存本轮重复两源输入，不重跑原307。

预算本地25分钟、模型/API/下载/隐藏案例读取0，单键六候选值的三源有限格≤216、≤8手算、至多两修订。输出保留参考与另一结构、左右归并、实际域及distinct输入/求值分母。二元局部通过不当模型成绩，不能据有限无见证证明结合律；若存在违反即支持反例，若域内一致只报范围。阶段结束据证据选择信息保留方案或换路，不无限扩相似层合并。
