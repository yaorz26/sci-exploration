# P13：局部可测机会与组合契约

问题：任务级yes独立行为可测，是否能作为拆分方案组合容易的直接证据？竞争解释H_local为局部行为正确足以解决接口协调；H_edges为组件可能都正确而数据版本/缓存键绑定错误使组合失败。现有标签只记录行为机会，尚未记录方案实际数据流义务。

选B05树变换/路径筛选、C03调用键/求和/缓存，两题均作者yes，一题没有跨操作历史、一题有资源竞争。不用模型生成，不根据隐藏成绩选题，选它们因外部契约能构造明确的接口反例。

方法：为每题写两个不同内部结构的正确实现；在正确可分组件不变的前提下，只改变入口数据绑定，构造2个具体缺陷。先用需求级局部手算锚点验证组件，再冻结代码与源哈希；之后才评原公开/隐藏测试及独立构造的手算集成反例。局部通过与整题通过分开。

B05边界义务为后阶段收到变换后的树，路径来自删除后的数组索引；只改单一边即可触发反例。C03边界义务为缓存用完整规范调用键，清空时保留累计计数；正确求和与键构造不能代替此状态绑定义务。

预算本地30分钟、模型0、下载0，最多两次修订；可信作者实现每进程20秒/1MiB。退出为两个合法结构的外部等价证据、4个组合缺陷及定位、局部锚点与整题判定的不同信息。人工设计缺陷不当真实模型发生率，不从局部有限通过推全域正确。若缺陷未被原测试发现，保留并登记数据集遗漏，不覆盖旧版本。

角色当前助手，非独立人工；不修改原结构标签或正式协议，不进行模型候选选择或储备调参。结果用来决定是否需要计划级契约证据，而不是把所有yes任务改为不可拆。
