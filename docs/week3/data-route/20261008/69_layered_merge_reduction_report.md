# P31：局部正确二元合并不保证多层组合正确

F03公开规则要求同一键的所有候选均为对象才递归合并。它没有跨操作共享状态，但最终合并对象不足以作为一般的下一阶段输入。前层{x:{a:1}}、中层{x:{b:2}}、末层{x:0}应返回{x:{a:1}}；先合并前两层，或先合并后两层，均得到{x:{a:1,b:2}}。该手算输入在执行和本阶段隐藏描述暴露前已保存。

七个手算锚点包括上述反例、A对象/B标量/C对象的结合律反例、全对象、缺失、null与空对象控制。参考和另一结构实现的三种计算各42项手算预期全部符合。本轮六值域为0、null、{}、{a:1}、{b:2}、{a:1,b:2}，同键三源216格。两实现直接多层结果216/216一致；左归并28/216偏离，右归并14/216偏离，两者同时偏离14/216，左右结果不同14/216。两个14集合并非同一个概念，不能合并为“28个任务”。

缓存后每实现273个不同实际输入/调用，共546次实现求值；2230是缓存求值引用次数，不能报成实际调用。输入保持且无异常。未重跑原307用例、未调用模型或API，未使用隐藏期望评分。

本阶段曾在定位实现时截取curator文件，意外显示F03的12条隐藏输入描述及相邻题的描述。记录保留此失误；后续锚点和有限域属于公开规则的管理端诊断，不能称为未见确认、储备模型效果或独立验证。隐藏内容没有进入模型提示，原题和切分没有改变。

竞争解释得到区分：调整括号不能普遍救回二元最终值归并；问题来自全候选类型门槛及最初高优先级整个值的信息丢失。它支持在任务结构记录中区分“无跨操作状态”与“中间接口必须保留联合判断的信息”，不说明分解方法平均效果，不证明所有纯函数流水线无效。
