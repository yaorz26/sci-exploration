# D1复核前置审计报告（2026-10-08）

## 结论

复核前置条件部分通过：盲审包隔离检查通过，两轮成本账本重算通过；但当前20题的切分不能支持结构因素的因果比较，正式模型评测暂不启动。

## 盲审包

对 experiments/d1_blind_annotation20_v2_20261008/ 做了机器检查：

- T01—T20共20个唯一盲号，review_form有20行且全部保持unknown/空白；
- curator_key_private.json包含20个映射，requirements_blind.json中没有来源名、仓库名、D1任务号或已知提交标识；
- 目录只有README、需求、空表和私有映射四类文件。

这说明包的文件隔离符合“审查员不看来源、初标、隐藏测试和成绩”的要求。它不等于已经完成独立人工审查；当前人工判定仍为0，不能计算κ。

## 数据覆盖审计

20题切分为development 11、reserve 9。仓库和切分完全重合：boltons 6题全在development，cachetools 5题全在development，more-itertools 5题全在reserve，confuse 4题全在reserve。20个function_family均只出现1次。结构标签也不是均衡设计：operation_sequence只在两类来源中出现，none和operation_sequence的testability分布不一致。

因此，若直接比较当前11道开发题，来源、家族和结构会一起变化；观察到的差异不能归因于“是否有共享状态”或“是否适合拆分”。正式协议草案要求先完成双审，并重新安排正式比较切分；若无法做到跨来源覆盖，只做描述性边界。

## 成本账本审计

两轮成本探针均通过机器重算：

- B04/C03：summary与call_ledger均为24次调用，预检12次、生成12次；每个候选的生成token等于账本中 prompt_eval_count + eval_count 之和；预检和真实生成的prompt计数逐一相等；
- B03/B05/C04：summary与call_ledger均为32次调用，预检16次、生成16次；候选冻结数量、token合计和预检匹配全部一致。

机器审计只证明记录自洽，不证明模型方法有效，也不替代对private隔离和人工结构真值的审查。
