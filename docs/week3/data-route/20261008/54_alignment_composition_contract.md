# P24：无状态排序的有效行域与合法分解边界

具体未知：M05的跨列对齐是否必须先截断再排序，还是能在不同合法阶段顺序下保持同一有效行域？竞争解释：需求确定唯一阶段顺序；或阶段顺序可变，但排序索引必须最终限制在所有列的共同有效域，纯组件正确不足以保证组合正确。

最低成本验证仅用公开允许域。冻结两个手工两helper方案：A先以最短长度截取各列，再对有效行生成稳定排序索引；B在所有键列可用的范围上排序，再在组装时过滤为所有列均有效的索引。B的无效行不参与输出，键列值仍符合公开可比较保证。strict/空域/reverse需按同一公开需求处理。两方案不规定模型必须如此拆分，也不当作模型结果。

固定纯helper局部契约：排序器的索引域是明确传入的键域，并按keys/reverse稳定排序；对齐helper提供所有列的有效上界/截取。冻结手算有限锚点和代码后，只改变B的组合，把“过滤索引<共同上界”误改为“截取排序结果的前L个”。找输入各组件局部正确但组合错误/越界的例子，保持组件字节/AST不变。对缺陷用公开手算例，不读取隐藏选择；无需重新跑原20题测试。

预算本地25分钟、模型/API/下载0、两合法方案/一个组合缺陷、最多1000有限输入、两修订。保存正确与失败原输出、不同输入/求值分母；异常按不可测/失败而非关系相等。无状态不等于无数据域义务，额外输入不计307，初标和正式盲审不回写。

第一手算候选：columns=[[2,1],["a"]]、keys=[0]、strict=false。共同有效行只有索引0；正确输出[[2],["a"]]。在键域[0,1]先排序得到[1,0]，过滤索引<1得到[0]合法；只截取首1项得到[1]，非键列越界。反向及同键稳定性另给锚点，不以特例改公开域。

如果证据只重复已有“组件对不保证组合对”，停止扩同类缺陷，下一项转测量协议如何区分任务可测机会、特定计划边界和对齐域义务；不靠持续构造例子虚增贡献。阶段结束按新证据选择下一项。
