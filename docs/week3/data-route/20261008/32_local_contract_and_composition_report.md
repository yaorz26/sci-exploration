# P13结果：行为可单测仍需计划级数据流义务

在B05和C03两题上，两个不同内部结构的正确实现均通过原公开/隐藏测试和手算集成反例（共4/4实现）。保持行为helper字节和语法树不变，仅修改入口连接或状态绑定的4个缺陷均被原数据集及手算反例识别。局部24个不同锚点在正例和缺陷程序中共72次求值全部通过。

这说明任务存在两个可单测行为，与某个拆分计划正确组合是两层证据。它没有否证原假设H1“可单测机会可能有助于拆分”，也不说明yes任务不应拆；它要求额外记录方案实际连接的契约，避免用任务级yes代替计划级协调条件。

## 两题与四个具体边界错误

| 任务 | 两个合法结构 | 只改入口的缺陷 | 关键边界义务 |
| --- | --- | --- | --- |
| B05 | 树变换后另遍历筛选；一次递归联合返回树和匹配 | 将原树交给筛选 | 下游消费变换后的版本及删除后的索引 |
| B05 | 同上 | 额外把threshold乘factor | 变换参数与筛选阈值语义不能混用 |
| C03 | 独立调用键/求和加OrderedDict；内联行为加记录列表 | 只取完整调用键中的args部分 | 缓存必须用完整位置/关键字语义键 |
| C03 | 同上 | clear时累计计算次数也清零 | 清空缓存与累计计数是不同状态义务 |

B05手算集成输入为`tree=[null,3],factor=2,drop_null=true,threshold=5`；结果树必须为`[6]`，匹配为路径`[0]`的6。两个行为组件可正确变换/筛选自己的输入，入口错传旧版本或新阈值仍会使结果错误。

C03手算序列是kwargs `{a:1}`调用、`{b:2}`调用、clear，容量2；两次结果分别1与2、累计计算次数最终2。规范调用键和求和组件均未改变，入口丢关键词或清空计数仍使组合错误。

局部锚点与程序先冻结、保存哈希，之后才评既有公开/隐藏测试。程序由助手按公开需求人工编写，不是模型候选；不根据隐藏评分选择生成方案，不修改原数据、不新增307原案例。24个不同局部锚点的72次执行不是72个独立行为、人工审查或全域正确性证明。

## 对测量与贡献的影响

建议把“需求中可单测的行为机会”保留在任务侧；实际生成计划另记组件契约、谁拥有状态、谁消费哪个版本的数据、哪些键/计数必须保持，以及是否遵守依赖。两者不可互换。名字和签名正确只是较外层契约，B05还需要数据版本和路径语义，C03还需要缓存身份与状态所有权。

本次有限人工缺陷实验说明当前两题测试能识别这四个组合错误，不能估计模型中的发生率，也不能主张所有组合缺陷覆盖。它为自由拆分数据集提供了可追溯的计划边界反例；不会把人为设计的“好拆法”作为唯一标准答案。
