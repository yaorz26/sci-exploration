# P42：非缓存多统计功能是否提供新的独立契约机会

具体未知：boltons Stats公开功能能否提供至少两个用途不同、可各自给输入/输出的语义行为，且不是作者预定有序转换管线？这个候选针对P40初标表中独立可测与依赖标签对应的缺口，不代表已经独立测量/填格成功。

竞争解释：多统计量只是同一整体行为的多个展示字段；或中心位置、离散程度等不同用途可由同一数据分别定义契约；或浮点/默认缺值/有效域使所谓独立契约只能局部成立。共享同一输入并不自动是共享可变状态，也不自动证明独立。

最低成本验证：先冻结固定commit公开Stats文档/API定位，不看原private；定义候选适配范围及至少两个行为的用途/域/观察单位和反例锚点，再执行少量本地公开新输入。依赖代码路径不当标签依据，不能为填格把应有ordered_transform删掉。候选若需要实现内部唯一方案，则拒绝该设计；若只能有限局部成立则保留条件。source查询可以从已有固定ZIP读取一个模块的docstring/API，不运行源码寻找隐藏案例。

预算25分钟、一个公开功能/最多6手算锚点/至多300额外整数小域输入、两实质修订；模型/API/付费/训练/新增下载/原测试/隐藏读取0。新增候选只入扩展池，原20、307、作者初标、11开发9储备不改，人工0。旧P31储备暴露限制不消失，此候选为开发来源新公开功能，不称独立未见确认。

退出：明确是否真的有不同用途的任务側契约、行为域/测量分母及对补足设计的影响；若不成立，保留结果改查另一个公开非缓存功能，不重复扩大统计枚举。完成后按证据开始下一项，不新增模型调用或宣称收益。
