# P21：有限隔离关系会不会被错误程序虚假满足

具体未知：P12结构关系若将来用于生成程序诊断，仅通过“插入另一实体动作后目标投影不变”是否足以支持程序实现了实体隔离？竞争解释：关系通过意味着基本功能实现；或恒定/退化输出也能满足相等关系，关系符合性必须与需求行为正确性分开。

最低成本验证：只读取P12保存的C04关系及参考输出，不重跑552关系的参考实现。冻结两个明确错误的研究程序：一份输出记录形状、实例键与基本类型合法，但所有call返回0、计数/缓存尺寸始终0；另一份总抛ValueError。前者观察相等关系与历史/同实例淘汰阳性是否区分，后者检查朴素错误对象相等是否被当成关系通过。不是模型候选，不用失败结果调模型策略。

先冻结代码、选择的全部C04关系编号、投影定义与判定规则，再运行最多120条保存关系，每条两输入/两错误程序，保留输出与失败分母。关系执行成功且输出符合最基本形状/类型才允许投影；异常、形状不符或输入改变记不可测，不记隔离通过。不把通过此基础门槛当语义正确。绝对行为符合性用保存参考输出单独记录；手算阳性与有限阴性分别报告，不求一个混合总分。

冻结后原2公开及隐藏案例仅验证两个新人工错误程序，案例数从文件读取、原测试不改。原P12结果不被覆盖，它用于测量需求参考/另一结构实现，不是本次给生成错误程序打的分。新诊断关系不计原307；关系方法已有前人工作，不主张方法首创或人工可靠性。

预算本地20分钟、模型/API/下载0、两个人工错误程序、最多120关系，单评分进程20秒/1MiB；最多两次实质修订。若只得到预期退化反例，不为增加数量扩更多相似程序，而转P22：已有两个跨来源扩展候选是否真正解除P15来源/家族别名。研究完成后保存阶段审查、方向审查，再启动下一项。
