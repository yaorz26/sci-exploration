# P24结果：共同有效域约束允许不同合法阶段次序

M05的两个手工两helper方案使用完全相同的纯组件，一个在所有列的共同有效域内排序，一个在所有键列的可用域内排序后过滤到共同有效域。两者均通过7个先冻结手算锚点（14次正确方案求值）和640个有限输入（1280次正确方案求值）。不能把公开“先截到最短长度”的外部行为要求直接写成所有内部实现必须具有同一阶段顺序。

## 有效域义务及组合反例

两个helper分别明确计算共同域/键域上界及稳定排序索引，三程序中的组件字节和AST相同。6个不同局部锚点、三个程序各执行，共18/18通过；第三程序只是把组装时`indices=[i for i in indices if i < length]`改成`indices=indices[:length]`。

最小反例为columns=[[2,1],["a"]]。共同域仅索引0，键域排序结果[1,0]。先限制域排序得[0]；先排序过滤<1也得[0]，均输出[[2],["a"]]。错误组装截取前1项得[1]，读取非键列越界。组件正确没有约束入口必须消费正确的索引集合。

有限格为键列长度0—3、键值0/1/2的全部序列、非键身份列长度0—3、reverse/strict各两值，共640输入。另用按行zip、排序再转列的手工对照求值640次，不调用原隐藏测试；组合缺陷求值640次、58输入失败。58/640是这套人工格中的缺陷检出，不是模型出错率或随机总体概率。

## 第二遍质疑

合法第二方案会排序一些最后不输出的键域行，可能多做工作。本阶段检查的是合法存在性与连接义务，不是速度、token复杂度或哪种模型更易生成；不据此推荐第二方案为正式策略。

先在较大键域排序再筛选，与只在有效域排序相容，需要键值比较/稳定排序规则相容。本格只用声明域内整数、有效键，未证明任意异常比较对象；公开题面已保证对应键列可比较。strict长度不齐按需求ValueError，空共同域输出[]，它们作为手算分母保留。

阶段收益超出“组合也会错”的已有一般结论：确定了一种非缓存、无跨操作状态的共同有效数据域义务，并给出同纯组件、不同合法次序。任务结构证据不应把作者的一份步骤清单当唯一正确分解；后续记录应能表达数据版本、身份、有效域及持久状态等不同连接条件。
