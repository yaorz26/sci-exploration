# P52：公开文本流的历史依赖与合法重算

具体未知：固定boltons.HTMLTextExtractor的分片feed/get_text语义，能否提供缓存家族之外的输入历史候选？仅把片段各自html2text再拼接是否丢失跨片段标签/字符实体；一次持续解析与按累计前缀重算是否都可满足相同观察契约？这补主A当前历史/来源/家族支撑缺口，而非把任何有源码状态的函数直接初标global。

竞争解释：文本片段可独立提取并拼接；或者跨片段词法信息必须保存，但可放在持续解析器或完整原前缀重算中，不强制跨helper可变状态；或者上游best-effort规则/边界无法形成清楚契约，应该留池换另一公开非缓存功能。

最低成本：来源公开API定位在契约前已做，不冒称未见来源。先冻结同commit strutils模块/HTMLTextExtractor585—609/html2text612—623及许可哈希，六全新完整字符串的分片与逐值终值预期。任务形态仍JSON输入chunks/输出每次feed后text快照及终值，不写真实文件/联网；三手工结构：持续解析、累计前缀重算、逐片提取后拼接控制。快照由前两结构互证，不能当独立手算真值；终值有事前解析锚点。输入无修改、所有诊断公开、结构标签先null/扩展另池、同boltons来源不充新独立来源。

边界六组：标签拆开、实体拆开、标签名与结束标签拆开、普通文本控制、数值字符实体拆开、属性引号拆开。每组至多三结构18solve（底层feed/html2text次数另记，不伪装18原API），不得调用/泄漏原测试。预算25分钟两实质修订、最多六组；模型/API/下载/原测试/private/模型预算增量均0。不能形成可复核需求就保留负结果、换非缓存函数，不扩无界HTML语法；成功后审查真实新增支撑，不能照抄粗标签。
