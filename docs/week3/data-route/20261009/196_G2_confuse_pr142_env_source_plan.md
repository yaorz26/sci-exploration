# G2候选计划：confuse PR142环境变量配置源任务

所属宏观阶段：D1-G2真实项目功能构建；承接195号三轮新问题挖掘。具体未知：官方PR142能否恢复为真实父/合并项目任务，使环境变量→配置命名空间→最终读取形成非路径数据连接，同时不把环境状态或JSON包装当作任务功能。

竞争解释：H1父/feature可恢复，EnvSource与配置优先级形成跨组件数据链，公开操作可稳定观察；H2只是独立EnvSource字典转换，无法观察项目级连接；H3需求虽真实但源码/许可证/依赖不可恢复，不能形成候选；H4环境变量污染/机器环境使公开输入不可复现。

可见终点：`experiments/d1_G2_confuse_pr142_env_source_v1_20261009/`下来源元数据、父/feature非测试源码或否决证据、最小需求、公开环境输入/输出锚点、不同组织实现与功能遗漏控制，及research_pool_only纳入/No-Go结论。不是模型效果、正式结构标签或发布数据集。

## 三轮计划审查

### 第一轮：可行性

先读已保存`confuse_pr142_metadata.json`、`confuse_pr142_files_metadata.json`和PR126候选公共许可/依赖记录；随后最多两次定向恢复父/feature非测试源码（优先官方API/raw commit；失败则只保存元数据失败）。不克隆整库、不读PR142变更测试、不查D1隐藏、不调用模型。

最小实现只需能导入父/feature包并观察：单环境变量、前缀剥离、嵌套分隔或优先级中至少两种公开行为；若必须完整依赖PyYAML，使用已有固定依赖，不下载新大包。最多30分钟或两次恢复，源码无法取得就No-Go，不改题目路线。

通过条件：至少有父/feature提交及许可证、非测试源码可恢复，或失败记录能说明权限/网络/来源缺口。第一轮不以候选通过为预设。

### 第二轮：意义与重心

PR142可能比PR126更贴近项目配置来源，但功能说明很长。只保留改变G2缺口的最少行为：环境变量来源如何进入配置对象、与已有文件/命令行来源如何决定优先级、嵌套命名是否保持。不要把所有EnvSource参数做成矩阵，不复制PR正文为需求，不增加同一功能的多版本包装。

若只能观察EnvSource自身字典，降级为来源行为证据，不纳入“跨阶段连接”候选；若父/feature没有真实项目调用上下文，保存No-Go。成功只需一项自然功能任务，不追六项/三来源。

### 第三轮：区分力与可信度

父/feature差异必须来自已合并PR与直接父提交，需求取PR公开说明和父API，不把合并源码反推的实现细节写入模型可见需求。公开测试、feature补丁、控制实现与正确答案留在评价侧；环境变量在每个worker中显式设置/清理，避免主机环境混入。

最小锚点至少包含：无环境变量保持父行为；单变量前缀映射；与文件/命令行冲突时的优先级或嵌套解析（只在官方说明明确时）；一个功能遗漏控制。两个不同内部组织必须共享外部行为评价，但同助手构造不算人类真值。新候选formal_labels/split null，来源仍confuse储备仓库，不并原9题；污染unknown。

## 执行顺序、预算与失败转向

1. 保存计划审查后读取两份PR142本地元数据，确认文件列表与父/merge SHA。
2. 恢复最少非测试源码/许可证到独占目录，做hash和可见边界清单；网络失败不重复超过两次。
3. 冻结需求和公开锚点后，分别运行父/feature最少诊断和一个不同组织/遗漏控制；实际行为≤12个场景，若源码不合格不执行。
4. 输出纳入或No-Go，保留失败与下一问题；不读上游测试/原D1 private/模型结果，不把通过数当贡献。

预算：来源恢复≤30分钟、最多两次实质尝试；新增下载只取必要文件且总量不超过原D1 200MiB边界；行为≤12场景，模型/API/人工/训练/RL/发布0。G2单项困难超过30分钟无新证据即换路；若PR142失败，G2转实际已有候选交付与K3缺口说明，不继续无界搜索。

当前状态：计划三轮审查未完成，正式源码恢复不得开始。

## 第一轮审查：可行性（未执行恢复）

发现：PR142元数据已有parent/base/head/merge，但本地没有对应父/feature源码；此前网络恢复也曾受代理限制。若把“有元数据”当“可执行候选”，会重复P77的过度承诺。

修订：允许两次最小恢复尝试，失败本身是No-Go证据；只要能拿到父/feature非测试文件和许可证才进入行为诊断。行为上限12且不先建立矩阵；模型/人工/隐藏均0。第一轮通过。

## 第二轮审查：意义与重心（基于第一轮修订）

发现：EnvSource参数很多，按prefix/sep/lower/parse_yaml_docs/handle_lists全做会变成覆盖率和包装工作。主A所需的是数据连接是否存在，不是参数数量。

修订：只保留来源进入配置对象、优先级/嵌套中由官方说明支持的最少行为；最多一个单变量、一个冲突或嵌套、一个保持行为和一个遗漏控制。无法观察跨组件就降级，不继续扩展。

判断：若成功，补K1且与PR126路径连接不同；若失败，明确真实项目任务恢复边界。第二轮通过。

## 第三轮审查：区分力与可信度（基于前两轮修订）

发现：环境变量属于外部机器状态，若未在worker内清空设置，输出会混入主机；把feature实现字段写入需求会泄漏；confuse属于原储备仓库，不能将新项写成独立确认。

修订：每worker显式环境隔离并记录；需求只取PR公开说明/父API；feature/patch/测试/控制留评价侧；新项research_pool_only、formal_labels/split null、污染unknown。父行为与合并行为使用同一最小公共调用。

判断：三轮均有具体修订并通过，现可执行来源恢复；执行中若方向偏离立即保存失败并停止。
