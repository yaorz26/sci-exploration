# P91：真实项目补丁执行入口

研究问题：在6500题目—方法总token上限内，现有BudgetedClient能否接收真实包源码补丁，保留请求/回答并区分预算拒绝、计量失效、补丁失败和实际行为失败？当前solve入口不能承接两个真实项目候选；本阶段只打通这一必要入口，不声称拆分效果或新增结构样本。

竞争解释：H1预算客户端与代码表示无关，可直接复用；H2补丁应用/工作区隔离会误收或误拒，不能可靠评价；H3保存失败分母仍会把未执行行为记成实际0分。

可见结果：一个可运行的研究侧项目补丁入口，以及预定控制的原始请求、原始回答、冻结清单、工作区和行为输出。正确/不完整补丁能到达不同的行为结果；格式失败与预算拒绝不会伪造行为执行。结果限于给定文本和模拟transport，不是模型生成，也不启用网络transport。

初拟步骤：1读旧预算客户端/solve入口和已有项目评价器；2新增独立补丁入口，复用BudgetedClient与原生词表，不改旧pipeline；3先保存输入/给定回答/程序/预测哈希；4执行一次预定控制集；5保存阶段与方向审查，停止适配支路，根据新证据三轮挖掘下一问题。

数据：confuse父工作区、P86仅需求API上下文与研究侧正确patch，P83公开评价器；不完整patch只遗漏core.py。另用cachetools父工作区、公开需求和父TTLCache API，不读上游测试。给定研究答案与提示分别保存，生成入口不读取feature快照或评价器。

指标：是否发出transport请求；已知输入/输出文本token；补丁是否严格应用；完整候选是否存在；行为是否实际执行及通过数；失败类别；原始父文件哈希不变。缺失行为结果为null，不填0/8。

预算：模型/API/人工/联网/付费/训练/RL/发布0；本地上限30分钟或两次实质修复无新增证据转向。6500/8192仅模拟严格计量路径；全局约98/100模型调用不动。输出目录exclusive-create，旧数据/代码结果不覆盖；正式标签/split null，公开诊断不是未见确认。

## 第一轮审查：可行性

发现：BudgetedClient已经在解析前保存原始请求/响应，失败计量保留且禁止继续；旧run把任务限定为开发manifest+solve签名，直接改它会把新研究池误当正式开发题。真实两个包均有可独立调用的公开评价器，父源码/给定正确答案已本地保存，无需模型或下载。

修订：采用独立research_pool_only适配文件，BudgetedClient保持原样；仅通过注入transport运行模拟控制，CLI不提供网络入口。行为评价在冻结所有候选之后执行。初拟不调用模型的路线可行，通过；下一轮审查适配工作是否会再变成连续包装。

## 第二轮审查：意义与重心

审查时间：2026-10-09T09:39:16.610224+00:00。承接第一轮“独立入口可行”，进一步发现：仅证明补丁解析成功会重演P67—P71的工具支路；它不能改变两个任务的可用性判断，也不能回答A。因此删除打包、发布门与更多格式变体，执行结束立即退出适配工作。

修订后的唯一控制集为六个给定回答/transport条件：confuse完整补丁、遗漏core补丁、第二文件原行损坏的多文件补丁、请求前预算拒绝、响应缺计数、cachetools完整补丁。前三者区分可运行/行为缺陷/应用失败；后两者区分未请求与成本未知；cachetools检查同入口能承接另一真实任务，而非只为confuse写死。只有完整confuse、遗漏core、完整cache三个工作区进入原公开评价器，共21次旧诊断，经新代码路径执行有明确理由，不算新测试输入。

通过依据：可见产物让研究池任务首次通过同一个预算客户端到达项目行为评价；这只是研究必要基础设施，不单独称科学发现或A的效果。上限六条件、两项目，不扩大候选数量。进入可信度审查。

## 第三轮审查：区分力与可信度

审查时间：2026-10-09T09:40:11.381967+00:00。承接第二轮六条件限制，发现四个实质风险并修订：

1. 只允许参考改动的三个文件会把合法单模块替代和新helper误拒。补丁目标允许父包内任何现有.py和新增.py；不能用参考改动表限定目标。统一diff暂不支持删除/重命名/二进制，明确记为表示边界，不能据此认定功能错误。纯内存小例验证新增文件及越界拒绝，不计任务输入或模型结果。
2. 多文件第二hunk失败不能留下“第一文件已应用”的半候选。先在内存校验所有文件、再复制父工作区落盘；失败没有candidate workspace，也不进入行为评价。上下文须逐行、原/新坐标和行数一致，不做模糊匹配。
3. 模拟回答的原生词表计数不能冒称服务端实际消耗。所有transport标为simulated=true；响应缺计数使cost_status=unknown，禁止用0补填；请求前拒绝的行为null、消费0有真实未请求依据。
4. 评分必须在六条件的原始回答/候选/失败全冻结之后；父工作区和评价器哈希校验。生成入口只接父源码、公开提示及transport，不读取feature或测试。评价器使用指定可信脚本和独立进程；本阶段只执行给定研究代码，不声称可安全执行任意敌对代码。

最终执行计划：新增严格项目补丁函数与独立预算入口；编写六条件零模型驱动（原生计量，给定回答明确归研究者构造）；事前冻结预测/input/reply/源码哈希；生成所有候选后冻结，再实际21次旧诊断。正确confuse预期8/8、遗漏core7/8、cache5/5；后文件损坏patch_failure、预算拒绝budget_or_context_failure、缺计数measurement_failure，三种失败behavior=null。若预测不符，保留原输出并定位原因，最多两次修复/30分钟无新证据换路，不补格。结果带完整6条件分母、2任务、3行为工作区，不能当6独立任务。
