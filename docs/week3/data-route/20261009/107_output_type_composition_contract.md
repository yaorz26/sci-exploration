# P50：数值相等是否保留项目消费行为

具体未知：E_B09题面count整数，但原json_equal允许数值1=1.0。一个浮点数量返回会不会在独立JSON计分中通过、在以数量创建索引的项目消费中失败？这决定候选数据集怎样限定“项目功能”兼容性，是否需要候选专属输出类型约束；不追溯修改原20规则。

竞争解释：JSON数值相等足以保留所选消费行为；或者评分相同但range(count)消费不同，任务声明的整数约束没有被评分器落实；或者消费依赖是我们额外加的要求，不能推为所有项目函数都需严格数字类型。第三种限制即使第二种获证也保留。

最低成本：执行前冻结一个全新公开诊断payload={data:["x"]}、expected={count:1,mode:"x"}；四个完整程序分别返回count 1/1.0/True/2，mode固定x。各经原有界评分一次（4solve），保存机器输出；另四次消费list(range(result.count))，明确这是公开构造消费者而非boltons真实调用点。比较原评分/消费与候选count精确int形状门槛，最多12个单位。预期原分数true/true/false/false，消费正确true/false/true/false，联合形状+原比较仅整数正确者true。这些预测先于执行保存，不反向构造答案。

预算15分钟、4程序/4新solve/4消费/4形状比较，两实质修订；模型/API/隐藏/下载/旧12诊断重跑0。如果没有分歧则不加形状规则；出现分歧则保留原规则，E_B09登记候选专属形状门槛待单独验证。禁止将构造消费者当真实项目集成效果，禁止一次反例泛化全部原题缺陷。完成先保存审查/计划，再启动影响范围的最小前置核对。
