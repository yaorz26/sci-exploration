# P53：终值正确能否掩盖提前结束前缀的错误快照

具体未知：把每个累计前缀当完整输入、feed后close再get_text，是否和P52未close的逐步观测一样？即使完整六终值相同，中间快照会不会不同，使终值诊断不足以检查任务声明？主A需要分清历史观察单位与方案实现状态。

竞争解释：六组里close不影响快照，旧终值/轨迹足以支持契约；或者完整终值过但部分前缀提前EOF输出不同，必须明确快照时机并判全轨迹；或者上游规则不可独立清楚说明，应把流式候选留池而非强迫模型猜内部时机。

最低成本：冻结P52六轨迹/源码哈希及新结构（每步完整前缀feed+close+get_text，下一步从原输入重算）。只新六solve/一个新程序，旧18solve不重跑。终值用原事前预期；快照直接与保存持续结构比较，明确同源非人类真值。另先解析四个第一前缀的EOF预期：`A &am`→`A &am`，`<`→`<`，`<a href='x`→自身，普通`A`→`A`。若第一三个输出与保存feed快照不同则支持观测时机边界，不能称上游bug。

预算15分钟、六组/六新solve、透传记feed/close/get_text次数，最多两修订；模型/API/下载/原测试/private0。六完整字符串未强制close与终值一致不推广所有HTML语法。发现漏测后对未来候选明确EOF/观察语义，原20/原标签/旧成绩不改，不不断增加同类坏解析器。
