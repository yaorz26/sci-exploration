# P82 真实候选的结构证据审查

## 具体未知

PR #126 的真实源码是否能分别观察主问题 A 需要的三类结构信息：阶段之间是否有数据依赖、状态是否在阶段之间传递、功能结果能否独立检查？

## 竞争解释与证据

1. **跨组件依赖是真实的。** 合并源码中，`sources.py` 的 `ConfigSource/YamlSource` 新增并保存 `base_for_paths`；`templates.py` 的 `Filename.value` 在稍后解析相对路径时读取它；`core.py` 的 `Configuration.set_file` 把参数传给源对象。父/合并源码差异和行号见 `actual_project_v1/structure_evidence_v1.json`。这支持“源构造 → 模板解析”的有序数据链。
2. **状态范围是对象级，而不是全局共享。** `base_for_paths` 挂在每个 `ConfigSource` 对象上，并在之后的模板求值中被读取。当前三文件没有发现进程全局变量或跨请求缓存。因此可以记录“对象状态被后续阶段消费”，不能把它写成全局共享状态。
3. **行为可以观察，但结构归因仍有不确定性。** 已保存的真实 API 诊断区分了应用目录、源目录、覆盖选项、绝对路径和父版本不支持等结果。这个行为 oracle 是研究者根据公开源码和需求整理的，没有人工双审；同一输出可能由不同内部实现得到，因此正式独立可测标签仍为 `null`。

## 决定

该候选在任务层面有实质贡献：它补上了原先“库函数包装”缺少的真实项目上下文，并提供了父版本/合并版本、跨文件数据链和可执行行为例。它只能进入 `research_pool_only`，不能改写 initial20，不能填正式三轴标签，不能被描述为已回答主问题 A。

P80—P82 之后停止 PR #126 的边界扩展、更多静态门和更多包装任务。要真正回答主问题 A，仍需要多个同来源或可比来源的真实任务、冻结结构标签和在同总 token 上限下的整体/拆分模型比较；当前模型余额和人工资源不允许假装这些结果已经存在。
