# P72：行为证据能否把结构标签变成可追溯比较行

## 具体未知

主问题 A 需要比较阶段依赖、共享状态和独立可测程度。initial20 目前有单人预标，但预标本身不能当真值。未知是：把 D1_B01、D1_B03、D1_B05、D1_C03 的公开契约和已保存行为证据整理成“证据行”后，是否至少能形成一组可追溯的结构差异；还是只能说明各题的局部契约，无法形成同条件下的一轴对照。

## 竞争解释

1. P57、P54/P55、P62 和既有 C03 序列证据足以支持依赖、状态和可测范围的有限证据行，并发现可比较的同源对。
2. 行为证据只能支持输出义务或接口条件，不能把 single_pass/pipeline/stateful 变成任务固有标签；来源、模块和任务语义仍混杂。
3. 现有四题虽然有不同结构描述，但没有“同来源、同切分、其余两轴相同”的一轴对照，无法支撑主问题 A 的正式比较，只能明确缺口。

## 最低成本验证

只读 initial20 manifest 和已经保存的 P57、P54/P55、P62、C03 计划/状态报告，建立四条 evidence row。每行分开记录 dependency_claim、shared_state_claim、testability_claim、evidence_status、witness_counts、scope 和 provenance；不改原 manifest 的 formal labels。随后枚举四行的同来源/同切分/其余维度相同配对，检查是否存在可支持的一轴对照。

## 预算与红线

预计 20 分钟；模型/API/下载/任务求值/private/人工均为 0。结果若只有局部证据或没有匹配对，必须把“缺口”作为结果保存，不通过自动规则填正式标签。
