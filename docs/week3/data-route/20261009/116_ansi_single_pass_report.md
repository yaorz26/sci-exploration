# P54：两个局部删除阶段会改变被处理的文本版本

六个新锚点共24结构求值、六次二次来源查询：上游strip_ansi与独立ASCII扫描器各6/6；CSI先/短码先两串行结构各5/6，失败输入不同；六输入中三条再次strip_ansi会改变结果，非幂等。实际来源strip调用12，所有输入保持，模型/API/下载/原或私测0。

设ESC为U+001B。输入`ESC + ESC[31m + M`在原串只有中间CSI完整，单次删除后得到`ESC + M`；再运行短码删除会多删掉新接合出的码。另一个`ESC + ESCM + [31m`先删短码会接合出CSI；后续CSI阶段误删。只换两个阶段的顺序不能同时修复两例。`ESC + ESC[31m + [0m`还显示同类删除可制造新CSI，因此不能用“清理总应重复到稳定”代替来源单次规范。

两类别helper按其局部定义各可正确，却接到了另一个输入版本。独立扫描器只在不可变原串上判完整匹配，六锚点与来源一致。这是连接/数据版本义务，不能把任务无跨操作状态或局部可测解释为任意阶段连接都安全。

口径限制：原B03需求给精确ASCII范围与保留不完整片段，但未显式写单次原串非重叠删除；本阶段单次解释来自固定来源sub，六解析锚点并非人工真值。建议未来需求明示该点，不能宣称原正式语义已由两个助手判断可靠，也不改原20/初标/旧模型分数。不将发现归因于P9真实模型失败。

原证据`experiments/d1_ansi_single_pass_v1_20261009/`的公开规则/六预期/源码先冻结，worker原始输出及summary保留；模块SHA c5ecb7efd3b2e86f92545c18d8d72193f45a1bd1d0edaf3da65868aa0e8bcdda，源码规则与单次sub在strutils.py362—413。

阶段审查：六有限规范解释/接口反例获证，原需求单次口径尚需澄清。方向审查：不枚举更多ASCII坏串，P55仅检验两类helper都返回原文本匹配区间、入口一次重建是否修复，复用原六终值不重跑来源。局部区间有逐值解析预期，不把新接口说成最小/唯一或模型有能力生成。
