# 从比较矩阵转向任务契约的三轮深挖

日期：2026-10-09。所属宏观阶段：G3的任务行为证据与G4的共同验收条件。所有审查为助手自审，不是独立人类审查。

## 第一轮：从证据找未知并审来源

214号留下的未知包括内部状态所有权、强物理时点和收益关联。前两者不能靠继续读取同一公开结果解决，后者受完整模型预算及身份限制。重读已有公开题面和已知评价器时发现另一种具体未知：题面列出的所有公开功能义务，是否都在当前诊断域内有观测？例如PR126题面同时要求ConfigSource、YamlSource和set_file，但八项诊断只直接调用前者和set_file。这个线索来自任务自身，未读初始20隐藏材料或上游测试。

初始候选是“跨任务规范是否中立”和“现有诊断是否能误收违反明示义务的实现”。审核后保留后者为主要判断，前者只作为解释边界。理由：泛泛的中立性表格容易变成又一份没有新证据的文档；一个能通过旧诊断而违反题面义务的实际项目实现则会改变任务可用性判断。

## 第二轮：追机制与可证伪结果

竞争解释H1：已诊断入口共享项目代码，八项通过足以支持其余明确入口；H2：入口可独立遗漏，旧评价器会把不完整项目功能判成通过；H3：未覆盖条款实际上是题面过强或不明确，而非评价器缺口。H1不能凭源码相邻认定；H2需要真实可运行反例；H3需逐条区分公开API义务、构建者限制、内部算法要求。

修订问题为：当前有限研究任务的题面—诊断契约是否一致，是否存在明示义务未被当前验收识别？可见结果先是一份带原文定位的义务—观察映射；若发现明确遗漏，再选择一个真实项目控制与一个新公开场景区分H1/H2。不追求全域完备，不测试未写入有限域的输入，不把源码组织当唯一答案。

## 第三轮：资源、信息收益和否决

全域穷举、隐藏集扩量、三任务全部变异、模型探针、人类模板打包均否决：资源或信息收益不成立。选择一次限定的契约核对，最多四个已管理候选、只读现有题面/公开例/评价器。若没有可复查的新缺陷，结束这项核对且不宣称研究进展；若有明确缺陷，后续只批准一个最小行为反例，须另三审。

本轮选定问题：有限真实项目任务的明示外部义务是否超出已观测范围？结果应直接改变“当前评价可支持什么”的表述，而非增加任务/报告数量。当前宏观计划的模型预算、内部自由、候选状态、旧数据不改；受影响G3/G4接续须在216号三审后开放。
