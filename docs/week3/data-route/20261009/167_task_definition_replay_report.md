# P81 候选任务定义复核

P80 形成了一个真实项目候选后，P81 只检查任务定义能否独立复查，不再增加功能覆盖。

第一次复核保留在 `actual_project_v1/task_spec_replay_v1.json`：绝对路径例中的 `<app>` 占位符没有在输入值中展开，导致复核失败。这暴露了任务格式缺少运行时占位符规则。修正 `task_spec.json`，明确 `<app>` 代表临时应用目录，并在复核器中统一替换与规范化路径。

修正版 `actual_project_v1/task_spec_replay_v2.json` 在合并快照上复核 4 个行为例，4/4 通过：默认行为回到应用目录；源标志和模板标志进入源文件目录；绝对路径保持不变。复核器只导入已保存的合并源码，不读取上游测试，不把合并补丁放入任务输入。

这一步确认候选任务的行为例可以复查，同时保留了一个具体格式缺陷及其修复。它仍然不是人工标签，也不是模型效果，更不支持主问题 A 的拆分收益结论。下一步只做一次结构证据审查：根据真实源码调用关系判断三轴是否可分别观察；不能把审查结果直接写成正式标签。
