# P53：完整终值漏掉快照错误，且一条EOF手算预测失败

只执行新“每累计前缀feed+close+get_text”结构六次solve，P52旧18solve不重跑。它的终值6/6通过，完整feed后快照仅3/6相同，3条轨迹有4个不同快照。底层14对象、14feed/14close/14get_text、85输入字符；模型/API/下载/原测试/private0。机器冻结/新worker原输出/比较结果在`experiments/d1_stream_finalization_v1_20261009/`。

例如`A &am`，不结束输入的feed观测为空；在前缀执行EOF则得到字面`A &am`。对完整实体字符串两者终值相同。终值全部通过不能证明声明的流式快照正确，需求必须明确feed后观察、何时EOF、是否允许提前输出。

负结果必须保留：四个新EOF解析预期仅3/4符合。预测未完成带引号标签`<a href='x`在close后当文本返回，实际仍为空；原预期/原结果不改，不把该错误补写成事前正确。新close结构相对“未close的feed快照”不合规；另一EOF观测契约下可合法，不能称上游bug/所有流式解析错误。

学到：快照/终值是不同观察要求；相同最终HTML不能使观察时机可省略。排除：所测终值判分足以验证全部流式要求、以及我们的简单“EOF都保留未完成标记”解释。仍不知道：如何不用上游内部语义就清楚、独立地说明这类前缀延迟行为。两正确结构同源，人工0、候选标签null，快照真值未独立冻结。

阶段审查：观测时机反例获证，独立预期有失败，E_B10仍需修订。方向审查：本轮不继续解释更多HTMLParser细节，不追加类似EOF控制、不冒称已得完整数据集任务。候选留研究池，保留失败，转原开发B03公开ANSI精确范围：其一次删除原始匹配是否幂等，按两种代码类别分阶段删除会不会重新识别新接合出的码？这是明确字符域的输入版本/连接问题，不追溯归因旧模型失败，不读私测。
