# P59：候选类型门槛与完整执行链能否共用

具体未知：P51验证了值比较函数，但直接把它用在执行器的整条结果上，会不会丢失异常分支或输入不变约束？新增明确的候选类型规则是否在真实JSON序列化后仍能检出数值同值漂移，而保留合法float/default和合法异常？这决定E_B09能否成为可审查的数据候选，服务主问题A的可测契约资料。

竞争解释：值门槛已足以替代执行器；或它只处理正常value，需要另接error分支及原输入检查，否则错误异常/输入修改可能误判；或序列化抹平了所需类型区分，不能靠这个门槛满足候选规则。

最低成本：另存v2执行器，不修改原评分器/v1候选。先冻结八个新诊断输入、逐值/异常预期和五个程序：原正确whole在新输入运行；浮点count、众数/default数字类型替换、先算正确返回再改变输入、改变异常类型四个控制。八输入覆盖128/129长度、合法空float/default bool/int、整数众数、额外字段先于元素错误、data类型先于default类型。五程序各八次，共40solve，旧十二例零重跑。每次JSON标准化后，同一个保存actual同时供旧值规则与新typed规则判断，输入不变保留严格类型与键次序检查，异常只比较其类型而不向accept_output塞error对象。

决策：通过则保留完整v2公开执行候选、来源/许可/旧新诊断分开，结构标签仍null/人工0；只称八新输入链路验证，不称原36次升级或全域覆盖。失败最多两实质修订且保留原输出，15分钟无证据则回到其他任务。不得引入hidden/model或以错误控制频率估计模型缺陷率。
