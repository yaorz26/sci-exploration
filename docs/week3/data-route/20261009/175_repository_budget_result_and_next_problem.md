## 三轮下一问题挖掘和严审

第一轮从证据找问题：加大预算改变已确认条件，不自行做；直接截断代码破坏可见信息，否决；按需求公开API提取父源码并允许项目补丁，有实际工作区支撑且不需要金标准选区，可检验；停止项目任务只保留小函数会弱化题目，尚无必要。

第二轮追机制：超限来自原包中的大量不相关接口和整文件输出。把下一问题细化为“需求API提取+补丁能否容纳已知正确修改且真实应用到父快照”。只算给定正确文本的可容纳性，不把它当生成成本/效果。任何抽取规则只能用需求明示API和父代码，不能看参考patch选择片段；参考只用于另存输出可容纳和补丁复原验证。

第三轮比较审核：一套固定AST提取规则和一个真实合并补丁足以判断此局部路线是否仍超限，以及补丁能否应用；不枚举排版、不扩源任务、不启动模型。缺上下文仍可存在，后续实际方法总输入也会变大，必须保留未知。最终选择这项可见协议适配结果，按176号三轮审查再执行。
