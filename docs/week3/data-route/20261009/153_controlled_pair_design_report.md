# P73：主问题 A 的最小控制配对设计（完成）

## 具体未知与竞争解释

P72 发现旧题没有正式一轴对照。本阶段问：能否设计一组自然、可验证、预算可配平的控制配对，固定来源、切分、题面规模和两个结构轴，只改变一个轴。

可能性有三种：旧任务可以通过小幅契约设计形成控制对；结构轴天然联动，强行隔离会制造不自然题面；即使能隔离，也只能作为设计候选，不能直接说明拆分有效。

## 设计结果

形成 4 个配对模板：

- **DEP-01 依赖轴**：保持无持久状态和中间输出可观察，只改变第二阶段是否必须消费第一阶段的变换值/路径。低依赖版本重新读取原始规范，高依赖版本把消费原始值定义为缺陷。风险是两版本若为了保持最终输出完全相同而显得人为，必须淘汰。
- **STATE-01 状态轴**：保持同一功能结果、操作词汇和局部检查；纯版本每次重算，状态版本跨操作保存缓存/最近使用/计数，并把 work_count 明确写入输出。若纯版本无法在不模拟历史的情况下提供同义 work_count，就只能做测量探针，不能做正式配对。
- **TEST-01 可测轴**：保持依赖、无状态、输入和最终结果，只增加一个有稳定精确 oracle 的中间投影。新增字段的 token 成本必须纳入相同总预算；无法配平时不用于效果比较。
- **NEG-01 负对照**：D1_B01 与 D1_B05 都是无状态 pipeline 且有明确中间/最终行为证据，但任务内容不同。它只能检验“看到两个 pipeline 就归因结构”的错误，不能被当作结构效果估计。

每个模板都登记了整体、局部、序列 oracle、唯一变化项、风险和淘汰条件。P73 v1 首次运行发现负对照缺少 oracle 计划，保留原目录；v2 修正后 4/4 模板均有 oracle、风险和单一变化轴。没有执行新任务或模型。

## 结论与下一步

现在有了可以真正推进主问题 A 的数据设计候选，但它们还不是任务数据或效果证据。下一步只做“自然性和等 token 可行性筛选”：优先检查 DEP-01 和 STATE-01 能否从现有公开函数改写出不人为的同语义配对；TEST-01 另算新增字段成本。任何不能自然隔离的模板直接淘汰，不进入模型评测。
