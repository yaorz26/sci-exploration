# 跨候选最小观察维度矩阵计划

归属宏观v2的增量G3→G4边界。具体未知：PR126、PR142、PR440三项有限任务是否共享足够的外部可观察维度，支持未来同题比较的任务筛选；若不足，哪些字段必须保留任务特有或unknown？

竞争解释：共同“前后调用”维度是实质可比较证据；共同表述只是抽象类比；结构字段被参考实现/接口条件污染；cache副作用/来源共变使任何共同轴不可靠。可见终点是矩阵、字段逐条证据和明确的可比较/不可比较结论，不是新增任务数、标签数或统计显著性。

执行步骤：1. 只读取`structure_records_v2.json`、三项task/candidate需求、PR元数据、四类行为机器结果及cache观察路径；不读取测试/private，不重跑。2. 对每候选填固定维度：输入域、操作历史、后续公开结果、旧行为控制、跨组件/对象链、公开接口条件、合法组织自由、内部状态所有权、观察副作用、来源/家族混杂、可支持的主A用途。3. 每格标`observed`、`inferred`、`unknown`或`not_applicable`，附原始证据路径和不能推出的解释；不把“两个组织通过”升级为独立结构真值。4. 计算只做证据计数/缺口清单，不算轴相关或效果；形成G4限制说明。5. 保存方向审查与下一问题三轮审核，不改原任务/标签/切分。

资源：零模型/行为/下载/人工/付费/训练/RL；本地只读和一次新JSON/报告，≤60分钟。原200MiB、约98/100、DLL/人工限制继承。若来源证据不足，矩阵宁可空/否决；不再扩G2、不修v3包装。

## 第一轮可行性审查

发现：三项记录格式和来源层级不同，直接拼字段会把memory推断当机器观察。cache观察路径有公开源码片段但强时点未证；PR440 G3增量是事后证据，不能假装有计划冻结。

修订：矩阵保留`evidence_status`和`provenance`，把事后结构表标为阶段证据而非预注册标签；只允许引用已有文件/哈希。先建立证据allowlist和空值规则，再构造，不能从代码私有字段补值。第一轮通过，尚不执行。

## 第二轮意义与重心审查

发现：矩阵容易退化为报告包装。若没有一个字段能改变G4的合法比较决定，它不算成果；“共同都有输入/输出”过于空泛。

修订：每个字段必须回答“它是否决定未来可比较任务的纳入、观察或解释范围”。至少保留一项否决性结论：若来源/机制共变或观察副作用无法分开，就禁止把该字段当统一结构轴。矩阵只服务数据集适用边界，不增加候选、不重跑既有行为、不填正式标签。第二轮通过。

## 第三轮区分力与可信度审查

发现：PR126/PR142同confuse，PR440不同来源；三候选仍不足三轴独立估计。两个替代组织由同助手构造，不能称人工验证；同外部结果不证明内部状态相同。若把观察通过当真值，会把实现可运行误报为任务结构。

修订：矩阵同时列观察结果、竞争解释、尚未区分项和结论上限；共同维度仅作为候选筛选/协议设计依据，不能作生成前正式结构标签。对cache明确“观察会触发expire，物理返回时点unknown”；对PR440明确“回调内归约结果可观察，存储所有权unknown”。三轮通过；现在才允许一次只读矩阵构造。
