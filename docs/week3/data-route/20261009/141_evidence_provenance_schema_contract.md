# P67：把结构证据来源写进数据集协议而不冒充结构标签

## 具体未知

P66 表明新增候选能补足输出契约和有限适配边界，但不能补足正式三轴标签。未知是：能否把 contract_origin、necessity_scope、evidence_status 三个字段做成可校验的证据层，保留“任务义务、接口条件、额外观察、未定规范”的区别，并与现有数据集字段向后兼容。

## 竞争解释

1. 三个字段及其枚举足以让候选证据进入数据集，且不会被误读为 dependency/state_scope/testability 的正式值。
2. 三个字段过于粗糙，会把接口条件或额外测试误当任务固有义务，必须增加来源位置、适用范围或否定证据。
3. 新字段会改变旧 manifest 或评分器口径，兼容性风险大于收益，应继续把证据留在旁车文件。

## 最低成本验证

以 P58 六条已保存主张、P66 两候选矩阵和原 initial20 manifest 为样本，先冻结一个只增字段的 JSON schema 草案，再做枚举、必填、旧字段不变和 provenance 指针检查。验证只读已有 JSON/Markdown，不生成模型候选、不读 private、不填正式结构标签；若 schema 仍无法区分必要范围，保留失败并改为旁车证据协议。

## 预算与红线

预计 15 分钟；模型/API/下载/任务求值/private/人工均为 0。旧 20 题、原评分、切分和正式标签不改；schema 通过也只表示证据记录可机读，不表示三轴已获得人工真值。
