# P65：极值key相等是否足以判断合法代表

具体未知：P64不同合法代表不能用单一参考精确输出判定。如果只比较abs(minimum)/abs(maximum)的极值key，会不会接受根本不在输入中的代表、bool伪装整数或错误输出形状？需要怎样的最低规则，才能同时接纳合法并列选择与拒绝这些错误而不规定helper？这关系自由内部拆法的评测真值。

竞争解释：极值key判断已经充分；或必须同时要求精确整数类型、成员归属、恰当字段形状才满足未来abs-key候选公开语义；或这些规则会额外拒合法并列代表，需要保留不同实现见证。仅限非空精确整数列表及P64唯一最小key范围；异常、任意key、流输入另案，不泛化。

最低成本：首动作冻结P64四保存输入/八合法输出、六个构造输出控制的逐值接纳预测、原机器结果hash。只比较14个保存/构造输出，不再调用source/builtin/solve/模型。规则候选比较“极值key-only”与“形状+精确int+成员+极值key”；新增类型/非成员/非极值/缺字段/额外字段控制来自保存输入的允许域。声明这是比较函数有限验证，不是完整执行链；输入修改与异常规则不冒称已验证。

决策：若key-only放过非成员或bool，则另存未来比较规则候选与明确适配需求，不扩当前E_M07。若强规则拒八合法见证，至多两次修订后保留失败换路。不能通过修改保存预期取得通过；原评分器、任务、标签、旧分母保持。
