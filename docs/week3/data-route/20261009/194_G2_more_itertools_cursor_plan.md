# G2候选计划：more-itertools真实游标操作历史任务

所属宏观阶段：D1-G2真实项目功能构建。G1已经按192号完成一次只读纳入条件核对；G2本计划解决缺口K2：现有真实任务只有路径元数据连接和TTL过期报告，尚无非缓存操作历史功能。

## 具体未知、竞争解释与可见终点

未知：more-itertools官方历史功能能否提供一个真实项目API，使同一对象的前序操作改变后续公开结果，并在同一需求下允许不同内部组织、用最少公开操作序列区分正确和功能遗漏实现？

竞争解释：

- H1：官方有可追溯的游标/回放功能变更；父版本和feature版本可恢复；操作历史是公开需求的一部分，替代组织可用。
- H2：功能只是无状态输入迭代器或列表适配；所谓历史依赖来自测试写法/私有字段，不能成为自然项目任务。
- H3：功能存在但提交、许可、依赖或父源码无法可靠恢复；只能保存来源线索，不能纳入研究候选。

可见终点：`experiments/d1_G2_more_itertools_cursor_v1_20261009/`中的来源检查、父/feature快照或明确否决记录、需求草案、最小公开操作序列和研究池纳入/否决结论。结果必须是一个真实可复查任务或具体No-Go证据，不以任务数量增加或文档通过作为结果。

## 三轮计划审查

### 第一轮：可行性

执行只分两步：先用已有本地来源线索与必要公开元数据定位最多两个more-itertools历史功能；找到提交后仅取父/feature相关非测试源码、许可证和官方需求，不克隆整库、不读上游测试内容。每个候选最多两次定位/恢复尝试，单支路约20分钟无新增证据就停止。

工具：`rg`检索现有本地实验与来源线索；PowerShell/Python只读JSON和源码；若公开网络来源已落盘则优先本地，网络检索仅为恢复官方提交/文档，不读测试。模型、Ollama/API、人工、训练、RL均0。

修订前可行性风险：more-itertools可能只有已保存的E_M07上下界任务，无游标变更；“官方功能”线索可能不足。若找不到父/feature，终点降为保存K2缺口否决，不继续搜无关仓库。通过条件：最少一个候选有提交关系和需求来源，或两个定向尝试均有可复查失败原因。

### 第二轮：意义与重心

只研究非缓存操作历史能否成为项目功能任务；不扩已有minmax候选，不重复流式HTML/ANSI支路，不构造手写游标控制来替代官方需求。一个候选已足够回答“当前缺口是否有真实来源入口”，目标不是凑6项/3来源。

如果功能只是输入序列多次调用，不能写成共享状态；若必须依赖私有迭代器字段，记录为不可公开验收。需求、项目API、公开操作域和实现方式分开保存。通过条件：候选任务对K2增加了可区分的机制证据，或No-Go明确说明为何现有来源不能补足。

### 第三轮：区分力与可信度

需要排除三类混杂：前后版本不只是重命名、操作历史不只是输入顺序、公开序列不泄漏feature实现。父与feature源码只用于构建/行为验证，未来任务输入不包含feature、patch、私有测试；上游测试不进入需求。公开操作序列至少包含“先消费/定位再读取”的历史对照和一个保持不变的初始行为，具体数量由需求决定，不预设结果。

真实功能诊断仅用于研究池任务有效性，不赋正式结构标签、储备split或人工真值；more-itertools即使来自原储备仓库，新任务仍`research_pool_only`。许可证、commit、依赖和污染线索分开记录；公开历史训练污染仍unknown。

### 执行步骤、预算、停止与保存

1. 读取已有E_M07来源记录与more-itertools线索，列最多两个官方游标候选，不立即下载。
2. 对候选逐个恢复需求、parent/feature commit、许可和最小源码；只存独占新目录，旧E_M07不覆盖。
3. 若合格，先写需求和操作序列冻结，再构造父/feature最少公开行为诊断及一个不同内部组织；若不合格，写具体否决原因，不造替代任务。
4. 阶段结束保存结果、竞争解释排除情况、仍未知和下一问题；若形成任务，再做三轮新问题深挖，下一题只能来自G2/G3，不跳回缓存。

资源：最多20分钟来源定位+每候选两次实质恢复；新增下载不超过原D1 200MiB总边界且未知剩余额度时只取必要文件；模型/API/人工/训练/RL/发布0。禁止读原D1隐藏输入/结果、上游测试、储备成绩；不执行旧已通过检查。

失败转向：找不到真实提交关系→保存No-Go并进入G3缺口说明；只有输入迭代无历史→保存边界并查K1，但须重新立计划和三审；源码恢复困难两次后换另一候选或结束，不无限搜索。

## 第一轮审查：可行性（未执行来源定位）

发现：若先查GitHub搜索或整库克隆，容易把来源调查变成无界网络工作；当前more-itertools的明确本地证据主要是E_M07 minmax，不足以预设游标功能存在。

修订：限定最多两个官方候选、先本地线索后最小公开元数据；每候选两次恢复尝试，20分钟无新增证据换路。把“找不到”设为有效No-Go结果，不用另找同类库填空；下载上限沿用原D1 200MiB但剩余额度未知时只取必要文件。

通过理由：在现有权限、网络和零模型预算下，能得到一个候选或明确来源否决；不依赖人工/隐藏测试/模型调用。第一轮通过。

## 第二轮审查：意义与重心（基于第一轮修订）

发现：游标任务可能退化成“多调用同一迭代器”，只增加一个状态名称，不能直接推进主A；如果把两个操作序列和多个helper包装成贡献，会重演过度评测。

修订：只接受官方需求本身要求历史影响后续公开结果的功能；一个候选即可回答K2入口，不追凑六项/三来源。必须说明现有confuse/cache为何不能替代，若只是输入顺序、私有字段或同一缓存机制则否决/降为边界说明。禁止重复扩HTML/ANSI和E_M07 minmax。

通过理由：成功结果会补主A结构测量中“非缓存操作历史”的真实任务来源；失败结果会明确当前候选域缺口，均比数量增长有信息。第二轮通过。

## 第三轮审查：区分力与可信度（基于前两轮修订）

发现：父/feature差异可能是重命名或测试写法；把feature源码/patch用于构造需求会泄漏；同一more-itertools来源又属于原储备仓库，容易错误写成储备确认。

修订：只读官方需求/提交关系和非测试源码，需求与feature实现分离；操作历史必须在公开API序列中可观察，并有保持不变对照；父/feature与参考实现只留在评价侧。新项固定`research_pool_only`、formal_labels/split null，不并原9题，不称未见污染；许可证和公共训练污染unknown。

通过理由：三类替代解释（无历史、来源不可恢复、泄漏/储备混用）都有可记录的否证条件；仍把有限操作域和同助手组织证据限制写入结论。三轮通过，现可执行来源定位。
