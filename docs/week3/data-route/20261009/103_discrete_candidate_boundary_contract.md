# P48：E_B09完整适配与新边界是否一致

具体未知：P47明确的count/mode外部适配能否用内部结构自由的完整参考执行，并清楚处理混合整数/字符串、并列、空域默认和无效输入？如果只能靠参考内部过程规定答案，便不适合作为D1数据集成果候选。

竞争解释：两个用途的离散输出均可由自由内部实现满足且输入不变；混合类型的并列规则或布尔/容器输入使不同实现/来源包装分歧；或者适配必须限制域并明确异常，才能形成可复核契约。结构标签暂留null，不因为两helper实现存在就写yes。

最低成本验证：先保存独立逐值解析的新输入/预期；创建公开候选task.json和需求，所有诊断公开，不假称新隐藏确认集。输入是仅含data与可选default的普通字典；data为长度<=128的列表，每项type是int或str，允许混合；bool、浮点、容器数据项拒绝TypeError；default允许有限JSON标量，不含列表/对象/非有限数。输出正好count/mode，count为整数长度；mode空域返回default，非空为最大频数、并列首次出现的原值。输入保持，容器/类型/额外字段无效按明确异常拒绝。两个纯标准库结构和来源包装执行最多12新边界，各从新契约开始，原六输入不重跑。

边界安排：六有效（混合并列、并列顺序反转、空default bool/null/string、单字符串）与六无效（bool/float/list元素、非列表、缺data、非标量default）。规范判分采用原json_equal及异常类/严格输入保持；不发布、不评分任何模型。源参考count/default分离明确记录，不能把额外校验冒称上游要求。
