# P50：数值同分没有落实候选整数类型声明

四个新完整构造程序各一次实际有界评分，分别返回count 1、1.0、True、2，mode均x。在这同一次solve中保存返回值及构造消费者list(range(count))结果，不二次执行程序。输入为新公开data=["x"]，预期count=1/mode=x；四种预测执行前冻结。

| 返回count | 原JSON评分 | 消费得到正确[0] | count精确int且原评分 |
| --- | --- | --- | --- |
| 1 | 通过 | 是 | 通过 |
| 1.0 | 通过 | 否，TypeError | 拒绝 |
| True | 拒绝 | 是 | 拒绝 |
| 2 | 拒绝 | 否，[0,1] | 拒绝 |

四预测均获证，4solve/4消费/4形状比较，模型/API/隐藏/下载/原12诊断重跑0。原机器证据在`experiments/d1_output_type_composition_v1_20261009/`：冻结预测/程序哈希、四有界输出、四同执行轨迹、summary均保存。

学到了什么：E_B09明确数量整数，但原比较器的int/float数值等价未落实该声明。数值相等足以给出相同JSON分数，并不足以保留一个依赖整数数量的消费行为。原比较器已经区分bool与数值，因此不能将问题扩大为所有类型都放过。整数形状门槛也不代替正确数量比较（2形状合法、值错误）。

边界：消费者是我们公开构造的range例子，没有查得/宣称boltons真实项目消费点；不是整体项目集成效果，也不是原20统一有缺陷。即便不考虑消费者，E_B09自己的明确整数声明仍须落实。数字类型对其它任务是否重要由需求决定，不将严格类型追溯到原评分/旧成绩。三参考36/36仍是原规则下有限诊断，不替代输出类型规则验证。

方向：E_B09暂不正式冻结，P51比较“仅count整数+旧比较”与“候选全数字类型保持+旧比较”：后者是否会错误拒绝合法浮点default，前者是否放过mode原值类型漂移？用六新的公开输入/输出比较对先冻结解析预期，直接调用保存评分函数两种参数，不运行模型或旧solve；依据结果创建另版本候选规则，原v1不覆盖。
