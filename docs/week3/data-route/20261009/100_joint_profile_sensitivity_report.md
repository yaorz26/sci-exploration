# P46：总有重复画像留下，不等于同一画像稳定

原始开发11题有7画像，其中重复3画像。13次预定删除分析含来源2、显式组件6、宽敏感性组件5：每次都至少剩1个重复画像，但没有同一个原重复画像在所有来源删除或所有显式组件删除后仍然重复。

删除boltons后剩5题、重复1画像，仅C01/C02的operation_sequence/global/partial，同属一个缓存显式组件。删除cachetools后剩6题、重复1画像，仅B01/B05的ordered_transform/none/yes，同一来源。不能把“两个删除情景各剩一个画像”说成“存在稳定的共同画像”。

| 原重复画像任务 | 剩余画像不再重复的显式组件删除 |
| --- | --- |
| B01/B05 | 删B01或B05单题组件 |
| B02/C01/C02 | 删整个cachetools组件；删B02/B04后仍有C01/C02，但只剩同一组件 |
| B06/C05 | 删B06或cachetools组件 |

宽敏感性群的删除也没有一个共同稳定画像，13情景重算仅描述前置支撑，不包含收益/成绩。原程序宽群用既有关系的覆盖编号，当前关系最终成员对应一致，但没有一般传递闭包实现；不可复用为任意重叠家族分析器。

P45初报告有一处数量口误：储备9题5画像、3画像重复，故单题画像是2个，不是3个；原机器记录正确。原P45程序预写“重复主要同来源/组件、开发画像接近题数”过概括：开发三个重复画像中两个跨两来源/两组件，第三个同来源跨组件。应依据成员表逐项解释，不声称画像与来源或组件完全绑定。该更正不影响7/3及5/3的频数。

阶段审查：排除“所有重复画像都会一删全部消失”，也排除“存在一个跨来源删除始终重复的画像”。仍可逐题配对、列有限画像描述与删除情景；现有支撑不适合稳定独立画像效应或多因素归因，不要求主A变成因果研究。

方向审查：停止重复画像统计，不继续换聚类名掩盖稀疏。下一P47解决P44新离散候选的评测实质缺口：原稿称json_equal但实际是Python ==，并未对上游API直接验证空输入默认值。先核对来源及评分类型口径，候选未通过则留研究池，不填原20标签空格。

证据：`decomposition-bench/experiments/d1_joint_profile_sensitivity_v1_20261009/summary.json`及追加判读`interpretation_clarification.json`。来源/组件删除为不同情景，不是独立复现；作者标签人工0、模型/API/任务求值/private读取0。
