# P45：开发集有少量联合画像重复，但支撑不足以拆开三项因素

按完整依赖集合、状态范围和独立可测程度组成联合画像，20题共有10个画像，其中5个重复；开发11题有7个画像，3个重复，最大画像频数3；储备9题有5个画像，3个重复，最大频数3。

开发集的三个重复画像是：

- `operation_sequence / global / partial`：B02、C01、C02，共3题，来自boltons和cachetools两个来源，落在两个显式关联组件；
- `branch_rules + direct / none / no`：B06、C05，共2题，来自两个来源，落在两个显式关联组件；
- `ordered_transform / none / yes`：B01、B05，共2题，都来自boltons但属于两个显式组件。

这说明联合画像可以用于有限的描述性分层，但不能把每个画像频数当独立样本，也不能把跨来源直接当作结构因素的干净对照。开发集的四个单题画像分别只出现一次，储备集的三个单题画像也只出现一次；来源与切分完全绑定，开发/储备差异不能单独解释为结构差异。

阶段结论：主问题A可以预先规定“逐题配对 + 联合画像描述 + 来源/关联组件敏感性”，不能预先承诺三个结构轴的独立效应或复杂回归。下一步按契约做留一来源/留一显式组件，确认重复画像是否依赖某个来源或组件。
