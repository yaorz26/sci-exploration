# P65：未来 abs-key 极值输出的最低合法判定（完成）

## 具体未知与竞争解释

P64 已显示同一 abs-key 下可以有两个合法的最大值代表。本阶段检验：只比较极值 key 是否会把不在输入中的值、bool 伪装整数和错误字段形状误收，还是必须加入精确类型、成员归属和字段形状；另一种可能是这些附加规则会误拒合法并列代表。

## 最低成本验证

先冻结 P64 的四组输入和八个已保存合法输出，再加入六个构造输出控制。只对冻结的 14 个输入/输出对象运行 key-only 与 strict 两个纯比较函数；不调用 source、builtin、solve、模型或 private 数据。冻结文件哈希为 ef7c5f44d803eb30f2894488abd5b009398edd65156af5ec7c7e67eda5650695。

key-only 只要求存在 minimum/maximum，并检查两个绝对值达到输入的绝对极值；strict 另外要求正好两个字段、值为精确 int、两个值来自输入。

## 原始结果

- 14/14 行预测与实测一致；key-only 接纳 11/14，strict 接纳 8/14。
- 八个 P64 保存合法返回全部被 strict 接纳（8/8）。
- 六个构造控制全部被 strict 拒绝（6/6）。
- key-only 错收 nonmember_same_key、bool_minimum、extra_field 三个控制。
- 本阶段比较调用 28 次，source/task solve/model/API/private/human 均为 0；构造控制是输出对象比较，不是新的程序执行。

## 结论与适用边界

对未来非空精确整数列表、abs key、两个极值字段的有限域，最低可区分规则是“正好两字段 + 精确 int + 成员归属 + abs 极值”。它允许两种并列最大值代表同时成立，避免单一来源精确输出误拒；key-only 不足以承担真值判定。

这只证明比较函数在冻结有限域上的行为，未验证输入修改、异常语义、任意 key、流输入或完整执行链；不改变 E_M07 当前无 key 候选、不填正式标签/切分、不提供主问题 A 的模型效果。并列比较支路到此停止。
