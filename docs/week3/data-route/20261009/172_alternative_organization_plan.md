# 下一循环：评价是否偏好原补丁组织

问题：P83评价器能否接受单一模块完成兼容扩展的实现？与主A关系：数据集不应预设正确拆分结构。H1外部行为一致即接受；H2评价或导入隐式要求原三文件结构；H3替代实现错误，不能把失败归为评价偏好。

可见目标：真实父项目上的一个替代工作区、同一八诊断实际输出和局部结论。非模型、非新增题/输入、非全域合法性证明。

草案：保留父sources/templates/core不变，单一模块追加兼容行为；原评价器一次执行。失败仅因明确替代代码缺陷允许一次修订，保留首次输出，不改测试。预算20分钟/两实质尝试，模型/人工/下载/发布0。

第一轮审查：父源码公开类可兼容包装构造与方法，环境和评价器已可运行，无需新资源。风险为覆盖旧relative_to/cwd优先级。修订：先保持旧解析，只有源目录功能实际生效才指定源基准；不更改全局目录。改动单一模块并保留原三文件，资源可行。通过，第二轮审查此修订。

第二轮审查：P83只接纳原完整补丁，对合法替代组织的偏好未知；直接关系到整体/拆分能否共用评价。风险是把手写方案通过说成模型效果或任意合法程序证明。修订：只认一个可执行组织反例，标助手编写、不填结构标签、不计模型效果、不把重复八例计新输入。通过，第三轮检查H3的歧义。

第三轮审查：通过同一外部测试可排除必须修改原三文件位置的解释；失败只能检查具体语义，不能直接归因评价偏好。修订：执行前保存替代代码、父三文件实际hash对比和相同评价器hash及预测，不改评价器。八例外合法性未知必须明说。三轮按顺序审查过修订后的计划，通过；允许执行一次及至多一次因明确代码缺陷修订，不新增输入。

状态：三轮完成，可执行。
