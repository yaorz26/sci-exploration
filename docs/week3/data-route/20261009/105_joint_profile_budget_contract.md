# P49：相同联合画像内的构造提示预算差异

具体未知：P45开发集三个重复联合画像里的题，按同一M2构造提示情景是否有不同输入占用与剩余输出上限？它影响主A的结构关联解释：粗画像相同不一定代表同等可用生成余量。

竞争解释：固定格式/helper数/注释量后，画像内占用大致一致；或者相同画像仍有题面长度/提示重复造成的明显差异；或者字段连接/旧构造器版本不一致，根本不能比较。这里不定义事后“明显”阈值，保存所有精确差值与占6500比例，让证据限定结论。

最低成本：只读P14 rows.json与P45已保存的画像汇总，并用原manifest提供逐题来源与初标（执行前补明第三文件；不把汇总误称逐题冻结行）。冻结三个文件哈希及固定情景pretty、2helper、0注释、总cap6500。连接开发11题，核对每题恰一行、来源/切分/可测/状态一致，manifest哈希与P45输入记录相同；列三个重复画像内所有题对的M0/M2输入、输入额外成本、余量差及题面长度差。存全表与全部5对（B02/C01/C02三对、B06/C05一对、B01/B05一对），程序以组合枚举确认。不先假定差异来源。

用途：有差异时，把构造提示开销作为主A描述中的同题方法负担，不能由粗标签替代；无差异时不强加解释。若有M2与M0题序反转，可提出固定token预算的比较资格边界；否则另找非重复测量问题。预算20分钟、最多11连接行/5画像内题对，两实质修订；模型/API/新token计量/任务执行/隐藏/下载均0，不能消耗剩余模型调用。

限制：P14是合成计划/helper文本下的历史构造计量，不是这三画像的真实生成成本或效果。当前tokenizer/prompt哈希须沿原记录引用。只查开发，储备不参与任务选择。完成后保存阶段/方向审查，转能改变比较设计的下一问题，不扩相同情景表。
