## 一、决策结论

**选择 G1 选项 2：有条件采用公开数据。**
具体为：**采用 ClassEval 作为第一阶段唯一评测数据**，产出派生物（字段统一 + 按方法切分公开/私有测试 + 分环节归因字段）；**不采用** EvoCodeBench / DevEval / Commit0 / LCA；**第一阶段不建自建数据**（不进 WP4B）。

## 二、为什么是它：候选对照（含被排除者的理由）

| 候选 | 判定 | 决定性理由（一手证据） |
| --- | --- | --- |
| **ClassEval** | **采用** | MIT（仓库 + 数据集均核实）；**91/100 题参考实现连续 3 次稳定通过**（实测）；方法↔测试类一一对应 → **公开/私有可按方法切分**（24/24 校验通过）；单题中位 0.29 秒、最大上下文估算 4102 token；无容器依赖 |
| EvoCodeBench-2403 | 不采用 | 数据集 HF 无 license tag；数据是 **25 个真实仓库源码**，上游许可含 **AGPL-3.0×2、GPL-3.0×1、无许可×2**；官方要求 Ubuntu + conda |
| DevEval | 不采用 | **GitHub 仓库无 LICENSE 文件**（API `spdx=null`）＋数据集 cc-by-4.0＋117 个上游仓库 → 许可链条不成立（硬性否决第 1 条） |
| Commit0 | 不采用 | 官方要求 **Docker 或 Modal** 才能跑测试；整库规模与 8192 token 输入上限不匹配（硬性否决第 4、9 条） |
| LCA（六个任务） | 不采用 | 六个任务**全部没有执行型判定**（ChrF / API Recall / 困惑度 / LLM-as-assessor；CI 修复还需真实 GitHub CI） |
| BigCodeBench | 保留为对照 | 可运行但任务单元是**单函数**，不满足五项判据前三条（硬性否决第 10 条针对"拆分问题"） |

**G1 必须回答的那个问题（执行文档 §9.2）**：候选里同时满足"至少两个自然阶段 + 能分阶段测试 + 许可证清楚 + 本机稳定运行"的比例＝**1 / 5**（只有 ClassEval）。"好运行的都不够可拆分、够可拆分的都不好跑"这一矛盾**在本机条件下已被实测坐实**。

## 三、这个决定的代价（必须接受的部分）

1. **规模小**：91 题可用；分层后目标层 32、边界层 25、负对照层 11 → 探索集按每层 8 题共 24 题，储备 67 题。**不足以支撑统计上可靠的确认性结论**（与 WP0 已确认的路线定位一致）。
2. **任务域窄**：单文件、类级、无仓库上下文；结论只能声称"在类级多方法任务上"。
3. **污染风险无法控制**：Qwen2.5-Coder 训练数据边界官方未披露，且候选数据全部早于该模型发布 → 污染风险记为 **unknown**，不得声称无污染。
4. **5% 的题不可用**：9 题因宿主/时间/浮点/OS 语义/NumPy 版本/非确定性被排除；其中部分在 Linux + NumPy 1.x 下可能可用（已用 `_51` 证明 1 例）。
