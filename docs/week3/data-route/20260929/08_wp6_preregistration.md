## 一、要回答什么

在**同一模型、同一预算、零训练**条件下：对给定的方法级分解，
**"逐方法实现再组装"（M2）是否比"一次性整体生成"（M0）更可靠**？
以及"先写实现计划再生成"（M1）能否解释收益来源（是一般性的"先想再做"，还是真正的分工与组合）。

## 二、设计（冻结）

| 项 | 内容 |
| --- | --- |
| 题目 | 冻结探索集 **24 题**，全部使用（**不按 P0 结果挑选**，避免事后选样） |
| 输入 | 全部臂一律输入**同一份骨架**（`inputs.decompose_given`）——ClassEval 的官方测试按固定方法名调用，API 必须给定 |
| M0 | 输入骨架 → 一次性生成完整类 |
| M1 | 输入骨架 → 先生成实现计划（≤200 字，仅文字）→ 再生成完整类（**2 次调用/候选**） |
| M2 | 输入骨架 → **逐方法独立生成实现**（每次调用只输出一个方法的完整定义，骨架作为上下文提供）→ **机械组装**（把生成的方法替换回骨架，无模型调用） |
| 候选数 | **每臂每题 1 个**（首候选对照）。这是相对冻结清单"3 候选"的**缩减**，理由＝本机算力预算；由此**候选池上限与 `public` 选择臂本次不适用**，标记为"未测"，不得用首候选结果冒充选择规则结论 |
| 生成参数 | `qwen2.5-coder:7b`（Ollama，4-bit）；`temperature=0.2`；固定 seed（M0=+11、M1=+22、M2=+33，按方法序号递增）；`num_ctx=8192`；`num_predict=2048` |
| 评测 | 候选冻结后：先跑**公开测试**（模型可见），再跑**私有测试**（模型不可见）；**私有测试全过 = 该题该臂解出** |
| 失败分类 | 代码跑不起来（语法/导入）／能跑但行为不对；两者分开统计 |
| 预算与停止 | 调用上限 400 次；单次测试超时 60 秒；超限即停并按已完成部分报告 |

## 三、主要指标与解释门槛（预先写死）

主要指标：
1. 各臂**私有测试全过的题数**；
2. `M2 − M0` 的**题目级成对差异**；
3. **双零题比例**（M0 与 M2 都不过的题）——P0 已实测该比率为 **75%**，因此必须同时报告"全部 24 题"与"非双零题"两个分母下的结果。

次要指标：公开测试全过题数、能跑起来的比例、逐方法调用数、token、墙钟。

解释门槛（照抄执行文档 §13.5，先于结果写死）：
- M2 的池上限与选择后成绩都不高于 M0 且成本更高 → **停止扩大，不训练拆分器**；
- M2 池上限更高但选择后不提高 → 问题在选择器；
- 两者都更高 → 可继续扩大的依据，但 24 题**仍只能称探索性正信号**；
- 两者池上限都很低 → 优先判断"模型共同天花板"，**不把失败归因给拆分**；
- 收益只来自更多 token/调用 → 不得称拆分机制有效；
- 差异区间同时覆盖有意义的正负方向 → 结论为"**现有题量下无法判断**"，默认不扩大、不训练；
- 本臂只做首候选，**不构成对"选择规则"的任何结论**。

## 四、已知限制（先说清，避免事后解释）

1. **24 题、每臂 1 候选**，功效极低：按 P0 实测的 25% 有解率，预计只有约 6 题能提供有效信息；
2. **分解由数据集给定**，因此本试跑**检验不了"拆分方案的选择"**——只检验给定分解后的实现策略；
3. 污染风险 unknown；M2 的组装是机械操作，组装失败会被归入"能跑但行为不对"这一类，需在报告里单列原因；
4. 单 seed，不构成确认性证据；任何"正信号"都只能是探索性的。
