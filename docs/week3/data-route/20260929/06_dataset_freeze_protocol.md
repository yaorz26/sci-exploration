## 二、"M0 是什么"的决定（对应决策单第 10 项）

**决定：把"给完整骨架（=已给分解）"设为独立对照臂 `M2_given`，默认 M0/M1/M2 一律使用 `decompose_free`（只给类描述＋导入）。**
理由：ClassEval 的骨架已含全部方法签名与 docstring，直接当输入等于把"怎么拆"告诉模型，M2 与 M0 的分数都会失去解释力；拆成两条输入后，可以分别问"分解环节值多少"与"实现环节值多少"。

## 三、版本与不可覆盖

- 本冻结为 **v1**。任何参数（题集、分层、切分规则、臂定义、预算、seed、选择规则）改动 → 生成 v2 并保留 v1 的失败与结果记录。
- 冻结清单内含各产物文件的 SHA-256；重建数据集用 `scripts/wp4a_classeval/build_dataset_and_freeze.py`。

## 四、冻结时已知的风险（不隐藏）

1. 污染风险 **unknown**（模型训练边界未披露，且数据早于模型发布）；
2. 分层由"方法数量"代理，**未经人工/双 Agent 判据标注**；
3. 私有测试与公开测试来自同一份官方测试文件，**同一方法的核心逻辑在私有侧仍有覆盖**——这是本数据集能提供的最强隔离，但不是"独立新写测试"；
4. 91 题是保守下界（9 题排除中至少 1 题在 Linux + NumPy 1.x 下可用，未回流）。
