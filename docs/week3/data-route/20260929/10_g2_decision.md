## 三、决策

**1. 不扩大确认。** 理由：既没有"需要更大确认"的正信号（M2 ≤ M0），也没有可用的资源来源（见第四节）。按执行文档 §14.2，**正式选择"不扩大确认"**，把本阶段目标收敛为 **"边界刻画 + 数据与评测基础设施交付"**。

**2. 不进入训练，RL 不启动。** 按 §14.3 的七个条件逐条核对：

| 条件 | 状态 |
| --- | --- |
| 数据与评测器稳定 | ✔（91/100 可判分、24/24 切分校验通过、单题中位 0.29 秒） |
| 探索性试跑显示存在可利用的候选池空间 | **✘ / 未测**：每臂只生成 1 个候选，**池上限未测**；已知 M0 首候选 6/24、双零率高 |
| 明确训练对象 | 未定 |
| 训练/开发/确认按仓库隔离 | **✘ 不适用**：ClassEval 无仓库信息（已记录为限制） |
| 独立协议、预算、成功门槛、停止条件 | 未写（因前四条不满足） |
| RL 单独授权 | 未授权 |
| 信号不来自单一 seed/单层/额外 token | 不适用（无正信号） |

**七个条件至少四条不满足 → 不讨论训练。**

**3. 结论标签**：维持中性。建议标签仍是"本地 7B 上类级代码生成任务的分解策略探索性对照（基于 ClassEval 派生物）"，**待导师确认前不得升级表述**。

## 五、本次交付物（即使全负也成立的产出，§2.4）

1. **数据与评测基础设施**：ClassEval 派生物 v1（91 题、字段统一、公开/私有按方法切分、含两种输入变体）、冻结清单 v1.1、数据卡与 README、可复跑脚本（转换、切分、回归、探针、试跑、组装）与 10 个单元测试；
2. **可复用的工程事实**：① 91/100 题能在本机稳定判分（9 题排除原因逐条归档）；② 公开/私有可按方法切分且不影响参考实现（24/24）；③ **公开测试选择会选错**（最多 4/24）；④ 非确定性题（宿主名/日期/随机/跨调用状态）必须识别并剔除；⑤ WSL py3.10 + numpy 1.x 可作为 NumPy 语义兼容的第二环境；⑥ 类级任务在本机属"能跑但仍偏难"的档位；
3. **方法学结论**：① 在 API 给定的条件下，**M2（逐方法实现+组装）不优于 M0（整体生成），且成本高约 4.7 倍**；② M1（计划后生成）与 M0 差异与噪声无法区分；③ 双零率 70.8% 说明**主要瓶颈是模型能力天花板**，而非被检验的实现策略；④ 本项目自定义的五项可拆分判据**当前措辞不可靠标注**（κ=0.436，两项近常量），因此"按人工判定的可拆分性作分层交互检验"这条**尚未真正实现**。

## 八、附：v2 公平化重跑后的复核（2026-09-29 补记）

本决策作出后，又做了一次**公平化重跑**（见 `12_wp6_v2_report.md`）：三臂统一加"语法/完整性校验 + 重试一次"、M2 提示词禁止重定义已有方法名、候选数 1→2。结果：

| 臂 | 首候选私有全过 | 池上限 |
| --- | --- | --- |
| M0 | 7/24 | 7/24 |
| M1 | 8/24 | 8/24 |
| M2 | 7/24 | 7/24 |

- 双零题 16/24 = **66.7%**（v1 为 70.8%）；第 2 个候选**没有救回任何新题**（池上限 = 首候选）；
- 三臂相对 v1 各 **+1 题、幅度一致** → 与"换了一次随机抽样"一致，**说明 v1 的结论不是工具缺陷造成的**；
- 关键新证据：提示词已明确禁止重定义已有方法名，模型**仍然重复定义** `_to_camel_case`、`_select`（校验共 13 次重试，集中在 4 题）→ "撞名并覆盖签名"是**逐方法独立生成的固有失败模式**；
- 分层交互方向仍未出现：目标层 M2 反而比 M0 低 1 题，负对照层持平。

**复核结论：第一至三节的决策全部维持不变**（不扩大确认、不训练、不启动 RL、正式收束）。唯一补充：现在的结论有**两个独立抽样 + 一次工具修复后的复核**支持，比单次结果更稳。
