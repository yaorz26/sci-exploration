# D1 阶段性成果：真实项目任务与生成评测适用边界

## 研究问题

本阶段研究“面向项目功能级代码生成的任务分解评测数据集构建与适用边界”。主问题 A 只在同一题目、同一方法总输入加输出 token 上限下，讨论阶段依赖、共享状态、独立可测程度与拆分相对整体收益的关联；不把关联写成因果。

## 已得到的实质证据

1. **真实项目候选成立，但范围有限。** PR126（confuse 源文件相对路径）和 PR142（confuse 环境配置叠加）保留父源码、公开需求和公开行为评价；PR440（more-itertools 组生命周期）另存独立候选。它们是 `research_pool_only`，没有正式标签、切分或真实人工双审。
2. **评价器存在可复查的契约盲点。** PR126 的控制实现保留旧评价器所观察的行为，旧评价 8/8；但对公开题面明示的 `YamlSource` 入口直接调用为 0/1，完整实现和独立组织各 1/1。结论是旧评价器可能误收 API 不完整实现；新增锚点属于接口验收条件，不能据此填共享状态或阶段依赖标签。
3. **同预算真实生成目前不可测。** 本地 `qwen2.5-coder:7b` 对 PR126/PR142 各执行 M0/M2 两版适配，共 12 次请求。v1 在每臂 6500 token 下发生超预算；v2 压缩上下文后 M0 仍生成 hunk 坐标错误，M2 发生计划解析失败或组件再次超预算。格式剥离后 hunk 仍与父源码不匹配。四臂均无完整候选，行为分子未定义。

## 对数据集成果的贡献

当前产出可作为“研究池候选与适用边界”成果：它给出真实包源码任务、来源和公开行为义务，同时把评价器可能漏掉的外部接口条件单独暴露出来；它还给出一个实际资源边界——在当前 7B、上下文和 6500 总 token 协议下，不能从这些候选得到可比较的 M0/M2 行为结果。

## 结论强度

可以说：真实项目任务和行为评价入口已经形成可复查的研究池；PR126 反例证明某类旧评价会漏收明示 API；当前本地生成条件不足以产生主 A 所需的完整候选。

不能说：拆分方法已经优于或劣于整体生成；任务结构三轴已经得到正式标签；模型总体效果、人工一致性或因果关系已经测出；研究池已经是可发布的正式数据集。

## 后续资源缺口

若要继续回答主 A，必须先重新冻结一个资源参数：总 token 上限、模型身份与计量方式、或严格补丁接口。改变任何一项都要回到宏观计划做新计划和三轮审查；当前 G5 不擅自改变它们。
