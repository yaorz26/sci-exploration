# G4 完成后的接续问题审核

## 第一轮：从新证据找未知

新证据同时出现三类失败：v1 超预算，v2 的 M0 hunk 不可应用，v2 的 M2 计划或组件再次失败。它们都来自真实 Ollama 响应，不是静态检查。由此提出三个方向：增加总 token、换本地模型、或改补丁协议。共同缺口是：当前没有任何完整候选，无法观察行为收益。

## 第二轮：追机制和可证伪性

增加预算可以检验“预算先耗尽”是否是主因，但会改变既定同预算条件；换模型会把能力和模型身份混在一起；放宽补丁解析会把“方法生成”和“适配器修复”混在一起。唯一能直接证伪当前边界的可见结果，是在重新冻结预算、模型和协议后取得完整候选并运行同一公开评价器。现有证据不能证明 6500 以下所有提示都失败，也不能证明更大预算一定能成功。

## 第三轮：资源、收益和风险比较

增加预算的信息收益最高，但它是主协议参数，必须先重审而不能偷偷改；换模型的信息收益次之且无法与 qwen7b 的失败分开；继续格式修复的信息收益最低，且已经被一次 hunk 错位诊断否决。三者都需要新的计划审查、候选冻结和资源账本；当前原计划 G5 已可交付的结果是适用边界和“主 A 未测”。因此本轮不启动新模型或预算支路。

## 选择

选定下一问题为：**在不改变主问题 A 定义的前提下，若要恢复模型配对，首先必须冻结哪一个资源参数（总 token、模型身份或补丁接口），才能取得可定义的完整候选？** 这个问题暂存于 G5 资源缺口，不自动执行；下一阶段先交付本次边界结论和原始证据索引。
