# 评价器盲点是否会改变相对收益：三轮问题深挖

## 第一轮：从新证据找未知并审来源

219号提供了一个真实项目控制：旧8项全过，直接YamlSource入口失败；完整和独立组织在新入口通过。这个结果不含任何M0/M2生成，但暴露了一个直接关系主问题A的测量未知：如果两个方法都用同一旧评价器，漏掉的公开入口是否只造成共同的绝对分数偏差，还是可能改变相对收益符号？

来源只使用已冻结的真实工作区结果；不把control/complete说成模型产物，也不把“整体/拆分”标签赋给它们。它们只能作为两个合法候选实现的形式反例。

## 第二轮：机制、边界与替代解释

H1共同评价器的盲点会等量影响两臂，相对差值仍可信；H2两臂可能在遗漏明示入口上不同，盲点会把一个真实失败记成通过，从而改变差值；H3只要候选均满足完整公开契约，漏测不会改变相对值。

最小可证伪构造是把control和complete分别放到两个候选位置，计算旧评价与补充直接入口后的`Y`和`Δ=Y(M2)-Y(M0)`；交换位置还可检验符号是否可翻转。这个计算不产生模型效果，只证明测量协议存在何种偏差机制。若两种放置都保持同一Δ，H1更可信；若Δ由0变为±1，H2成立，H3只适用于已完整实现的候选。

## 第三轮：资源、信息收益和停止条件

不需重跑行为：旧8/8和新0/1、1/1已是原始结果；一次脚本只做四个布尔组合的算术映射，模型/人工/下载0。它能直接改写G4协议：在比较前，评价器必须覆盖题面明示入口，否则相对收益可能是评价盲点差异。它不能估计盲点在真实模型输出中出现的概率，也不能替代完整M0/M2实验。

否决再做PR142/PR440补测、随机模拟或把两个实现标成方法臂；若形式反例不改变Δ，记录No-Go并结束该支路。问题通过审核，允许一次只读计算并保存为测量协议边界。
