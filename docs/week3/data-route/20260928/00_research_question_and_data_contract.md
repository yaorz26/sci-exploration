## 一、主研究问题

### 1.1 一句话版本

> 在本地 7B 代码模型与有限计算预算下，对于本来就包含多个自然阶段、接口清楚、能够自动测试的项目式代码任务，"先拆分、分别实现、再组合"是否比直接生成完整代码更可靠？

### 1.2 它要区分的两种解释

既有 APPS 自定义切分上的负结果有两种可能原因，本路线的作用就是把它们分开：

- **解释 A**：拆分本身没有价值（拆开写永远比一次写完差）；
- **解释 B**：竞赛题的难点集中在一个无法拆开的算法洞察上，拆分在这些题上本来就不该有效。

### 1.3 定位（已知边界）

- 这不是"换一个数据集再跑一次"，而是**检验拆分方法适用条件的边界**；
- 第一阶段**只做评测，不训练**（用户 2026-09-28 确认，见 `docs/week3/9.28数据集路线_分步执行与Agent移交文档.md` §2.2 已决定第 2 条）；
- 本路线的主要产出是**数据与评测基础设施 + 探索性方向信号**，不承诺统计上可靠的一般性结论（用户 2026-09-28 确认，同 §2.2 已决定第 1 条）；
- 研究问题本身的正式定位**尚未获导师认可**，属 `【待决定】`；在认可前所有结果只能使用中性标签。

### 1.4 用户 2026-09-28 明确的侧重点：怎么做拆分

用户原话（要点）：目前主要想研究的是**如何拆分**——**拆分的方法**、**判断是否要拆分**、以及**拆分 / 生成 / 组合三个环节的提示词工程**。

这条对第一阶段的影响（不改变"只评测、不训练"，但改变要比较的对象）：

1. **不止比较"拆 vs 不拆"**：还要比较**不同的拆分方案**本身。即把 M2 从"一个方法"扩展成"一族方法"。
2. **拆分策略至少覆盖三类变量**：
   - **拆分粒度**：拆成几个子任务 / 每个子任务的职责边界；
   - **接口表达形式**：自然语言步骤、函数签名 + docstring、结构化 JSON/DAG（对应既有实验的 M2a=Python skeleton、M2b=JSON 分解）；
   - **是否拆分的判定**：允许模型输出"不应拆分"，并检验这个判定是否与人工标注、与最终成绩一致（对应 `docs/week2/9.18当前研究结果与后续工作.md` §9 阶段 B 第 3 条）。
3. **三个环节分别可评**：需求 → 拆分（分解环节）、每个子任务 → 子实现（生成环节）、子实现 → 可运行整体（组合环节）。三个环节各自有失败模式（分解不合理 / 子实现写错 / 接口接不上），本路线要能把损失归到具体环节上——这是既有实验里"接口类异常占失败样本一半以上"的直接延续。
4. **仍然不训练**：以上全部在**提示词工程**范围内做，用冻结的同一模型、同一预算比较不同提示方案。任何"训一个更会拆分的模型"的做法属于改变主目标，须重走 WP0（见 §三）。

## 二、可证伪假设

### 2.1 主假设（可被数据推翻）

> 与难度集中在单一算法洞察上的任务相比，项目式任务会降低拆分后的**接口断裂**与**全局协调损失**；这种下降幅度足以抵消额外格式、重复调用、组合稀疏以及没有训练补偿带来的代价，从而使 M2 相对 M0 的题目级差异翻为非负或正向。

### 2.2 两种必须分开报告的失败方式

1. **失败方式一**：项目式任务并没有降低接口错误率；
2. **失败方式二**：接口错误率下降了，但其余成本（格式税、组合稀疏、零学习补偿）仍然更大。

只要结果落在两者之一，都必须分别报告，不能合并成"拆分无效"一句话。

### 2.3 不成立的替代解释（必须排除或承认无法排除）

- **只是采样太少**：既有实验已排除为主要解释，本轮仍需报告候选数、组合数与有效候选率；
- **只是 token 更多**：若 M2 的收益完全由更多 token/调用带来，不得称拆分机制有效；
- **只是任务域不同带来的难度下降**：靠低可拆分负对照层检验，不能只比较总分；
- **只是题目被我们自己定义成"可拆分"**：靠五项判据的证伪条件（第六节）检验。

## 四、任务粒度与排除项

### 4.1 第一阶段允许的任务

- 语言：**Python**；
- 类型：后端业务逻辑、命令行工具、解析器、格式转换、数据验证、小型库功能；
- 粒度：单函数到小型模块级修改；
- 环境：能在本机（Windows 原生或 WSL2）独立安装与运行。

### 4.2 排除项（出现即排除，除非用户明确接受风险）

- 依赖浏览器、手机模拟器、真实数据库、外部网络服务或人工看界面的任务；
- 依赖 GPU 服务、云服务或需要长期运行的服务进程的任务；
- 只能人工主观评分的任务；
- 上下文明显超出本地模型输入上限、且无法在不改变任务的前提下裁剪的任务；
- 只能通过无法冻结的外部服务评测的任务；
- 必须依赖重型容器、且无法给出符合 D 盘落盘约束的方案的任务（见第十节）；
- 数据或参考代码许可证不允许当前用途或再分发的任务；
- 输入中直接包含参考答案、私有测试或等价实现、且无法修复的泄漏。

| `decomposition` | 子任务、接口、依赖（仅在将来训练拆分器时才需要） | 本轮不必需 |

### 5.2 `<requirement, code>` 是否足够

**不足够。** 导师提出的 `<requirement, code>` 只直接支持"需求 → 代码"的生成对照。要回答本路线的问题，还必须有：

1. **可执行测试**（否则无法自动判分，也无法形成公开/私有隔离）；
2. **项目上下文与 starter 状态**（否则无法区分"任务难"与"上下文缺失"）；
3. **来源与许可证信息**（否则不能合规使用与再分发）；
4. **可拆分性标注**（否则无法检验"任务结构 × 方法"的交互）。

缺上述任一项时，必须在 G1 明确说明该候选只能支持哪一类结论（例如只能做方法主效应、不能做交互检验）。

## 六、可拆分性判据：来源、量表与证伪条件

### 6.1 判据（五项）

来自本项目对竞赛题失败的自行归因（`docs/week2/9.18当前研究结果与后续工作.md` §8）：

1. 有多个自然处理阶段；
2. 阶段之间的输入输出接口清楚；
3. 单个函数可以相对独立地验证；
4. 公开测试足够丰富，能够区分候选；
5. 正确性不只依赖一个无法拆开的数学洞察。

### 6.2 判据的定性

**这是本项目自定义的待验证量表，不是公认真理。** WP1 必须查 DecompRL、MoT 及相关论文中的模块化/条件独立/任务结构定义，建立对应关系；**找不到对应依据时必须明确标为"项目自定义"**，不得暗示有文献背书。

标注方式：每题打 `是/否/不确定` 并写一句依据；至少由两名独立标注者或两个独立 Agent 判断，报告逐项原始一致数与全部分歧题。

### 6.3 证伪条件（判据无预测力的判定）

出现以下任一情况，视为五项判据未获支持，必须如实记录，不得靠汇总总分掩盖：

- 高判据组的接口类错误率并未低于低判据组；
- M2 相对 M0 的差异没有随判据层级改善（高判据层与负对照层方向相同或混乱）；
- 小样本下方向不一致：**只作描述，不得把"未显著"写成"判据无效"**。

## 七、统计口径与"不确定"出口

### 7.1 主要指标

- 私有测试**全部通过**的题目数（题目级）；
- M2 与 M0 的**题目级成对差异**；
- 高可拆分层与低可拆分负对照层中 `M2-M0` 差异的方向（小样本只作探索性描述）。
- **拆分策略层面的对照指标**（对应 §1.4 用户侧重点，第一阶段新增）：
  - 同一模型、同一预算下，**不同拆分方案**（粒度 / 接口表达形式 / 提示词环节）之间的成绩差；
  - **分环节归因**：失败样本中"分解环节不合理""子实现写错""组合后接口接不上"各占多少（沿用既有实验的接口类异常统计口径）；
  - **是否拆分的判定质量**：模型判定"不应拆分"的题，与人工标注、与最终成绩的一致性；被判定不宜拆分的题上 M2 是否确实不如 M0。

### 7.2 次要指标

候选池上限（假设提前知道正确答案时最多可解几题）、部分测试通过率、有效候选率、接口类错误率、公开测试并列率、独特程序数、调用/token/墙钟/测试执行数、`M0=M2=0` 双零题数量与比例、各层与各 seed 的方向一致性、生成提升与选择提升的拆分。

### 7.3 检验口径（冻结）

- **主口径**：题目级成对差异 + 效应大小 + bootstrap 置信区间；
- **补充**：配对精确检验（双侧）；
- 已知锚点（可自行验算）：`6:1 → p=0.125`（既有 60 题实测）、`6:0 → p≈0.031`、`5:0 → p≈0.063`。这说明小样本只有接近一边倒才可能达到常用显著阈值；
- `p<0.05` **只是证据之一**，不替代效应大小、区间和最低有意义提升。

### 7.4 最低有意义提升（**已冻结：净值 ≥4 题**）

**2026-09-28 用户授权由 AI 决定，现冻结为：净值 ≥4 题**（在 24--30 题规模上约 13--17 个百分点，分母为进入探索性试跑的题数），且 bootstrap 95% 区间下界 `>0`。

理由：

- 既有唯一实测效应量级是 60 题净增 5 题（约 8.3 个百分点），若项目式任务的成本更高（单题代码更长、M2 需多次调用），那么低于该量级的提升不足以证明值得投入；
- 在 25 题规模上，净增 4 题若方向为 4:0，配对精确检验 `p≈0.125`，即**即使达到该阈值也不能声称统计显著**，因此该阈值是"值得继续做"的经营性门槛，不是显著性门槛；
- 低于 4 题时，与噪声无法区分，结论应写"题量不足，无法判断"。

### 7.5 双零题（`M0=M2=0`）的预注册处理

困难题上已出现过候选池几乎全零的情况。预注册规则：

- 报告双零题数量与比例；
- 若双零题比例 **>50%**，名义题量按折半看待，并优先判断是"模型共同地板"而不是"拆分失败"；
- 双零题不得从分母中删除，也不得只报告非零题。

### 7.6 "不确定"出口（预注册）

若题目级差异区间同时覆盖有意义的正向与负向差异，或不同 seed/分层方向冲突，结论为 **"现有题量下无法判断"**。默认动作：**不扩大、不训练**，只交付数据与评测基础设施；任何扩大必须另立预算、新确认集和资源来源说明（见第十一节）。

### 7.7 seed 规则

- 单 seed 只允许**工程试跑或探索**；
- 若进入确认阶段，必须**至少两个预先固定的 seed**；
- 分析按"同一题在不同 seed 下的重复测量"处理，**不得把 task×seed 当成互相独立的题来虚增样本量**；
- 若单 seed 为正、第二 seed 反向或接近零，只能报告 seed 敏感，不得合并后掩盖方向冲突。

## 九、公开测试 / 私有测试边界

1. 私有测试**不得**进入提示词、候选生成、候选选择、调参或任何训练输入；
2. 私有测试只在选择规则冻结后运行；
3. 若某数据集只有一套测试，需在不泄漏的前提下预先切分，并记录切分规则；
4. 若某数据集没有合法、且不泄漏私有信息的公开测试，则 `public` 选择规则标记为**不可用**，不得临时从私有测试拆一部分再称"公开"；
5. 已揭盲的 A/B 确认集与 APPS 冻结题可以作外部描述性参考，**不得**作为内部负对照、调参依据或确认性证据。
