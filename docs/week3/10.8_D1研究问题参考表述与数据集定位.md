## 推荐的主问题

> 在相同生成预算下，按功能阶段分解生成相对于整体生成，能否提高项目功能级代码任务的正确性？这种收益或损失与任务依赖和共享状态有何关系？

通俗解释：同一个完整功能，可以一口气写，也可以分成几段再接起来。要测的是哪类任务拆了有帮助、哪类拆了反而更容易出错，并把额外成本算进去。问题允许正结果、负结果和证据不足，不预设拆分必然有效。

正式写作中，“任务依赖/共享状态与收益有关”先作为关联或预测问题。只有同题受控改变结构、算法和信息条件等额外设计，才适合进一步讨论因果。

## 五种可选表述

| 侧重 | 参考研究问题 | 要增加的证据与代价 |
| --- | --- | --- |
| A：适用条件（推荐主线） | 在等预算条件下，任务的阶段依赖、共享状态和可独立验证程度，与分解生成相对整体生成的收益有何关系？ | 含有明确来源的结构差异与内部负对照；按开发集以外的题评估。小样本只能探索关联。 |
| B：怎么拆 | 对同一项目功能任务，不同拆分粒度与职责划分方式，如何影响整体正确率、接口错误和生成成本？ | 同题比较较粗与较细的可行拆法；保持需求、实现模型和预算一致。需保存各分解轨迹。 |
| C：接口如何说明（适合作为首个机制子问题） | 在分解方案固定时，显式规定子任务输入输出、异常行为与共享状态，能否减少组合错误并提高整体正确率？ | 比较简略与明确接口，两者功能信息和算法提示尽量一致；区分少报错与最终正确率提升。 |
| D：是否该拆 | 依据生成前可见的任务结构，能否选择整体生成或分解生成，从而优于始终使用其中一种策略？ | 必须在独立仓库/题目上检验路由规则，不能看私有结果后再选策略。20--30 题初版不宜承担复杂路由训练。 |
| E：数据集与评测主线 | 如何构建并验证一个允许模型自主选择内部拆分、可复现评估整体功能正确性和接口协作失败的项目功能级代码生成数据集？ | 展示已有任务为何测不到这个能力，以及新任务在需求清晰度、结构自由度、测试判别力、来源追溯和基线复现上的证据。构建本身不等于创新已获认可。 |

A/B/C/D 是可供选择的研究侧重，不建议第一版全部展开。建议以 A 为主，B 或 C 选一个有限子问题；E 是数据集成果的质量与能力验证线。暂不同时铺开多种模型、拆法、接口模板、路由和训练。

## 数据集应支持什么

1. **固定外部功能，允许内部拆法变化。** 保留使用者可见的入口、输入输出和异常约定；测试不应要求生成代码复刻原仓库内部辅助函数名或阶段数。明确接口的诊断臂可以单独给拆法，但不能混同“自主拆分”主对照。
2. **用整体行为判分。** 私有测试应能够接受多种正确内部实现。某个参考拆法可作示例或诊断对照，不当作唯一最优答案；分阶段测试也不能使另一种合法拆法天然无法通过。
3. **任务结构在看结果前记录。** 描述阶段依赖、跨阶段状态读写、能否定义独立阶段测试；不要简单用函数数等同于可拆分性。此前五项判据 κ=0.436，未修订和复核前不能直接作为可靠分组标签；“应不应该拆”是待验证判断，不能当成已知真值。
4. **保留不适合拆分的任务。** 使用同类仓库或相近功能范围的负对照；不得只留本地模型拆了做得好的题，也不能看确认题失败后静默剔除。
5. **数据质量可验证。** 来源、固定提交与许可记录完整；未实现版本按预期失败、参考实现重复三次一致通过；需求与可见材料不包含参考答案或参考拆法；隐藏测试覆盖正常、边界和异常行为，并报告测试辨别错误实现的能力。
6. **本地可执行且可复现。** 按既有 WP4B 范围，先考虑 Python 小模块、解析器、格式转换、数据验证或 CLI 功能；不依赖外部网络或人工交互；按仓库隔离开发和评测，保留近似重复检查、依赖和失败审计。

例如“读取表格文件、校验字段、按规则筛选并输出报告”可有按功能阶段、按数据对象或少量整体函数等不同实现。数据集给出功能行为约定；是否拆成读取/校验/转换等内部函数，应由被测策略决定，不能预先写成唯一答案。

## 成果与范围

可使用的暂定定位：**面向任务分解研究的项目功能级代码生成数据集与评测方法**。拟贡献包括可追溯任务构建、允许多种内部结构的评测协议、结构与接口标注、可复现基线及边界分析。若源代码取自第三方仓库，应清楚说明原创工作和继承材料的范围，保留出处及对应许可；不能把抽取的全部源代码称为原创。

数据集的贡献成立与否，取决于它是否可靠测量了目标能力以及相对既有工作的增量，不取决于拆分实验是否得到正结果。失败实现或无收益同样可以留下有用边界。建议题目：**《面向项目功能级代码生成的任务分解评测数据集构建与适用边界研究》**；这是暂定题目，未宣称成果已经完成或具有足够发表新颖性。

既有 WP4B 建议初版 20--30 题，只能作为小型评测集与探索起点；不能直接称大规模通用基准或作普遍有效结论。主比较须预先确定统一预算口径，同时报告输入/输出 token、调用数、时间和测试次数。新题量、仓库数、seed、候选数与统计门槛本轮均未冻结；原确认集的“净增≥4题”规则不直接照搬到新任务域。
