核实口径（本文件所有"✓已核"项）：

- 数据集许可证：Hugging Face API `/api/datasets/<id>` 的 `cardData.license` / tags（一手）；

## 三、必须提醒的三个坑

1. **"DevEval / DevBench"至少有三个不同东西**：`seketeam/DevEval`（2405.19856，ACL 2024，1874 题）、`open-compass/DevEval`（2403.08604，全生命周期案例研究）、以及 2026 年的 `DevBench`（2601.11895，telemetry 实例级）。写材料时必须写清是哪一篇，不能统称"DevBench"。
2. **代码仓库许可证 ≠ 数据集许可证**：SWE-bench、Commit0、EvoCodeBench 三者的仓库有明确许可证，但其 HF 数据集**没有 license tag**；SWE-bench 的数据还来自 12 个上游仓库，**逐仓库许可需另查**。WP2 静态审计必须分别核查，不能只写仓库那一栏。
3. **`libs` 字段不可信**：BigCodeBench 的 `libs` 少报依赖（实测缺 `pytz`），环境预检必须实跑。

## 四、本文件未核实的项（不得当作已核实）

- DevEval（seketeam）GitHub 仓库**没有 LICENSE 文件**（GitHub API 返回 `spdx=None`）——这是**硬性风险项**，WP2 必须确认论文/数据集页对它使用的声明；
- CoderEval、`open-compass/DevEval`、DevBench(2026)、Long Code Arena 各子数据集的许可证未核；
- 各数据集的**实际磁盘体积**（除 EvoCodeBench 约 1.2 GB、LiveCodeBench 4.28 GiB 外）未核；
- 各数据集与本项目的"多自然阶段"判据匹配度仍是 `【推断】`，未逐题标注。
