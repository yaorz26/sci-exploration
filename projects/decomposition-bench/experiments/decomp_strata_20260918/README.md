# P5b 可分解性分层实验协议

状态：seed42 正式实验已完成；seed43 已完成必要性与合理性审查，按当前决策门不启动。

## 研究问题

在具有清晰、可独立实现阶段的任务上，提示式模块化生成是否能提高候选池覆盖率和选择后私有正确率，而不仅仅是在更难的任务上产生差异？

## 确认性切分

切分包含三个各 20 题的分层。每条成员记录声明使用可调用 starter API 还是标准输入输出；所有方法在同一题上必须使用相同模式。

1. `simple_single_stage`：负对照层。一个直接变换或一个主导算法步骤，不要求稳定的辅助函数边界。
2. `medium_multi_stage`：多个连续变换，但至少有一个阶段存在明显耦合或接口歧义。
3. `hard_naturally_decomposable`：困难任务，至少有两个命名阶段、明确的阶段间数据以及可独立规定的辅助函数契约。

成员资格在模型生成前冻结于 `selection.json`。每题必须有基于题面和 starter API 的公开信息理由。不得使用私有测试、模型输出或既有私有得分选择、移动或删除题目。

成员构建前由 `sanitize_prompt_visible_private_tests.py` 删除题面中同时出现非空输入和输出的自定义私有样例，避免直接示例泄漏。该检查是保守规则，清单记录保留题和删除项，不使用模型结果或私有得分。

## 数据暴露规则

- `apps_train_interview_function25.json` 不可使用，因为其 P5 私有结果已经审计。
- Introductory development-20 不可使用，因为它曾用于修改 M2 提示和协议。
- Introductory holdout-30 仅可作为负对照层，因为没有运行 P3/P5 结果。
- 中等层和困难层必须来自新获取、版本固定且未检查私有测试的 APPS 行。
- 标准输入输出题的 M2 必须生成最终零参数 `solve()`；确定性组合器只追加唯一的 `__main__` 调用，辅助函数仍按同一 DAG 协议独立生成。

## 方法与控制

协议定义 M0、M1、M2a、M2b，以及可选的自适应 M2 路由。当前正式结果只执行 seed42。M2 使用两次分解尝试、每个函数两个实现、每个分解最多八种组合；自适应路由的路由调用和直接回退调用必须分别计数。

候选选择按公共通过率、再按确定性候选序号冻结。冻结后才访问私有测试。池 oracle 仅为事后诊断。

主要结果是选择后私有全通过和私有池 oracle；次要结果包括有效分解率、有效实现率、公共平局率、调用数、输入/输出 token、模型时间、公共执行数和候选超时耗尽数。

固定 evaluator 策略记录在 `evaluator_policy.md`。由于无法取得官方 APPS evaluator，这是一项本地机制研究，而非官方 APPS 基准。

## 决策门

只有当困难自然可分解层的 M2 同时在选择后私有全通过和池 oracle 上超过 M1、两个 seed 的方向一致，并且报告自适应路由直接回退成本后仍保持优势，才可考虑 RL。否则保持 RL No-Go，并报告负结果或不确定结果。
