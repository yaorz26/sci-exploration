# 03. CodeT：模型自己生成测试，再用一致性选择代码

原文：[CodeT: Code Generation with Generated Tests](https://arxiv.org/abs/2207.10397)（ICLR 2023）  
对应文件：[03_CodeT_Code_Generation_with_Generated_Tests.pdf](03_CodeT_Code_Generation_with_Generated_Tests.pdf)

## 先用一句话记住

**CodeT 同时生成多份代码和多条测试，让代码候选与测试候选互相“投票”；被更多候选和测试支持的行为，被认为更可能正确。**

## 背景：多份答案有了，测试却不够

采样 N 次常能得到至少一份正确程序，但真实用户通常只需要系统最后交一份。人工写全面测试又贵又慢。CodeT 的问题是：能否让代码模型自己提出一些测试，再据此从多份程序中选出更可信的一份？

这里要分清两件事：模型生成的测试**不是权威答案**；它只是额外证据。CodeT 的巧妙处在于，不盲信单条测试，而是同时看“多少程序同意这个测试”和“多少测试支持这类程序”。

## 方法：双重执行一致性

1. 对题目采样多份代码候选；
2. 用同一模型按特定提示生成若干 `assert` 风格的输入—期望输出测试；
3. 逐一运行“每个代码候选 × 每个生成测试”；
4. 将在同一批测试上表现相同的代码看作一个行为组；
5. 选择得到最大一致性支持的代码组中的候选。

论文把这个思想称为 Dual Execution Agreement。直觉是：如果许多彼此独立采样的程序和测试都指向同一种输入输出行为，这种行为比孤立、少数的行为更可信。

```text
代码候选 A、B、C、D
        ×
模型生成测试 1、2、3、…
        ↓
找出“同一行为”得到最多代码与测试共同支持的群体
        ↓
从该群体选一份代码
```

## 作者报告了什么结果

论文在 HumanEval、MBPP、APPS、CodeContests 上评价，并报告稳定优于当时的候选选择方法。以 code-davinci-002 在 HumanEval 为例，作者报告 pass@1 达到 65.8%，比其单模型基线高 18.8 个百分点。

应把这一结果理解为：自生成测试加上“多方一致性”可以改善候选选择；不能理解为自生成测试本身已经等价于隐藏标准答案。

## 它没有证明什么

- 同一个模型会同时误解题目、写错实现、又写错期望输出，错误行为也可能形成多数；这是共同偏差，不是独立投票。
- 候选数与测试数增大时，执行组合接近 N×M，成本上升很快。
- 自动测试覆盖不到的边界条件仍不可见；复杂状态、随机性、I/O 和外部依赖会使执行更困难。
- 如果用官方测试的期望输出参与选择，再用同一批测试报告最终分数，不能说明对未见测试也有效。

## 与当前研究最直接的关系

CodeT 是“只有少量 public 测试或没有足够 public 测试”时的强基线，也给你一个很重要的反问：当 public 分数并列时，究竟应该用过程分打破并列，还是用额外生成的测试打破并列？

可以设计一个小而干净的比较：候选池固定；只在 public 同分的题上，比较固定 tie-break、过程 tie-break、CodeT 式生成测试的一致性 tie-break。最终统一用从未参与选择的 private 测试评价。这样比较的是证据类型，而不是谁多采样了候选。
