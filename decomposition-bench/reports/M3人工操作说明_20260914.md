# M3 人工操作说明

你现在只需要完成两件事：给 A/B 两份自动分解打分，再写出你自己的分解。不要运行测试，不要查看模型写出的函数代码，也不要打开 `*_blind_key.json`。这样你的判断不会受到结果好坏的影响。

## 打开的三个文件

1. `decomposition_quality_20260914.md`：题目、starter API、候选 A/B。
2. `decomposition_quality_20260914.csv`：给 A/B 候选打分。
3. `decomposition_quality_20260914_human_template.csv`：写你自己的函数拆分。

## 第一件事：给 A/B 打分

对每一个题目都有 A 和 B 两行，因此一共填写 20 行。每项只能填 `0`、`1` 或 `2`：

| 列名 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| `coverage_0_2` | 漏掉题目关键要求 | 只覆盖一部分 | 所有关键要求都有函数负责 |
| `io_contract_0_2` | 参数或返回值明显不对 | 大体能用但不清楚 | 每个函数拿什么、返回什么都清楚 |
| `dependency_clarity_0_2` | 依赖关系错或乱 | 能猜出调用顺序 | 谁调用谁、为什么调用很清楚 |
| `independent_implementation_0_2` | 无法单独实现 | 需要大量猜测 | 单看说明就能实现该函数 |
| `granularity_0_2` | 过少、过多或重复 | 有一点不合理 | 拆分数量合适，职责不重复 |

例如，候选只有一个“万能 solve”函数，`granularity_0_2` 通常是 0；两个函数职责清楚、入口函数最后、依赖明确，通常是 2。某项给 0 或 1 时，在 `notes` 写一句原因，例如“没有说明输出要排序”。

## 第二件事：写你自己的分解

在 `decomposition_quality_20260914_human_template.csv` 中，每题填最多 4 个函数：

- `human_function_1` 到 `human_function_4`：格式写成 `函数名(参数): 负责做什么`。
- 最后一个非空函数必须是题目的 starter API，函数名和参数一个字符都不要改。
- `human_dependencies`：写 `入口函数 -> helper1, helper2` 这样的调用关系；没有 helper 则写 `无`。
- `human_notes`：写任何不确定点或你认为题目的关键陷阱。

示例：starter API 是 `convert_bits(a, b)` 时，可以填写：

```text
human_function_1 = count_set_bits(n): 返回 n 的二进制中 1 的数量
human_function_2 = convert_bits(a, b): 对 a 和 b 做异或后调用 count_set_bits
human_dependencies = convert_bits -> count_set_bits
```

完成后不要改动 A/B 标签或删列。直接告诉我“已填写 M3”，我会先检查 CSV 是否完整、分数是否在 0--2，再自动统计人工结果，并把人工分解接入同一评测流程。
