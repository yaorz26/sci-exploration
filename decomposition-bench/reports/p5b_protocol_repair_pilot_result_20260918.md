# P5b 协议修复 pilot 结果

## 目的

检验两类低成本修复是否能降低 M2 困难 stdin 任务的结构失败：`repair_v1` 输出硬清单，以及允许无环依赖乱序并由组合器拓扑排序。

## 成对 pilot 结果

5 个未进入正式 60 题切分的题使用同一模型、seed 和预算；baseline 与 repair_v1 各运行 1 次分解、每函数 1 次实现、最多 4 个组合。

| 指标 | baseline | repair_v1 |
| --- | ---: | ---: |
| 有效分解 | 4/5 | 4/5 |
| 实现请求 | 14 | 14 |
| 有效实现 | 13 | 14 |
| 形成候选题数 | 3/5 | 4/5 |
| 组合结构错误 | 0 | 0 |
| 主要协议错误 | 前向依赖、额外函数、空实现池各 1 | 前向依赖 1 |
| 公共全通过候选 | 0/5 | 0/5 |
| 选择后私有全通过 | 0/5 | 0/5 |

`repair_v1` 减少了额外函数和空实现池错误，但同一题仍以不同函数名产生前向依赖。该错误属于声明顺序问题，不是新的模型调用失败。

## 拓扑排序修复检查

对 repair_v1 原始 JSONL 离线重放并允许无环前向依赖后，5/5 分解有效、无组合结构错误；但原严格运行因提前淘汰该题，没有保存其实现池，因此离线重放仍有 1 个空实现池。随后只对该题补做一次 `repair_v1 + allow_forward_dependencies` 运行：

- 分解：1/1 有效；
- 实现：3/3 有效，组合：1/1；
- 公共全通过：0/1；私有全通过：0/1。

因此，拓扑排序修复能够消除结构层阻塞，但没有产生公共正确候选。

## 阶段审查

**状态：通过但门槛未通过。** 修复假设得到部分支持：结构错误下降，候选形成率提高；但预注册的公共全通过候选门槛为 1 个，实际为 0 个，不能扩大到 60 题，也不能进入 RL。

## 方向审查

- **拒绝：扩大 repair_v1/拓扑排序到全量 60 题。** pilot 没有达到公共正确性门槛，扩大只会增加成本。
- **拒绝：启动 seed43。** 当前协议和模型的 No-Go 仍未改变。
- **保留：离线算法语义归因。** 只分析已生成的可组合代码为何公共测试失败；若没有低成本、明确的语义修复，不再调用模型。

## 限制

pilot 题数很小，不能估计总体正确率；单题补生成不是完整的 5 题成对复验。结果仅用于结构协议决策，不改变正式 seed42 结果、成员资格或 RL 决策门。
