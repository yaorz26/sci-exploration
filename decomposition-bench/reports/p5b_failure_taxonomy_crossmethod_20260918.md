## 目的

回答方向决策问题：在冻结的 P5b 分层 60 题 seed42 数据上，四种方法（M0 直接 / M1 计划 / M2a skeleton / M2b JSON）的失败分别属于哪一类——**算法理解、结构协议、还是局部可修复错误**。该问题由 `docs/ai-conversation/方向.md` 的诊断实验设计提出，本报告用已有冻结数据以零模型调用完成其中的机械分类部分。

## 数据边界

- 全部 private 结果来自 `pool_oracle.json`（`post_selection_diagnostic=true`），即选择冻结后的诊断文件；本分析不产生任何影响候选选择、提示或成员资格的输出，不修改任何既有文件。
- 候选级 public 结果来自各方法正式 `evaluations.jsonl` / `recombinations.jsonl`，按 `code_hash` 与池 oracle 记录连接。
- 题级结果与正式报告交叉验证一致（简单层 pool oracle：M0 15、M1 14、M2a 10、M2b 7；困难层 M0 1、其余 0）。

## 解释

1. **算法理解错误是所有方法的共同瓶颈，且量级最大。** 困难层 zero_wrong 是四种方法最大的失败类别（M0 13/40、M1 17/40）；困难层 19–20 题对连 M0 也无全过候选，且各方法候选表现高度一致（同题离散≈0），说明失败源于题目与模型能力的差距，而非选择或组合噪声。
2. **接口/组合类失败是 M2 的专属超额失败，且可量化。** 困难层 zero_runtime 候选中，接口类异常（NameError、TypeError、RecursionError、EOFError）在 M2a 占 55%、M2b 占 61%，而 M0 为 0%、M1 为 25%（2/8）。NameError 意味着组合后程序引用了未定义名字——组合/接口断裂的直接证据；M2b 的 TypeError（24/46）与 JSON schema 协议下模块间参数类型不匹配一致。这与既有契约审计（困难层 53 条 helper I/O 违规）和错误归因报告（阶段契约错误）相互印证，并首次给出候选级比例。
3. **"接近正确"的候选在困难层很少，且集中于 M2a。** M0/M1 困难层 partial 候选大多只过 ≤25% 的测试（M0 10/15、M1 6/13），朴素的"局部修复"收益空间有限。M2a 有 15 个 0.5–0.75 的 partial 候选（模块大体工作、组合层面断掉），与第 2 条的接口类结论互相印证。
4. **M2 的成本效率低一个数量级以上**（结果 5），且简单层 M2 候选 public 全过但 private 失败的比例更高（26% vs M0 12%），组合候选更容易满足公共测试而不真正正确。

## 与方向决策的关系（证据呈现，不替代决策）

`docs/ai-conversation/方向.md` 的决策规则与本次证据的对应：

| 决策规则 | 机械证据 | 判定 |
| --- | --- | --- |
| "大部分是算法错误 → 拆分/AST 帮助不大，应换方向" | 困难层所有方法的主导失败均为算法类；19/20 题对 M0 无全过候选 | **对基线成立** |
| "大量接口/依赖/组合错误 → 可研究结构约束" | M2 困难层 zero_runtime 的 55–61% 为接口类异常；M2a 另有 15 个 0.5–0.75 partial | **对 M2 内部成立** |
| "大部分只差一小块 → 可研究局部修复" | 困难层 M0/M1 partial 多为 ≤0.25 弱部分 | **证据偏负** |

合并解读：接口/契约问题是**真实、可量化的 M2 专属失败**，修复它可能让模块化方法在候选质量上**追平**基线；但在当前模型下，困难层的上限由算法理解错误决定（对 M0/M1/M2 一视同仁），没有任何证据表明修复接口后模块化能**超越**基线。若以"超越"为目标，仅修契约不够；若以"理解模块化失败边界"为科学问题，契约修复是明确的下一步假设。

## 限制

1. 分类是机械的：zero_wrong 是"算法理解类错误"的代理，不能区分算法根本错误、遗漏题目要求与边界条件错误——细分需要语义复核（人工或模型），本报告未做。
2. NameError/TypeError 不必然是跨模块接口问题，也可能是模块内部缺陷；但 M0 对照组为 0% 支持接口解释。
3. partial ≠ 局部小错：只过 ≤25% 测试的候选可能只是碰对了平凡用例；分带分析只是部分缓解。
4. 仅 seed42、困难层 20 题；比例数字无显著性检验，只作方向参考，不得外推。
5. 异常类型分析只覆盖困难层（决策关键层）；简单/中等层数据在 JSON 中但未展开。
6. 本分析与既有正式结论一致：No-Go for RL 不变。
