# G4-v4 函数级输出协议（草案）

状态：**草案，仅协议与规则**。适用于宏观 v4 的 G4 第二步。
决策约束（2026-10-11）：只批准起草协议、拼装规则与失败分类，并完成三轮审查；
**未批准模型执行**，**未批准把"整文件 vs 函数级"当作 M0/M2 方法比较**。
因此本文不含任何执行结果；所有数字均为待测量的设计值。

## 0. 为什么需要这一版协议

G4 第一步的归因结论（`experiments/d1_G4_protocol_attribution_v1_20261011/`）：

- 三题 M0 补丁 **0 个格式错误**；失败是 **E3 坐标失败**（PR126 五个 hunk、PR440 一个 hunk）与 **E2 包路径失败**（PR142 自加 `beetbox/` 前缀）。
- 4 个确定性夹具 × 3 任务 **12/12 符合预期** → 补丁入口判定正确，**不是入口过严**。
- 完整文件接口在 6500 预算下不可执行（三题剩余 −5692/−551/−22241），且本地模型在该提示形态下只输出 2 token。

因此本协议的定位是：**绕开行号坐标与整文件体积这两个失败源，同时不引入"任意拼装"的自由度**。

## 1. 一个具体未知

在**不依赖行号坐标**的补丁接口下，本地 7B 能否产出可组装、可应用、可评价的候选？
（竞争解释：H1 能，失败原本主要来自行号坐标；H2 不能，失败还会转向语义与接口断裂；H3 能产出但拼装规则本身产生额外失败。）

## 2. 模型输出格式（唯一允许的形态）

模型只输出**被修改的顶层定义**，每个定义一个块：

```
### DEF: <顶层定义名>
```python
<该定义的完整新内容，含定义头>
```
```

规则：

1. `<顶层定义名>` 必须是父文件中**已存在的顶层 `def`/`class`** 名，或（新增辅助）以 `_d1_` 前缀命名。
2. 块内必须是**完整可独立解析的定义**：不允许 `...` 占位、不允许只给函数体片段、不允许 diff。
3. 未修改的定义不输出。
4. 不允许输出文件级语句（import、模块常量、`if __name__` 块）；需要新增 import 时改为在块内使用**全限定名**（如 `import os` 已在父文件中则直接 `os.path`）。
5. 输出中不得出现行号、不得出现 `@@`。

## 3. 拼装规则（确定性，逐条可判定）

按下列顺序把块拼回父文件，产出候选工作区：

| 步骤 | 规则 | 失败码 |
| --- | --- | --- |
| A1 | 解析块；块头重复或缺失定义名 → 拒绝 | `F1` |
| A2 | 对每个块，在父文件中查找同名**顶层定义**（AST 顶层，`def`/`class`）；找不到 → 拒绝 | `F2` |
| A3 | 用块内容替换该定义在父文件中的完整源码段（AST `lineno`→`end_lineno`），其余字节保持不变 | `F6` |
| A4 | 新增 `_d1_` 前缀定义按块出现顺序追加到文件末尾 | — |
| A5 | 拼装后做 AST 解析；不通过 → 拒绝 | `F3` |
| A6 | 记录：改动的定义名集合、新增定义名集合、每块字节数 | — |

**接口证据（不改变判定，只用于诊断）**：若新增了 `_d1_` 辅助定义，检查入口定义是否出现对该名的调用；未出现则登记 `interface_never_called`（对应已有证据：helper 被调用不等于返回值参与终值，而这里更强——连调用都没有）。

## 4. 失败分类（与 v1/v2 的 E 类并列，不混用）

| 码 | 含义 | 判定方式 |
| --- | --- | --- |
| `F1` | 输出格式不合规（块头缺失/重复、含行号或 `@@`、含文件级语句） | 解析期 |
| `F2` | 声明了父文件中不存在的顶层定义 | 拼装 A2 |
| `F3` | 拼装后语法不通过 | 拼装 A5 |
| `F4` | 拼装通过但导入失败 | 评价前 |
| `F5` | 行为未通过公开评价 | 评价期（唯一与语义相关的失败） |
| `F6` | 替换段定位失败（AST 边界异常） | 拼装 A3 |
| `P0` | 请求前预算预检拒绝 | 预检期 |

**要求**：报告必须分别给出 F1—F6、P0 的计数；**不得把 F1—F4、F6、P0 写成行为失败**，也不得把 F5 之外的失败当作方法效果。

## 5. 预算与预检（沿用既有口径，正式值待冻结）

- 每臂总 token 上限、模型身份与计量、seed、ctx：**均待 G4 资源门冻结**，本草案不预设数值。
- 请求前必须做 ChatML 预检；超剩余预算的请求不发送并记 `P0`。
- 逐臂预算拒绝计入该方法失败，保留在分母。

## 6. 与既有协议的关系（不得混淆）

- 本协议是**接口变更**（统一 diff → 定义级替换），不是方法变更。
- **不得**把"整文件接口"与"函数级接口"直接当作 M0/M2 比较；M0/M2 的定义仍是"整体一次生成"与"预先登记 2—3 组件 + 组装"。
- 若将来要比较接口本身，必须另立阶段计划与三轮审查，并明确它是**协议消融**而非主问题 A 的方法对照。
- 旧 v1/v2/v3 批次的失败与成绩全部保留，不回写。

## 7. 已知偏差（必须随结果一起报告）

1. **接口偏离真实工具**：真实代码代理多用 diff 或整文件编辑；定义级替换是构建者为绕开行号失败而设定的约定。
2. **禁止文件级语句**：父文件中若需新增模块级 import，本协议不允许，可能人为抬高难度；该限制必须写进结论边界。
3. **单文件范围**：本协议默认每次只处理一个目标文件；跨文件任务（PR126 涉及三个文件）需要分文件多次请求，请求数因此上升，预算摊销方式待定。

## 8. 三轮审查（本节为草案自审，待独立复核）

**第一轮：可行性**
- 输入全部来自已冻结的父源码与需求；拼装为纯本地确定性操作，无需网络。
- 风险：PR126 需要改三个文件，按第 7 节需三次请求，可能超出单臂预算；**修订**：允许在协议中显式声明"本题按文件拆分请求数"，并把请求数与 token 一并计入账本。
- 结论：可行，前提是请求数纳入冻结表。

**第二轮：意义**
- 成功后可直接回答"能否取得可评价候选"，从而决定 G5 是否启动；失败也有价值（把失败从坐标问题推进到语义/接口问题）。
- 风险：若拼装规则过宽，会把"方法失败"混成"适配器修复"；**修订**：A5 之后不做任何人工修补，F3 一律计入方法失败，不尝试自动修复。
- 结论：通过。

**第三轮：区分力与可信度**
- 三个竞争解释 H1/H2/H3 可由失败码分布区分：H1 预测 F1/F2 显著下降且 F5 为主；H2 预测 F5 与 `interface_never_called` 上升；H3 预测 F1/F2/F6 仍高。
- 混杂：定义名匹配与文件范围会引入新失败源（F2/F6），因此**必须与旧批次分开报告**，不能直接比较成功率。
- **修订**：F5 必须由同一评价器与同一公开用例判定；F1—F4、F6、P0 不与 F5 合并统计。
- 结论：通过。

三轮审查为助手自审，**不是**独立人类或外部审查。
