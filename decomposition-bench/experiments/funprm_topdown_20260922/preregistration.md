# FunPRM top-down 函数轨迹：分阶段实验协议

创建时间：2026-09-22  
状态：阶段 0 已通过；阶段 1 在唯一一次定向提示修复后仍未过门槛，已按协议停止

## 1. 研究问题

在同一本地 `qwen2.5-coder:7b` 和自定义 APPS 评测条件下，严格遵循 FunPRM 的高层函数在前、辅助函数在后、每个函数带 docstring 的 Chain-of-Function 轨迹，能否形成可用的函数前缀标签和足够的候选选择空间，并最终提高无执行反馈的候选选择成绩？

本实验不启动 RL，不覆盖旧 `functionized` 输出，也不把工程冒烟当作效果结论。

## 2. 阶段图

`阶段0快照 -> 阶段1协议与冒烟 -> 阶段2数据与候选池门控 -> 阶段3训练标签 -> 阶段4固定7B评分器 -> 阶段5多确认集 -> 阶段6奖励校正/更强模型 -> 单独RL审查`

每个阶段都必须完成阶段审查和方向审查。前一阶段不通过时，只允许定向修复或停止，不直接扩大预算。

## 4. 阶段 1：独立 top-down 协议和 10 题冒烟

### 4.1 代码协议

- 新增独立方法名 `top_down_cof`，保留历史 `functionized` 原义不变。
- 生成一个完整 Python 程序，包含 2--5 个顶层函数。
- starter entrypoint 必须是第一个顶层函数；高层函数可以调用随后定义的辅助函数。
- 每个顶层函数必须以非空 docstring 开头；不得使用嵌套函数。
- 允许 import、常量和普通声明；不得在所有辅助函数定义完成前执行入口函数。
- prompt 不包含 public/private 测试、测试结果或标签。

### 4.2 前缀和奖励协议

- 每个非最终函数边界形成累计前缀；原前缀逐字保留，续写只能追加剩余辅助函数。
- 续写提示不得再次要求入口函数位于最后。
- 结构合规与训练奖励分开记录：结构错误用于审计，奖励只由训练 split 的 private 单元测试是否全通过决定。
- 函数式任务的完整程序在模块导入完成后由 evaluator 调用入口函数，因此入口函数可以引用后定义的辅助函数。

### 4.3 冒烟预算和门槛

- 数据：现有训练用途的 `data/processed/apps_train_introductory50_private_safe.json` 前 10 题；这些题不作为新确认题。
- 模型：Ollama `qwen2.5-coder:7b`；seed 52；每题 2 个候选；最多 20 次模型请求。
- private 延后：生成和结构审计阶段不执行 private；冒烟只检查提示、解析、顺序、docstring、前缀和 public 可执行性。
- 通过条件：无测试泄漏；解析器接受规范 top-down 样例并拒绝 helper-first/缺 docstring 样例；生成输出中至少 8/10 题有一个结构有效候选；前缀检查全部通过。
- 失败条件：入口顺序仍被误杀、前缀被改写、private 提前执行、或少于 8/10 题有结构有效候选。
- 最多一次提示词定向修复；若仍失败，阶段状态为停止，不进入新数据抓取。

### 4.4 首次冒烟与唯一修复记录

- `v1` 实际结果：20 次请求中仅 3 个结构有效生成，覆盖 2/10 题，未达到 8/10 门槛；private 程序评测和 private 测试执行均为 0。
- 主要失败：16/20 个回答触发 `function_count_out_of_range`；其中多数只生成一个顶层函数，另有 3 个把辅助函数嵌套在入口函数内部。
- 唯一修复：仅强化既有结构约束，明确单函数回答无效、每个 `def` 必须顶格、简单题也要抽取至少一个有意义的 helper，并要求输出前自检 2--5 个顶层函数、入口顺序和 docstring。
- 不变项：数据、前 10 题、模型、seed、每题候选数、解析标准、public/private 政策和通过门槛均保持不变；重跑写入独立 `v2` 后缀。

### 4.5 阶段 1 最终审查

- `v2` 实际结果：20 次请求中 8 个结构有效生成，覆盖 6/10 题；低于至少 8/10 的通过门槛。
- 前缀审计：11/11 个累计前缀逐字保留，续写提示均包含原前缀且不含入口函数最后的旧要求。
- 隔离审计：`private_program_evaluations=0`，`private_test_executions=0`。
- 阶段决定：`fail_stop`。不进入阶段 2，不继续修改同一提示追逐门槛。
- 方向建议：如继续，另立阶段 1b 预注册结构化生成协议；不得把它写成阶段 1 的成功重试。
- 结果报告：`reports/funprm_topdown_phase1_smoke_20260922.md`。
- 机器审计：`data/processed/funprm_topdown_smoke10_qwen25coder_7b_n2_seed52_audit.json`。

## 5. 后续阶段冻结原则

- 候选池 oracle 在训练前只允许读取开发池 private；确认集 oracle 必须等评分选择冻结后再计算。
- “至少 100 道训练题”指实际进入优化的可用问题，不包含验证集、开发集和确认集。
- 训练、验证、开发和 2--3 个确认集在模型调用前一次性冻结、去重并清理 prompt 可见 private。
- 所有节点先做 4 次 rollout；中间标签节点可按冻结规则补到 8/16 次。采集器必须按单次 rollout 断点续跑，不得重做或覆盖前四次。
- 若同时改变轨迹顺序、训练题数和 rollout 数，必须保留等预算消融；否则只报告整套系统结果，不归因给单一因素。
- 更强模型前先评估论文的 meta reward correction；现有含 public 特征的 Ridge 路由器不视为该机制。
- RL 始终是独立审批阶段，当前状态为 No-Go。
