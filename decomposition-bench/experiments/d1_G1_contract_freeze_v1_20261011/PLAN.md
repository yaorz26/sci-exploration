# G1 公开契约与评价器冻结（宏观 v4）

阶段：G1（宏观计划 v4 第五节）
前置：`RESEARCH_PLAN.md` v4；依据证据 219 号、224/225 号反例、232/233 号
投入上限：一次 90 分钟；零模型、零付费、零训练、零新增行为（除非判定要求补一个锚点）

## 1. 一个具体未知

现有三个研究池候选（PR126、PR142、PR440）与一个待解候选（cache）中，**题面明示的公开入口是否都被当前验收覆盖**？

## 2. 竞争解释

| 编号 | 解释 | 可区分观察 |
| --- | --- | --- |
| H1 | 覆盖完整：所有明示入口都已被某个评价项诊断 | 每个明示义务都能在矩阵中连到评价项或行为锚点 |
| H2 | 旧评价漏掉入口（可独立遗漏） | 存在义务：需求明示、当前无直接诊断、且能构造合法行为反例 |
| H3 | 入口可观察性本身不足 | 义务存在但公开观察无法判定（如内部时点、未提供参数的默认行为） |

## 3. 最低成本区分验证

从**已保存**产物构建合并矩阵：`contract_observation_audit.json`（义务与观察状态）＋各任务候选的评价器/公开用例/冻结哈希＋PR126 已完成的入口反例。**只读、确定性、零行为调用**。仅在出现"会改变纳入判断的明示入口缺口"时，才补一个最小行为锚点。

## 4. 可见产物

`experiments/d1_G1_contract_freeze_v1_20261011/contract_matrix.json`：
逐任务、逐明示义务一行，含需求出处（文件+行）、入口、有效输入、公开观察、旧评价覆盖、补充锚点、替代组织、未观察项、状态与理由、证据路径与哈希。

## 5. 事前判定

| 观察 | 判定 |
| --- | --- |
| 义务有评价项或行为锚点覆盖 | `covered` |
| 义务明示但无直接诊断，且已有行为反例证明旧评价会误收 | `contract-ready`（已补锚点） |
| 义务明示但无直接诊断，且能构造合法行为反例、会改变纳入判断 | `gap-needs-anchor`（最多补一个最小锚点） |
| 义务存在但公开观察无法判定（内部时点/未给参数默认值） | `unknown-unobservable`（保留，不自动补测，不填成通过） |
| 任务需求或交付材料与交付目录不一致 | `pending-inconsistent`（不进可用分母） |

**禁止**：把"静态未观测"写成"已通过"；把内部私有状态当公开行为；为凑格补默认参数/缓存/包装测试。

## 6. 退出条件

每项被标记为 contract-ready、research-pool-only with unknown 或 reject，并有原始证据路径。没有新增行为证据时只做冻结，不以报告数量作为结果。

## 7. 三轮审查（执行前自审）

- **可行性**：全部输入为已保存 JSON/MD 与哈希，路径已知；无需模型、网络或行为执行。通过。
- **意义**：直接决定后续哪些任务可进 G4 比较；把"明示入口是否被覆盖"从印象变成逐行可核查矩阵，改变纳入判断。通过。
- **区分力与可信度**：H1/H2/H3 三态可由"需求明示性 × 现有诊断存在性 × 可构造性"区分；不把静态缺口当假通过；不把形式反例当模型效果；保留分母与 unknown。通过。

审查为助手自审，不是独立人类或外部审查。
