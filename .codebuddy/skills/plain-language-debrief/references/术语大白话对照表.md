# 术语大白话对照表

用途：写到这些词之前，先看这里，确保给用户的是"先讲人话、再给术语"的表述。
遇到表里没有的新词，按同样格式补一行，这张表会越用越省事。

格式约定：**术语** → 一句大白话（必要时补一句"在本项目里指什么"）。

---

## 一、数据与切分

| 术语 | 大白话 |
| --- | --- |
| split / 切分 | 把题目分成几堆，哪堆放什么用途提前定死 |
| custom split | 自己定规则分出来的题目集合，不是官方发布的那个标准分法 |
| 冻结 / frozen | 定下来之后就不许再改。改了，后面的结果和前面的就不能比了 |
| leakage / 泄漏 | 不该看到的东西被看到了。比如用来打分的私密测试题，被混进了给模型看的提示里 |
| 预注册 / preregistration | 先写死"要做什么、怎么算成功"，再开始跑。防止看到结果后倒过来编标准 |
| 分母 | 一共算了几份。写 9/25 时，25 就是分母。分母不一样，两个分数不能直接比 |

## 二、评测指标

| 术语 | 大白话 |
| --- | --- |
| pass rate / 通过率 | 做对的比例。25 题过 9 题，就是 9/25 |
| public test / 公开测试 | 明面上给的测试。程序写完可以自己跑，看看过没过 |
| private test / 私有测试 | 藏起来的那份测试，用来识别"是不是真的会做"，而不是"是不是猜中了公开测试" |
| candidate / 候选 | 让模型就同一道题写出的若干份不同答案，一份叫一个候选 |
| candidate pool / 候选池 | 同一道题所有候选放在一起的那一坨 |
| 首候选 | 模型第一遍写出来的那份，不做任何挑选。也是一个自然的对照基准 |
| oracle / 上限 | "假设能作弊"的成绩：同一批候选里，不看公开测试、直接挑真正最好的那份。这是这批候选能达到的天花板 |
| pool oracle / 池 oracle | 同上，强调是在整个候选池范围内取的最大值 |
| baseline / 基线 | 拿来对比的那个"老办法"，一般是首候选或最简单的做法 |
| 上限 / upper bound | 最好情况下能到哪。到了上限也只等于别人的下限，就说明这个方法本身没价值 |
| partial / 部分通过 | 只过了一部分测试，说明方向对但没做全 |
| all-pass / 全通过 | 所有测试都过 |

## 三、失败分类

| 术语 | 大白话 |
| --- | --- |
| zero_wrong | 候选在测试上得 0 分，原因是**算法想错了**（比如题意理解偏了、步骤漏了），不是代码写错了 |
| zero_runtime | 候选在测试上得 0 分，原因是**跑起来就崩了**（语法/名称/类型之类的错误） |
| 归因 / attribution | 弄清"到底是什么原因造成的"，而不是只知道"结果不好" |
| 反例 | 和结论相反的例子。找到反例，结论就得改，所以反例比支持证据更值钱 |
| 反事实 / counterfactual | "如果当时不这么做，会怎样"。用来检验某个原因是不是真的在起作用 |

## 四、方法与协议

| 术语 | 大白话 |
| --- | --- |
| 基线（方法意义上的） | 直接让模型一次写完整程序，不做任何拆分。记为 M0 |
| M0 | 直接生成完整程序（对照组） |
| M1 | 先让模型写一段文字计划，再按计划写程序 |
| M2a | 先拆成几个函数骨架（只有函数名和说明），再把每个函数分别实现 |
| M2b | 同 M2a，但拆分结果用 JSON 格式表达 |
| 模块化 / 分解 | 把一道题拆成几个小函数分别写，而不是一口气写完 |
| skeleton 分解 | 只给出函数名、参数、说明的"空架子"，实现留空 |
| 阶段契约 / stage contract | 各段之间约定的"你负责什么、交出什么"。约定没写清或没遵守，接起来就崩 |
| helper I/O | 拆分出来的小函数，它接收什么、返回什么。这里对不上，拼起来就出错 |
| composer / evaluator | 负责把各段拼起来的部件 / 负责运行和判分的部件 |
| 硬门控 / 硬门控反事实 | 一条硬规则：不满足条件就一律不要。用它做一次"假如从一开始就拦掉，会怎样"的检验 |
| 组合 / combination | 拆分出的各段，每段有多个实现版本，从中各挑一个拼成完整程序，一种挑法叫一个组合 |
| 全空间穷举 | 把所有可能的挑法全部试一遍。（注：前提是每段都有至少一个能跑的实现，某段全崩就根本拼不出来） |
| format tax | "为了满足格式要求"而额外付出的代价。比如硬让模型按某种格式输出，本身就会拉低质量，跟方法好坏混在一起很难分清 |
| 等预算对照 | 让两边花一样多的算力/次数再比。不这样做，赢了也可能只是因为赢的一方多试了几次 |
| 确定性装配 / 机械装配 | 不再让模型重复写固定格式，而由程序按已经定好的规则排序、补格式和拼起来；程序不能趁机改算法 |
| token 预算 | 允许模型说多少话的额度。额度不同，结果不可比 |
| tie-break | 几个候选分数一样时，按什么规则挑一个。规则要提前定死 |

## 五、模型与训练

| 术语 | 大白话 |
| --- | --- |
| LLM / 大模型 | 现在这类会写字、会写代码的 AI |
| Qwen2.5-Coder | 一种专门写代码的开源大模型。3B / 7B 指参数量，越大越强也越吃资源 |
| Ollama | 在本机跑这些模型的工具，不用连网 |
| LoRA / QLoRA | 一种"只微调一小部分参数"的省资源训练法，能在普通显卡上给大模型做改造 |
| RL / 强化学习 | 让模型自己多试，试对了就奖励它，慢慢学会怎么做对 |
| PRM / 过程奖励模型 | 专门给"解题过程"打分的模型，相当于一路给评语，而不是只看最后答案对不对 |
| CodePRM | 上面那类模型用在代码题上的版本。**本项目的神经 CodePRM 部分没超过简单基线** |
| DecompRL | 一篇论文提出的方法：把题拆开写，再用强化学习训练。**本项目只复现了它的"拆开写"这部分，没有做强化学习，所以不能叫 DecompRL** |
| 推理 / inference | 让模型写答案的过程。不改模型参数，只是用它 |
| 训练 | 改模型参数。花费远大于推理 |

## 六、统计与决策

| 术语 | 大白话 |
| --- | --- |
| seed / 随机种子 | 控制随机的初始数值。同一个 seed 跑两次结果一样。所以只看一个 seed 的结果，说明不了稳不稳定 |
| 双 seed 稳定性 | 换一个随机起点再跑一遍，结论还成不成立。没做这个检验，就不能说结论稳 |
| Spearman 相关系数 | 两个排名有多像。1 是完全一样，0 是毫无关系 |
| Ridge / 岭回归 | 一种简单、稳当的拟合办法，用来从数据里学一个打分规则 |
| GVR | 一种"生成多个候选再验证挑一个"的通用做法，就是多写几份、挑最好的 |
| 误差 / ± | 数字后面的加减号表示波动范围。比如 0.45±0.03，意思是大约在 0.42 到 0.48 之间 |
| No-Go | 结论是"停"。在这套条件下这条路没走通，不建议再投资源 |
| Go | 结论是"继续"。值得投入下一步 |
| 复现 / reproduction | 按论文说的方法自己做一遍，看能不能得到同样的效果 |
| 缩小规模复现 | **因为机器条件限制，把规模缩小了再做一遍**。它不等于严格复现，标签也只能写到这个程度 |
| 方向决策 | 决定"接下来往哪个方向走"。**这类结论由用户和导师做，AI 只负责提供证据和选项** |
