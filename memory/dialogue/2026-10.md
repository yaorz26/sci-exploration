## D077｜2026-10-02 18:03+08:00｜用户提问：相关论文用什么模型、为什么、为什么不用更强的模型

- 用户请求（原话）："我想知道一个问题，相关论文研究都用的是什么模型，为什么他们使用对应的模型，为什么不使用高级模型"。
- 做法：不凭记忆作答，先扫本地证据——用脚本 `tmp/scan_models_in_papers.py` 统计 `archive/pdftext/*.txt`（8 篇全文）里的模型提及与相关理由句，再据此成文。
- 产出 `docs/week3/10.2相关论文的模型选择与理由.md`（六节）。核心结论：
  1. **主力模型几乎都是 7B 级开源权重**（Qwen2.5-Coder-7B / Qwen2.5-7B / Llama 3.2 / Gemma 3 / LLaDA-8B）；**专有 API 模型主要当强基线与上界参照**（GPT-4o-mini、GPT-4、o 系列、Gemini、DeepSeek-R1）。
  2. **选型理由（逐条带原文出处）**：① **必须能训练**（PRM/RL/SFT 类方法在闭源 API 上做不了——这是首要原因）；② 成本（MoT 专设 RQ3 成本分析并选 GPT-4o-mini"API 成本极低"；CodePRM 明言 7B 是"成本与效果的平衡"）；③ 硬件预算（FunPRM 2×A100、SecCodePRM 4×80GB、AdapTrack/EfficientGrammarConstrained/Lookahead 8×A100、DecompRL 80×H100）；④ 可复现（多篇开源权重与脚本）；⑤ 需要 logits/词表做约束解码（闭源 API 不返回 logits）；⑥ 上下文预算（AdapTrack 为小窗口模型剔除 3,584 token 以上样本）。
  3. **"为什么不用最强模型"分三种情况**：想用但用不了（不能训练、不给 logits）；用了但只当参照；**刻意不用**——太强的模型会把方法差异压平（HumanEval 已饱和到 90%+），中等模型上差异才可测量。
  4. **对本项目的意义**：我们的 4-bit 7B 与文献主力同档，不是异类；但我们的负结果正对应这一档的能力天花板，而文献正结果集中在"API 大模型 + 纯提示词"或"带训练补偿"两类配置——**我们的"本地 7B + 零训练 + 等预算"恰好落在正结果之外的那一格**，故负结果与论文正结果不矛盾。
