# 研究发现与问题

## 已验证发现

### Prompt-only 模块化与 top-down

- M2 分解、独立实现和组合在简单/中等/困难分层上没有稳定超过直接生成；困难层主要瓶颈是算法理解，接口不一致是额外损失。
- 穷举已保存实现池后上限仍未改善，排除了“只是组合采样太少”的主要解释；同预算直接生成明显强于增加 M2 组合。
- 真正 `top_down_cof` 协议已实现，但单轮、JSON 契约两步法和阶段 1c 的 JSON 函数体/论文式 few-shot 两路均未过门槛。本地 7B top-down 分支正式停止。
- 事后机械装配能改善格式合规，但不能证明模型按 top-down 顺序生成，也不能改写预注册失败。
- 接口/契约断裂是拆分专属的超额损失：困难层运行时异常中接口类（NameError/TypeError/RecursionError/EOFError）占 M2a 55%、M2b 61%，M0 为 0%、M1 为 25%；直接反例为 `NameError: name 'dict_scores' is not defined` 与 M2b 的 24 次 TypeError。**注：本地未做奖励张量 rank 检验，不能称已证明条件独立假设失效。**
- 协议级损失：M2a 11/35（31%）、M2b 14/35（40%）的有效分解因某函数实现全部解析失败而完全无法组合。
- 成本效率：每 10 万输出 token 的池全过题数（简单层）M0 105.2、M1 93.2、M2a 7.5、M2b 6.0；P5c 等预算对照为 8/20 对 3/20（2.6 倍 token 差距），且 M2a 可达解是 M0 池的严格子集。
- 论文原文核对（2026-09-26，`archive/pdftext/08_DecompRL.txt`）：DecompRL Table 1 在 1 万 token 时解出率 0.25、低于基线 0.31--0.32，**5 万 token 才领先**（0.40 对 0.39），10 万/50 万为 0.44/0.48；Table 4 确认无 RL 层级推理 11.0% < 标准生成 14.0%；§6 自述格式税、模块化对模型是 off-policy（CodeContests 参考解法仅 65% 含函数）、存在规模坍缩。

### Helper-first FunPRM

- **复现忠实度清单（2026-09-27 代码层核实）**。与论文一致：步骤单位为函数；评分器为生成式 `+/-` 概率（`score = p(+)/(p(+)+p(-))`）；Best-of-N 聚合函数级分数选优；选择时不看公开测试。**偏离**：① 论文的**元学习奖励校正未复现**（论文用可训练奖励校正表 + 双层优化、有限差分近似元梯度；本项目直接用节点真实测试成功率作标签）；② **轨迹方向相反**——`src/whole_program.py` 的 `functionized` 分支要求 helper 先写、入口函数最后（helper-first），而论文 CoF 要求主函数先写（main-first，对应本项目已失败的 `top_down_cof` 分支）；③ 规模缩小（7B Q4 本地、APPS custom split 60 题确认、候选 10/题，vs 论文 O4-mini/Qwen3-Coder 等、LiveCodeBench 454 题、候选 8/题）。故结论口径为"FunPRM 主干机制的本地缩小规模复现，含两处实质性机制缺失"。
- 旧结构门禁错误要求入口函数最后。unit-test-only 重标把旧 48 题成功 rollout 从 `47/412` 修正为 `160/412`，正节点 `54/103`，覆盖 `28/48`，split-half Pearson 从 `0.488` 升至 `0.808`。
- 扩量得到 100 个源问题、188 个前缀节点和 1308 次 rollout。冻结训练节点的 4/8/16 次分布为 `85/61/42`，正节点 87，均值标签 `0.3277925532`。
- 原协议在按首 4 次结果筛出的 55 个不确定节点上 Pearson=`0.4305`，按原协议确实失败。另立的不看标签哈希 64 节点校准为 `0.8864800569`，bootstrap 95%区间 `[0.8297,0.9363]`；新证据不追溯改写原失败。
- 扩量 7B QLoRA 的内部留出 MSE=`0.1816646`、MAE=`0.2940561`，内部证据混合；真正有判断力的是冻结候选选择评测。
- 20 题验证中新/旧 adapter 均 `9/20`，首候选 `5/20`，随机期望 `5.2/20`，候选池上限 `13/20`；修正字段读取后的四条件准入门槛通过。
- 两批全新确认均为正：A 为评分器 `5/30`、首候选 `3/30`、随机期望 `2.2/30`、池上限 `6/30`；B 为 `7/30`、`4/30`、`5.0/30`、`8/30`。
- 合并确认：评分器 `12/60`，首候选 `7/60`，随机期望 `7.2/60`，池上限 `14/60`；相对首候选净增 5 题，6 胜 1 负，精确双侧符号检验 `p=0.125`。
- 冻结 10,000 次 bootstrap 相对随机期望的 95%区间为 `[0.0266666667,0.1433333333]`；两切分四条件门槛全部通过。
- 事后敏感性复算把随机基线改成只在有效候选或题内去重候选中抽，随机期望分别为 `7.3777778/60`、`7.3555556/60`，100,000 次 bootstrap 区间下界仍大于 0。481 个有效候选中只有 6 个题内重复槽位，重复没有制造主结论。
- 评分器已取得候选池可达到的 12/14 个全通过题，同池只剩 2 题 headroom。当前主要瓶颈是候选池质量，不是评分器明显漏选大量正确答案。

## 当前推断

- **结构定位（2026-09-26）**：在已梳理的全部"拆分"文献中，M2a/M2b 是唯一同时具备"跨候选重组"与"零学习补偿"的配置；其余方法至少放弃其一（DecompRL 有重组但有 RL；MoT/CodeT 无学习但不重组）。论文的拆分要么不重组（无接口风险），要么重组但有学习补偿。
- **预算区间错配（2026-09-26）**：DecompRL 的收益要到每题 ≥5 万 token 才出现，本机约 3.3k token/题，低 15 倍以上——我们把方法用在了论文自认不占优的预算区间。
- **模型能力阈值（假设）**：MoT 的 prompt-only 模块化在 GPT-4o-mini / DeepSeek-R1 上为正、本地 7B 为负；但 MoT 不重组、不搜索，只有强弱两点对照，属假设而非结论。
- 7B 能从函数前缀 rollout 标签中学到可跨两个新切分重复的候选质量信号。
- "拆成更多函数"本身不是收益来源；可靠标签、冻结选择顺序和候选池中确有正确答案更重要。
- 在当前候选池上换更强评分器的理论收益最多 2/60；若目标是提高最终正确率，改善生成候选的预期信息收益更高。

## 结论边界与不确定性

- 正结果属于 helper-first FunPRM 候选选择，不是 top-down 成功、论文完整复现或生成模型能力提升。
- 绝对成绩为 `12/60`，虽通过预注册门槛，逐题符号检验 `p=0.125`，不能写成“强统计显著”。
- 官方 APPS evaluator/test split 未取得，结论只适用于本地 evaluator 和 custom split。
- 候选生成器与评分器同属 7B 家族，可能共享偏差；训练中的自适应停止和 `max_length=768` 截断仍是限制。
- 只有两个确认切分而非三个；两批均为 30 题，总样本 60 题。

## 已排除或暂停的方向

- prompt-only M2 原样扩大或直接进入 RL。
- 仅靠增加组合数量修复 M2。
- 继续修补本地 7B top-down 提示。

## 提示词层面的未试缺口（2026-09-27 代码与论文原文核对新增）

- 本地 M2 分解提示（`src/decomposition.py`）与 DecompRL 论文 Appendix I 原版提示存在三处实质差异，且均与实测失败模式对应：
  1. **论文用 one-shot 完整示例**（逆序对/归并排序，带类型签名与 Args/Returns docstring），本地为零样本规则式提示；9.14 计划写明 M2a 使用"论文 Appendix I 的 one-shot 函数骨架 prompt"，但实际实现未搬示例（适配 starter code 可解释部分改动，one-shot 整体缺失未见正式标注）；
  2. **论文显式要求共享状态参数化**（"If shared state needs to be passed between the functions, describe it in one of their docstrings and make it an argument"），本地仅有"依赖按名字调用、不自动接收返回值"规则——与 `NameError: dict_scores` 类共享状态断裂失败直接对应；
  3. **论文示例重类型标注**（签名与 docstring 均带类型），本地写 "Omit type annotations when unsure"——与 M2b 困难层 TypeError 24/46 的主导失败对应。
- 已试的三轮提示词修复（repair_v1 检查清单、阶段 1b 结构化契约、阶段 1c few-shot 与 JSON 函数体）**全部针对格式合规**，而非上述接口质量部件；每次都修好了目标失败模式（实现有效率 99.7%、拼装零失败）但未缩小与直接生成的差距。
- 结论：提示词改进**未全部试尽**，剩余一个有依据的实验（论文原版 one-shot 分解提示 + 类型化 docstring + 共享状态规则，在冻结中等+困难 40 题上重跑 M2，规模约 600 次请求，与 P5c 相当）；但按既有证据其预期上限为"接口类失败减少、中等层可能追平"，无证据支持超越等预算直接生成。
- **"强模型分解 + 7B 实现"隔离实验（2026-09-27 复核）**：DecompRL 原文 Figure 7(b) 确认"去掉实现训练不伤害 pass@10，分解策略是主要 RL 瓶颈"，为分解质量杠杆提供论文级依据；M3 人工分解（10 题，3/10 = M0）为本地反证但弱。该实验在 9.20 方向文档中被列为"必要的隔离实验"，从未执行；强模型只做分解时成本约 80 次请求（低于一次确认批次），实现与评测仍在本地。强版本（docstring 携带算法洞察）可能突破困难层天花板，但成功含义变为"强模型设计+弱模型抄写"。

## 经判据筛选与文献核查的候选研究问题（2026-09-27，取代上节作为立题候选）

**候选 1（首选）：评分器的"跨生成器迁移"与"家族偏好"**

- 问题：同家族训练的函数级评分器，学到的是"代码质量"还是"本家族的写作风格"？
- 两个可分离的子问题：(a) **迁移**——用 Qwen 训的评分器挑另一个模型生成的候选，相对首候选的优势是否还在；(b) **偏好**——两族候选混合时，评分器是否系统性偏向同族候选（超出真实质量差异的部分）。
- 为什么是"未知"：本项目 `12/60` 只在同族（Qwen 生成 + Qwen 评分）条件下测过；这恰好是本项目报告"结论边界与风险"里自己列的限制。文献核查（2026-09-27）：LLM 评审的自我偏好已有报道；OpenAI 代码评审文章提到评审对模型生成代码与人类代码存在分布偏移但"没有干净的直接测量"；**函数级 PRM 在代码候选选择上的跨生成器迁移未找到直接研究**。【不确定】立项前需再做一轮更细的文献核查。
- 实验草案：Dolphin3 8B Q4（本机 9.14 已验证可跑）在 30 道冻结新题上生成每题 10 候选 → 现有 Qwen 评分器选择 → 冻结后揭盲 private；混合池测偏好指数；同族弱模型（Qwen 1.5B/3B）作对照臂，以区分"家族不匹配"与"候选池本身更差"；public 选择器与随机基线同池对照。
- 成本：约 300 次生成 + 评分 + 评测，与一次确认批次同量级，本机可行。**需解除"暂停"状态，属用户决定。**
- 决策价值：不迁移 → 该方法的部署含义是"评分器绑定生成器"；迁移且无偏好 → `12/60` 的解释从"可能学了家族风格"升格为"学了代码质量"。

- "提前预测某题候选池上限是否为 0 / 何时停止采样"：文献核查发现该方向拥挤（Speculative Rejection NeurIPS 2024、ST-BoN NeurIPS 2025、RASC、Damani et al. 2025、自适应测试时计算综述等），通用框架已覆盖；代码执行反馈的窄变体至多是增量工作。不推荐作为立题方向。

**一、过程中观察到的异常现象（多为意外，科学价值最高）**

1. **标签定义方式的影响可能大于模型与损失函数**。仅把"入口函数必须在最后"的结构门禁换成"直接看测试是否通过"，成功 rollout 从 `47/412` 变为 `160/412`（3.4 倍），split-half Pearson 从 `0.488` 升至 `0.808`，零新增模型调用。待探索：过程标签应由"结构合规"还是"功能结果"定义？结构先验会系统性误杀哪些合法写法？
2. **公开测试的区分力可能依赖"候选是怎么生成的"**。模块化候选在最高公开分上的并列率为 `20/20`（100%），直接生成为 `17/25`（68%）；且模块化候选"公开全过但私有未全过"的比例为 26% 对直接生成的 12%。待探索：public 信号的信息量是否随生成方式系统性衰减？若成立，会动摇"用 public pass rate 选候选"这一广泛做法的前提。
3. **简单题上"拆分反而损害"候选质量**（池有全过：M0 `15/20` → M2a `10/20` → M2b `7/20`）。文献通常只报平均值，此处出现明显的"难度 × 方法"交叉效应。待探索：拆分在何种难度区间是负收益？
4. **加约束反而降低覆盖**：接口硬门控使 M2a 候选覆盖 `15→12/20`、M2b `13→7/20`，正确率仍为 0。待探索：结构约束的"可用性收益"与"多样性损失"如何权衡，是否存在净正区间？
5. **难题上采样多样性塌缩**：困难层 19/20 题连 M0 都无全过候选，且题内候选表现高度一致（同题通过率离散 ≈ 0）。待探索：选择类方法的收益上限是否由"采样多样性"决定，而多样性在难题上会塌缩？这直接解释池上限 `14/60` 的硬天花板。
6. **组合空间的有效维度未知**：P5d 中 M2a 的 284 个组合只产出 105 个独特程序（重复约 63%）。待探索：DecompRL 的"条件独立假设"在真实题目上成立到什么程度？——论文 Appendix J 的 rank-1 检验方法可直接照搬，本项目**尚未做**。
7. **两批确认的相对增益弱于单批**：9.22 单批为 `15/30` 对首候选 `8/30`（+7），9.26 扩量后双批为 `5/30`、`7/30` 对首候选 `3/30`、`4/30`（+2、+3）。待探索：是题池难度分布不同，还是"训练数据扩量"本身未带来增益？**未做归因**。

**二、方法缺口（可补的消融）**

8. **函数级评分 vs 整段评分的对照未做**：用同一批候选、同一预算，只改变"评分器看到的粒度"，可隔离"函数级"这一设计的净贡献。
