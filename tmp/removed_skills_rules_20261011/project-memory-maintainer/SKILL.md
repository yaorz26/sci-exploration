# 项目记忆维护技能

本技能在 `D:\yaorz\research` 每轮对话中强制使用。目标是跨会话保存用户意图、研究背景、决策、结果、失败与下一步。
主记忆入口 `PROJECT_MEMORY.md`，辅助记忆在 `memory/`，原始证据在 `codeprm-reproduction/`；记忆只负责导航与连续性，不替代证据。

**本技能不记录逐轮对话**（2026-10-02 用户要求移除该功能）。需要留存的细节一律写入主题记忆 `memory/<主题>.md`。
`memory/dialogue/` 是 2026-10-02 之前的历史记录，只读、不再更新。

## 零、记录范围：只记与研究相关的内容（2026-10-02 用户要求）

记忆只服务于后续的研究判断与实验执行。写入前先问一句：**这条内容会不会影响以后的研究决策或实验怎么做？** 不会，就不写。

**要记**：研究目的与问题；研究方向、方案取舍与用户决策；实验、数据、代码产物及其路径与口径（分母、样本量、seed、模型、指标）；结论、失败与负面结果、被排除的解释、限制与不确定项；影响实验能否开展的环境与资源约束；用户对研究提出的要求与纠正。

**不记**：AI 辅助性工作及其过程——本项目记忆系统自身的维护改造、技能与规则文件的编写与修改、工具与插件安装配置、文档归档与路径引用整理、格式美化、以及会话流程性的过程叙述。

**边界**：用户明确提出的行为要求（例如汇报方式、提问方式、文档归档规则）属于用户要求，按第三节④与红线③保留；但“AI 按用户要求做了哪些改动、怎么做的”这类**过程**不写进记忆。两者的区别是：记要求，不记执行过程。

## 一、开始任务前（低开销恢复）

1. 完整读取 `PROJECT_MEMORY.md`。它是每轮唯一必读的文件。
2. 按当前请求**选择性**读取主题记忆，不必全读、不必整读：

   | 当前任务是关于 | 读 |
   | --- | --- |
   | 目的、约束、成功标准、范围 | `memory/project-contract.md` |
   | 结论、失败、开放问题 | `memory/research-findings.md` |
   | 方向选择、计划、门槛 | `memory/decisions-and-next-steps.md` |
   | 文件位置、来源、入口 | `memory/artifact-map.md` |

   只需要其中一小节时，先检索定位再局部读取；确需整读时说明理由。
3. 研究事实必须回查 `codeprm-reproduction/.research-state/PROJECT_STATE.md`、实验清单、报告或机器输出。记忆不得推翻证据。

## 二、交还用户前

1. 当前目标、状态、方向、用户偏好、阻碍、结果或下一步有变化时，更新 `PROJECT_MEMORY.md`。
2. 只更新本轮涉及的主题记忆；新细节写入对应的 `memory/<主题>.md`，同名文件存在时追加，不新建重复文件。
3. 本轮新建或移动重要文件时，更新 `memory/artifact-map.md`。
4. 本轮改变研究结论或实验协议时，同步更新 `codeprm-reproduction/.research-state/PROJECT_STATE.md` 与追加式研究账本。
5. 执行一次自动压缩检查（第三节）。

研究任务、研究结论、方案取舍、用户对研究的要求与纠正都必须落盘；用户说“继续”“暂停”“中断”时，也要保留**研究执行状态**的变化。纯辅助性工作按第零节不落盘。不得等用户再次提醒。

## 三、自动压缩规则（2026-09-29 用户要求）

**压缩＝移动，不是删除。**

主记忆条目分四类处理：① 当前状态、待决事项、下一步 → 留在主记忆，一条一行；② 已完成的阶段任务 → 压成一行（做了什么＋结论＋产物路径），执行细节移入主题记忆；③ 过时、被取代、一次性的过程内容 → 移出主记忆；④ 长期结论、核心数字、红线、用户要求与纠正、研究协议变化 → 保留，可精简措辞，但事实与数字不得删。

**不得压缩掉的内容**：① 研究结论及其原始口径（分母、样本量、seed、模型、指标）；② 负面结果、失败尝试、被排除的解释、限制条件；③ 用户原话级的纠正、偏好与规则；④ 研究协议、口径、切分的变化及其理由；⑤ 冻结值、红线与结论标签上限。

**动作**：细节必须**先落盘**到 `memory/<主题>.md`，再在主记忆里换成一行指针；禁止先删后想。
压缩后自检：主记忆能否独立回答“在做什么、结论是什么、下一步是什么、有什么约束”四问；任一项答不出说明压缩过度，应回填。

本规则只管项目记忆文件；面向用户的过程总结与历史报告仍遵守“扩写时不得压缩已有内容”。

## 四、准确性规则

- 区分已验证事实、用户决定、助手建议、假设与未知项，不确定项显式标注。
- 保留负面结果与已放弃的方向；明确标注事后分析、探索、已被替代的结论。
- 记忆与原始证据冲突时，修正记忆，把更正说明写入对应主题记忆，并保留证据路径。
- 影响决策的结果使用准确数字和准确路径。

## 五、语言规则

- 记忆正文、计划、说明和项目级技能正文一律使用中文；不得用英文做自然语言叙述。
- 模型正式名称、文件路径、字段、命令、既有论文标题等无法翻译的技术标识可保留原样，周围解释用中文。

## 六、token 控制（2026-10-02 用户要求）

- 主记忆每轮必读，**它越短，每轮开销越小**：只放当前状态、长期结论和指针，细节一律外移。
- 主题记忆按需读取，能不整读就不整读。
- 不把大段原文、日志、原始数据或代码拷进记忆，只留结论、口径与路径。
- 更新记忆时用替换或追加，不要把整份文件重抄一遍。

- `.codebuddy/skills/project-memory-maintainer/` 是本技能唯一完整正文；`.agents/skills/project-memory-maintainer/SKILL.md` 只负责发现与跳转，不复制完整规则。
- 非每轮必需的细节——主记忆板块清单、主题记忆文件表、大小与保留限额、证据优先级——见 `references/memory-schema.md`，需要重建或大改记忆结构时再读。
