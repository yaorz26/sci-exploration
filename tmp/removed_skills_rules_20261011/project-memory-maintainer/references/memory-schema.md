# 记忆结构细则（按需读取）

本文件是 `.codebuddy/skills/project-memory-maintainer/SKILL.md` 的补充。它只包含**不是每轮都用**的结构性细则；每轮流程、压缩规则和红线以技能正文为准。
只有在重建主记忆、新增大板块、或判断某条内容该放哪里时才需要读本文件。

## 一、`PROJECT_MEMORY.md` 的板块

主记忆保持精简并反映当前状态，既有板块如下；更新时沿用现有结构，不要随手增删板块：

- 项目目的与核心目标
- 核心目标与红线（含不可违反的限制）
- 当前状态（含停止点、未闭合项、待决清单）
- 当前结论（含已验证数字与口径）
- 六步方案状态 / 分阶段任务状态
- 训练与验证事实
- 重要失败与纠正
- 结构定位判断
- 结论边界与风险（可以说 / 不能说）
- 暂停点与恢复建议
- 用户工作偏好
- 关键证据入口

当前状态变化时**替换**旧状态，不要把第二份时间线堆进主记忆；旧状态保留在主题记忆中。

## 二、主题记忆文件

| 文件 | 内容 | 何时更新 |
|---|---|---|
| `memory/project-contract.md` | 目的、目标、范围、红线、成功标准 | 项目目标或约束变化时 |
| `memory/research-findings.md` | 已验证发现、失败方向、问题与不确定性 | 得出或修正研究结论时 |
| `memory/decisions-and-next-steps.md` | 用户决策、停止/继续理由、下一步门槛 | 方向或执行状态变化时 |
| `memory/artifact-map.md` | 入口、协议、报告、数据、模型、代码位置 | 新增或移动重要文件时 |
| `memory/<主题>.md` | 按主题新开的承接文件（例如 `data-route-log.md`） | 主记忆压缩时承接被移出的细节 |

一个主题一个文件。新建主题文件时，把入口登记进 `memory/README.md` 和主记忆的“关键证据入口”。

## 三、大小与保留限额

- `PROJECT_MEMORY.md` 控制在约一百五十行内；达到或接近该规模，当轮必须压缩。
- 稳定细节写入主题记忆，不堆进主记忆。
- 重要历史决定、负面结果、用户纠正、协议变化不得删除；应精简后移入合适的主题记忆。
- 不得保存秘密、完整原始数据、完整日志、模型权重或大段论文原文。

## 四、证据优先级

出现冲突时，依次以**原始机器输出 → 冻结实验协议 → 正式报告 → `.research-state/` → 主题记忆 → 主记忆**为准。记忆是导航，不是证据：与原始证据冲突时必须修正记忆，而不是反过来调整证据的解读。
