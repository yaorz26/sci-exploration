selection) from the reproduction plan. It uses a deterministic 20-problem,
APPS-Intro-like offline fixture because the APPS export and model libraries are
not currently available in the environment. It is a pipeline validation, not a
paper-scale result.

## Interpretation

The fixture intentionally contains a correct candidate in every pool, so the
private oracle upper bound is 1.0. Candidate order is rotated by problem ID to
avoid giving the first-candidate baseline a position advantage. The public
selector reaches the oracle on this tiny fixture, but that is not evidence of
paper-scale performance: the fixture has only one public example and two
private examples per task. On real APPS, candidate generation must be replaced by
an API/local model and the public/private split must come from the dataset
release.

## Continuation-level label audit and first neural pilot

The continuation collector was implemented so that each thought prefix produces
multiple complete code continuations. The node label is the mean private
pass-rate of those continuations; private tests are never included in the
generation prompt. A two-problem audit produced 8 nodes and 16 records with
zero label-construction errors.

The first strict-label pilot used APPS train-20, two candidates per problem,
up to three thought steps, and two continuations per node. It produced 118
nodes and 236 records, split by problem into 15 train and 5 test problems.
Qwen2.5-Coder 3B 4-bit QLoRA trained for one epoch and 44 optimizer steps.

| Evaluation on five unseen problems | Private pass rate | Pass@1 |
| --- | ---: | ---: |
| First candidate | 0.467 | 0.40 |
| Random | 0.333 | 0.20 |
| Public selection | 0.633 | 0.40 |
| Neural scorer selection | 0.533 | 0.40 |

The neural scorer's step-level Spearman correlation was `-0.152` and step MSE
was `1.084`. The candidate result is above first/random but below direct public
selection, so it is an exploratory pilot rather than evidence that the learned
CodePRM has surpassed the execution-feedback selector. The immediate next
technical task is to enlarge exact continuation data and stabilize the scorer
before running structured feature ablations.

## Sigmoid target and pooled-data diagnostic

The initial scalar head used an unbounded linear output even though the
continuation label lies in `[0,1]`. A sigmoid output was added and the same
three exact-label seed files were retrained for three epochs. Per-seed
independent training gave step MSE `0.217 +/- 0.006`, MAE `0.393 +/- 0.003`,
and Spearman `-0.030 +/- 0.160`; neural candidate selection remained
`0.378 +/- 0.168`, below the first-candidate mean `0.400 +/- 0.067`.

Pooling the three seed data files into 716 records and training one sigmoid
scorer for three epochs reduced the held-out step MSE to `0.215` on the fixed
last-five-problem split. Evaluating that same pooled scorer separately on each
seed's candidate pool produced:

| Seed | Step MSE | Spearman | Pooled neural private pass rate | First candidate | Public selection |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 42 | 0.226 | 0.157 | 0.533 | 0.467 | 0.633 |
| 43 | 0.232 | 0.167 | 0.400 | 0.400 | 0.633 |
| 44 | 0.184 | -0.071 | 0.433 | 0.333 | 0.633 |
| Mean +/- SD | 0.214 +/- 0.026 | 0.084 +/- 0.135 | 0.456 +/- 0.069 | 0.400 +/- 0.067 | 0.633 +/- 0.000 |

This is a useful protocol diagnostic: sigmoid calibration and pooling improve
score calibration and ranking relative to the first linear-head run, but the
learned scorer still trails the direct public-feedback selector on all three
seed pools. Structured feature ablations are therefore deferred until the
training set is expanded beyond train-20 and the objective is fixed.
