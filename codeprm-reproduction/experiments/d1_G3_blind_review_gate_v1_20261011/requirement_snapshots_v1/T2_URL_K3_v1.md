# URL 渲染双用途的有限功能任务（修订版 v2）

修订说明（v2，2026-10-11）：依据独立审查意见补齐四处口径——① 明确映射视图**不做百分号解码**；② 明确各组件可原样保留的字符集合；③ 删掉自相矛盾的注释表述；④ 明确空查询串与无查询串的差别。修订前的 v1 已快照保存。

任务来源：`boltons` 官方模块 `boltons.urlutils`（官方文档 `docs/urlutils.rst`；`URL.to_text` 的 docstring 明示两种用途）与固定父提交源码 `data/raw/d1_project_v1_20261008/repositories/boltons/boltons/urlutils.py`。

给定该模块的父版本，实现一个**有限域**的 URL 对象，使同一次解析既能按"给人看"的方式渲染，也能按"发到网络"的方式渲染。内部是否复用 `urllib.parse`、是否自写正则、辅助函数与模块划分均自由。

## 一、映射视图的取值口径（必须按此实现）

查询串映射视图返回的是**原文片段**，**不做百分号解码、不把 `+` 还原成空格**：

- 输入 `?q=a%20b` → `get('q')` 返回字符串 `a%20b`（不是 `a b`）。
- 输入 `?q=a+b` → `get('q')` 返回字符串 `a+b`（不是 `a b`）。

理由：本任务的两种用途都建立在"保留已编码文本"之上；解码属另一种用途，不在本任务范围内。

## 二、渲染的两类用途与字符集合

同一对象提供两种渲染，读同一份解析结果：

| 用途 | 调用 | 可原样保留的字符 | 空格处理 |
| --- | --- | --- | --- |
| 显示 | `to_text()` | 字母数字 `-._~`、以及 `!$&'()*+,-./:;=?@` 和 `%` | **原样保留** |
| 发送 | `to_text(full_quote=True)` | 字母数字 `-._~`、以及 `!$&'()*+,-./:;=?@` 和 `%` | **编码为 `%20`** |

- `%` 在两种用途下都在保留集合内，因此已存在的 `%XX` 序列**不得被重复编码**（`%20` 不得变成 `%2520`）。
- 本任务合法域内不含非 ASCII 字符；非 ASCII 的编码方式不在判定范围内。
- 查询串中的 `&` 与 `=` 属保留字符（它们分隔查询项），映射视图与渲染都不得改写它们。

## 三、公开功能义务

1. **映射视图与渲染读同一份解析**：映射视图不得改写查询串。
2. **保留重复键与顺序**：同一键出现多次时，`keys`/`items` 按出现顺序给出全部条目；`getlist` 返回该键的全部值；`get` 返回该键的第一个值，键不存在时返回 `default`（默认 `None`）。
3. **保留已有的百分号编码文本**：见第二节。
4. **两种渲染用途的区别**：见第二节；区别只在空格等违规字符，不在 URL 结构分隔符。
5. **不把 `+` 当空格**：映射视图与渲染都不得把 `+` 还原成空格。

## 四、公开调用入口

固定为：`URL(url)`、`URL.to_text(full_quote=False)`，以及查询串映射视图的 `keys()`、`items()`、`get(key, default=None)`、`getlist(key)`。这些名称与官方 API 同名；内部实现自由。

## 五、合法输入域

以 `http://` 或 `https://` 开头、主机为普通 ASCII 域名、可含路径/查询串/片段的 URL；查询项为普通键值对（允许重复键）。不纳入：用户信息（userinfo）、IPv6 主机、相对 URL、非 ASCII 主机与字符、空查询串与无查询串的区分（`?` 后为空视为无查询串）、性能或内存特性。

来源说明：两种渲染用途与"已编码文本不要重复编码"来自官方 docstring 与 docs；"空格在发送用途下编码为 `%20`"、"映射视图不解码"与"`+` 不作空格"是任务构建者为有限域明确的约定，不假装是 RFC 的唯一要求。
