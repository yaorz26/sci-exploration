# 环境变量进入项目配置的有限功能任务（修订版 v2）

修订说明（v2，2026-10-11）：依据独立审查意见补齐三处口径——① 明确前缀拼接方式（前缀直接拼键，不额外插分隔符）；② 明确嵌套键是**叶子级合并**而非整树替换；③ 明确调用入口签名、取值类型与异常。修订前的 v1 已快照保存。

任务来源：beetbox/confuse PR142 的公开功能说明。给定直接父提交 `cd1db04b07db00050900d2f548baf144bb92d261` 的非测试包源码。在真实 `confuse.Configuration` 对象中增加显式选择的环境变量配置来源。内部模块划分、辅助函数、字典构造方式均自由。

## 一、调用入口与签名（固定）

```python
config.set_env(prefix, sep='__')
```

- `prefix` 是**原样前缀**：环境变量名必须以 `prefix` 开头，例如 `prefix='D1APP_'` 匹配 `D1APP_HOST`（**前缀与键之间不再另插分隔符**，下划线属于前缀本身）。若写成 `prefix='D1APP'` 则同时匹配 `D1APPHOST` 与 `D1APP_HOST`。
- `sep` 默认 `'__'`，用于在剥去前缀后的键名中表示嵌套层级。`sep` 不参与前缀匹配。
- 本方法把该来源放到**当前最高优先级**，返回 `None`。

## 二、公开功能义务

1. **显式加入，不在构造时默认加入**：只有显式调用 `set_env` 之后，环境变量才参与配置读取；仅构造 `Configuration` 对象时不得自动加入环境来源。
2. **前缀匹配与键名转换**：只取以 `prefix` 开头的变量；剥去前缀后的键名转小写；键名中的 `sep` 表示嵌套层级。
3. **标量类型转换与 YAML 文件来源一致**：例如 `42` 读作整数、`hello` 读作字符串；最终通过已有配置视图的 `get` 读取，不另建 JSON 求解入口。
4. **优先级**：在文件来源之后显式加入的环境变量来源优先级更高；未被环境变量提供的键仍可由较低优先级来源读取。
5. **无匹配时保持原值**：没有任何匹配变量时，现有配置值保持不变。
6. **嵌套为叶子级合并**：当环境变量与文件同时提供同一父键下的不同子键时，两者必须**合并**，环境值覆盖同名的叶子键，未被子键覆盖。

## 三、合法输入域与域外行为

**合法域**：指定前缀的环境变量名；剥去前缀后非空且无父子键冲突的普通字符串键；`sep` 表示嵌套；值为不含集合语法的有效 YAML 标量；普通映射型配置文件。

**域外输入的约定（已按上游合并版实测校正，2026-10-11）**：上游对下列输入**不抛异常**，本任务按同样行为实现（证据：`experiments/d1_G3_fidelity_probe_v1_20261011/fidelity_PR142_PR440.json` 与 `detail_probe.json`）。

| 域外情形 | 上游实测行为 | 本任务约定 |
| --- | --- | --- |
| 变量名不以前缀开头 | 忽略 | 忽略 |
| `prefix=''`（空字符串） | 不报错，所有变量都匹配 | 同上游（不报错） |
| 剥去前缀后键名为空（如 `D1X_=9`） | 建立**空字符串键**（`keys()` 中出现 `''`），不报错 | 同上游（不报错） |
| 剥去前缀后含空层级片段（如 `D1X_A__`） | 在 `keys()` 中建立 `''` 键，不报错；正常键不受影响 | 同上游（不报错） |
| 值为集合语法（如 `[1,2]`） | 当作**字面字符串** `'[1,2]'` | 同上游（不报错） |

**判定顺序**：先判"不匹配前缀"（忽略）→ 其余情形按上表处理。本任务**不再要求**对任何域外输入抛 `ValueError`；`prefix` 传非字符串类型不在本任务合法域内，行为未测、不作规定。

不纳入：列表转换、完整 YAML 文档值、重新加载、性能或线程安全。

来源说明：前缀、键名转换、嵌套、标量转换与显式选择来自公开 PR 说明；"最高优先级入口"与"调用方必须显式调用"是任务构建者为现有 `set`/`set_file` 约定选定的调用约束；"前缀不再另插分隔符"与"叶子级合并"是构建者为消除歧义明确的约定。评价材料、合并版本与手写控制不属于未来模型可见输入。
