## 一、先给出结论

本轮 v4 计划已经完成它现在能完成的部分：研究池、任务契约边界、上游保真度、评价器盲点、模型资源边界和明确的不可回答范围都已交付。

本轮没有完成、也不能声称完成的部分：正式数据集、真实人工双审、正式标签、正式切分，以及主问题 A 的 M0/M2 收益比较。

v4 暴露出计划设计问题：

1. 把真实人工双审写成硬门槛，却没有在计划开头先检查人是否已经安排；
2. 把上游保真度检查放在候选形成之后，导致任务文本在执行中被多次纠正；
3. 没有在模型执行前冻结补丁接口、请求分配和失败分支，接口改版时又产生新的决策点；
4. 把 AI 质检的数值评分当成可用的审查信号，后来才发现二值缺陷清单更合适；
5. 状态文件没有和最新账本同步，造成当前进度看起来落后。

v5 的改法是：先做资源与外部依赖清点，再做上游保真度和任务冻结，最后才考虑模型。每个阶段的成功、失败和外部资源缺失分支在执行前写死。执行者遇到计划内情况直接按分支走，不再把这些情况退回用户决策。

## 二、研究终点

终点分成两个等级，不能混写：

- **边界交付**：交付可追溯的真实项目研究池、公开行为和契约边界、上游保真度、评价器风险、资源失败边界，以及主问题 A 在当前条件下不可回答的原因。这是没有人工双审或没有模型资源时的完整终点。
- **主问题 A 结果**：只有两位真实审查者、正式切分、冻结的 M0/M2 协议、足够资源和两臂完整候选全部具备时，才报告每题的 M0/M2 行为结果和差值。它是条件终点，不是默认终点。

正式标签、正式切分和主问题 A 的收益结果不能由边界交付补出来。

## 三、执行前一次性前置检查

在任何新阶段开始前，执行者必须先生成一张前置检查表。表中任何一项不满足，就按后面的边界交付分支结束，不进入模型执行。

| 前置项 | 必须看到的证据 | 缺失时的固定处理 |
| --- | --- | --- |
| 目标和口径 | 题目、主问题 A、分子/分母、允许结论已写入 RESEARCH_TARGET | 停止，不开始实验 |
| 外部人工资源 | 两位合格审查者的身份由决策方提供，且未参与构建、未见模型结果 | 记录外部依赖未履行；formal_labels/split 保持 null；走边界交付 |
| 任务真实性 | 每个候选都有官方需求或变更、父源码、项目入口和许可 | 缺少者降为研究线索，不进入真实候选 |
| 上游保真度 | 每个真实候选都有固定调用集、上游原始输出、逐条比较表和版本哈希 | 先修订任务文本并重新冻结，不能进入盲审或模型 |
| 公开验收 | 题面明示 API 都有公开行为锚点，评价器不漏入口 | 补最小锚点；无法观察则保留 unknown，不写成通过 |
| 评价器冻结 | 需求、公开用例、评价器、父源码和哈希已冻结 | 建新版本，不能覆盖旧版本 |
| 模型与接口 | 模型身份、tokenizer、seed、上下文、补丁入口、输出格式和失败码已冻结 | 不发模型请求 |
| 预算 | 每题、每臂、每请求的 token 和请求数可在请求前预检，含开发烟测 | 记录 no-go，走边界交付 |
| 污染与泄漏 | public、private、参考补丁、隐藏结果的使用边界已登记 | 停止，先清理证据链 |

这张表必须在执行前一次性完成，不允许做到一半再发现“还需要决策”。

## 四、固定阶段顺序

P0 前置检查对应原 G1 入口，P1 对应 G2 候选真实性，P2 对应 G3 冻结，P3 对应 G3 人工审查，P4 对应 G4 协议与资源，P5 对应 G5 交付。原阶段标识 G1、G2、G3、G4、G5 保留用于历史证据和账本索引。

### P0：前置检查与路线选择

**要回答的一个问题**：本轮能走到哪一个终点？

最低成本验证：完成第三节的前置检查表。

判定：

- 所有人工和实验条件齐备，进入 P1；
- 人工缺失但边界证据可完成，直接进入 P5 边界交付；
- 关键来源、契约或预算缺失，记录缺口并进入 P5；
- 任何 private 泄漏或身份不明，停止并修复，不继续取数据。

### P1：任务真实性和上游保真度

先验证每个候选是不是项目真实功能，以及任务文字是否忠实反映上游。固定顺序为：官方需求/提交 → 父版与合并版 → 上游源码与文档 → 固定调用集 → 两种合法组织 → 功能遗漏控制。

输出：每个候选一份保真度文件、原始输出、比较表、版本哈希和处理结论。

判定：

- 保真：进入候选冻结；
- 可修正的不一致：修正文案，保留旧版，重新冻结；
- 构建者自定义且不能合理解释为项目功能：降为合成任务；
- 无法观察：保留 unknown，不进入正式分母。

上游测试不能被拿来补写需求；固定调用集不是全域正确证明。

### P2：候选和验收冻结

冻结内容包括需求文本、公开用例、评价器、父源码、替代组织、遗漏控制、来源、许可和所有哈希。

冻结后不得直接修改文件。需要改动时必须新建版本，并记录旧版为何失效。

输出：候选冻结清单。候选数量不是成果标准；真实候选和合成任务分开。

### P3：人工审查或外部依赖分支

先让两位真实审查者独立填写二值缺陷清单：每个条目只有“已修/未修/不适用”，保留原始意见和分歧。

AI 隔离审查只做内部质量检查，不能计入人工分母，不能生成 formal_labels/split。

判定：

- 两位真实审查者完成且分歧可追溯：允许生成 formal_labels/split；
- 审查者不可得：登记外部依赖未履行，继续 P5 边界交付；
- 发现缺陷：回到 P2 新建版本，不直接修改冻结文件。

审查工具不再使用小样本的整体 1—5 分作为主要结论；若需量化，只扩大明确的二值判定项。

### P4：模型协议与资源预演

只有 P0—P3 的进入条件满足，才设计模型执行。设计必须一次写全：

- M0 和 M2 的方法定义；
- 每题请求数和每臂 token 分配；
- 模型、tokenizer、seed、上下文和计量方式；
- 输出接口和确定性拼装规则；
- 失败码、分母和停止条件；
- 开发烟测和正式题的资源总账。

先用确定性夹具验证入口，再做最小本地预演。接口改变属于新协议版本，不能混入旧结果，也不能把接口消融当成 M0/M2 方法比较。

判定：

- 计量身份、预算预检、夹具和最小预演全部通过：进入 P5-A；
- 任一项不通过：停止模型执行，进入 P5 边界交付。

### P5：交付分支

#### P5-A：完整比较交付

只有每题 M0 和 M2 都形成完整候选，才计算该题差值。生成失败、预算拒绝、拼装失败都保留在预定分母；缺候选时差值未定义。

不得用少量题目拟合结构—收益关系，不作因果结论。

#### P5-B：边界交付

无论是人工缺失、资源不足、协议 no-go、候选保真度不足还是污染限制，都交付：

- 当前真实候选和合成任务清单；
- 每项需求、上游行为、公开观察和 unknown；
- 失败分支及排除的解释；
- 人工审查分母和 formal_labels/split 状态；
- 模型配置、调用和 token 账本；
- 主问题 A 在当前条件下不可回答的具体原因；
- 若要恢复，唯一需要补的条件。

边界交付完成后，本轮结束，不自动开启新的实验。

## 五、执行者反馈协议

执行者只有在整个计划分支完成或确认无法完成时汇报一次。汇报必须用通俗语言先说“这一步在判断什么”，再给数字和文件路径。

不得在执行中把以下计划内事件提交用户选择：

- 发现候选契约与上游不一致；
- 发现人工审查者不可得；
- 发现预算预检拒绝；
- 发现接口夹具失败；
- 发现 AI 评分工具不稳定。

这些事件按本计划固定分支处理。只有以下事件才需要新的方向决定：改变题目或主问题 A、增加付费/训练/RL/外部发布、改动红线、改变 M0/M2 定义、或改动宏观阶段顺序。

每次汇报固定回答五件事：做了什么、新证据、改变什么判断、还缺什么、下一条具体命令。术语第一次出现时先解释；不能只报“G3/G4/no-go”。

## 七、三轮计划复盘

### 第一轮：可行性复盘

发现：v4 没有先确认人工审查者，也没有先确认候选保真度和完整协议资源。

修订：新增 P0 前置检查；把人工、保真度、预算和接口全部设为执行前条件；缺失时自动转 P5-B。

结论：通过。

### 第二轮：意义复盘

发现：AI 评分、重复入口补测和中途协议改版都不能直接回答主问题 A。

修订：上游保真度只做一次且在候选冻结前完成；AI 只做缺陷质检；接口变更和 M0/M2 比较彻底分开。

结论：通过。

### 第三轮：区分力与可信度复盘

发现：v4 把“有产物”误当成“满足进入模型的条件”，并且执行反馈没有明确区分人工证据、AI 证据、上游证据和模型证据。

修订：每个阶段写明证据类型、分母、失败分支和允许的结论强度；所有状态同步到 PROJECT_STATE.md 和 ledger.jsonl。

结论：通过。

三轮复盘是助手自审，不是独立人类或外部审查。
